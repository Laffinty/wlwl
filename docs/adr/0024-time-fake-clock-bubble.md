## Context and Problem Statement

wlwl 标准库**没有任何时间能力**(v0.11.2 计划 GAP-4):没有墙钟、没有单调钟、
没有睡眠。任何真实程序 —— 日志、超时、限速、缓存过期、TTL —— 都需要它;
这是标准库目前最大的一块硬缺口。

但时间能力与本项目的一个根本卖点直接冲突:**可复现性**。确定性并发、规范化
格式化器、契约门禁,全部建立在「同一输入 ⇒ 同一行为」之上;一旦 `NOW()`
进入语言,凡用到它的程序都变成两次运行两个结果 —— 而且是**静默地**变
(没有诊断,没有警告)。Go 生态对这个问题的答案是 `testing/synctest`:
测试放进一个「气泡」,气泡内 `time` 包走**假时钟**,`synctest.Wait()` 等到
气泡内所有协程阻塞才推进 —— 于是「测 10 秒超时」不用真等 10 秒,同一测试
每次运行的时钟轨迹完全一致。

## Decision Drivers

- 真实程序绕不开时间能力,缺口必须补;
- 可复现是品牌,不能为了时间能力整体放弃;
- `SCOPE` / `STEP` / `SPAWN` 调度器已经存在 —— 气泡有现成的宿主
  (确定性并发是假时钟的前提,这恰好是 wlwl 已有的东西);
- `std.rand` 的教训(D12-006):默认全局状态的东西要先裁决「全局状态 vs
  显式传递」,不能当函数加;
- 时间语义的隐藏深水区:单调钟与墙钟的关系、DST / 闰秒、纳秒还是毫秒、
  时区(建议:核心成员一律 UTC / 单调,时区是格式化层的事)。

## Decision(草案形态,待批准)

1. **时间成员只进气泡语义**:提供 `NOW() -> INTEGER`(Unix 秒或毫秒,墙钟)、
   `MONOTONIC() -> INTEGER`(单调,只用于测差)、`SLEEP(ms) -> NULL`(仅任务内
   可用,挂起任务而非阻塞线程 —— 沿 §17 挂起语义)。**成员签名本 ADR 不冻结**,
   实现批次按此形态细化。
2. **假时钟气泡**:`SCOPE` 的既有形态上增加气泡变体(具体落点是 `SCOPE` 的新
   形参、`STEP` 的选项、还是独立 `BUBBLE(fn)`,留实现批次裁决)。气泡内:
   - `NOW` / `MONOTONIC` 走**虚拟时钟**,初始值固定;
   - 虚拟时钟**只在气泡内所有任务阻塞时推进**(synctest 语义)—— 于是
     「`SLEEP(10_000)` 后超时」的测试瞬时完成且每次轨迹一致;
   - `SLEEP` 在气泡内 = 「登记一个唤醒时刻并挂起任务」,由时钟推进唤醒。
3. **气泡外**:真实系统时钟,行为如实文档化(不可复现是使用者的明确选择)。
4. **归层**:R2(触系统资源,ADR-0021 机械规则第 1 条);气泡机制在调度器
   (R0)开一个小口,由 R2 成员消费。
5. **可复现口径成文**:凡跨气泡取时间的程序,行为依赖真实时钟 —— 这一事实
   由规范在成员行上显式声明,不由运行时检测。

## 开放问题(实现批次必须先回答)

1. **气泡边界**:气泡能否嵌套?气泡内 `SPAWN` 出去的任务是否必然归属气泡?
   气泡内做真实 IO(HTTP / 文件)时时钟如何推进 —— 冻结到 IO 完成点?
2. **虚拟时钟的推进规则精确定义**:「所有任务阻塞」的判定与 §17 的挂起 /
   死锁检测(E0065)如何互不干扰 —— 真死锁与「等时钟」必须可区分。
3. **`SLEEP` 与 `CHANNEL_*` 超时形态**:气泡内的超时参数是否统一走虚拟时钟。
4. **精度与表示**:`INTEGER` 毫秒够不够(2038 问题不存在,但亚毫秒测量需要
   单调钟),`MONOTONIC` 的起点是否暴露。
5. **与 `std.test` 的关系**:`RUN_TESTS` 里是否默认开气泡(测试框架自动
   可复现),还是显式 opt-in。

## Consequences

- 批准后,时间能力进入待排期状态,实现前仍需独立里程碑(调度器开口 +
  成员面 + 气泡测试基建,工程量级不低于 `HTML_SANITIZE`);
- 不批准则 `std.time` 维持 GAP-4,本 ADR 的开放问题清单即为重启谈判的起点;
- 无论批准与否,**本批(v0.11.3)不实现任何时间成员**。

## 6 2026-10-06(业主批准时的重切:本 ADR 一分为三)

批准的同时,实施前的只读调查(`addendum-01` §3.6)发现**草案第 1 条把两件无关的事
耦合在了一起**,于是就地重切范围。重切的理由与逐条裁决如下。

### 6.1 耦合错在哪:纯读成员不需要气泡

草案第 1 条写「**时间成员只进气泡语义**」。但 `NOW()` / `MONOTONIC()` 是**纯读**,
「读系统时钟」与「有没有虚拟时钟」**毫无关系** —— 气泡只改变*读什么*,不改变
*能不能读*。

而且**仓里已有同款形状的先例**:`std.encode` 的 `RANDOM_BYTES` / `RANDOM_HEX`
直接调 `getrandom::fill`、**不经宿主**(W-04,`encode.rs`),当时写进规范的理由是
「`std.encode` 是熵源」。`std.time` 是时间的源,同款。

⇒ 「时间成员必须等气泡」这个前提**不成立**;它把 GAP-4 的闭合绑死在整份 ADR 里最有
设计风险的那一节上。

### 6.2 三片重切(本次批准的实际内容)

| 片 | 内容 | 宿主 / 调度器改动 | 依赖 |
|---|---|---|---|
| **A1** | `NOW()` + `MONOTONIC()`(纯读) | **零** —— `wlwl-std` 直读 `SystemTime` / `Instant`,与 `RANDOM_BYTES` 同款 | 无 |
| **A2** | `SLEEP(ms)`(挂起任务而非阻塞线程) | 一个新 `YieldReason` 变体 + park/wake 路径(小) | 无 |
| **B** | 假时钟气泡 | 「运行队列空 ⇒ 判定是否**全阻塞** ⇒ 推进虚拟时钟」这一处分支 + 时钟替换的接缝 | A2 |

**为什么这样更优**:B 是整件事里唯一有真实设计风险的部分(见 §5 开放问题 1–5
仍未逐条收敛)。切成三片后,**B 的不确定性不再阻塞 GAP-4 的闭合** —— 日志 / TTL /
超时 / 耗时测量先拿到手。反过来若先做 B,A1 的价值被压到最后一刻。

**A1 不浪费**:它在 `wlwl-std` 内先落一个**时钟接缝**(成员只调 `now_ms(host)`,
不直接摸 `SystemTime`;`host` 形参 A1 阶段以 `_host` 占位)。B 阶段只换函数体,
**不改签名、不改调用点**。

### 6.3 五个实施期裁决点(本次一并定)

1. **时间戳形状** → `NOW() -> INTEGER`,**Unix 毫秒**。理由:wlwl 的类型系统里没有
   `DATETIME`,而**新增内建类型是语言变更**、不是标准库扩张(ADR-0023 纪律);而取
   「秒」会引入 ±1 s 的量化误差,直接污染「缓存 5 秒过期」这类语义。
   `MONOTONIC()` 同取**毫秒**,起点是**进程启动**(`Instant` 语义)⇒ **绝对值无意义,
   只有差值有效**,规范必须写死这一条。**ISO-8601 字符串本批不做** —— 那是格式化
   层的事。**亚毫秒测量不支持**,同样写进已知限制(两个成员单位统一为 ms 是刻意的:
   `SLEEP(ms)` 与时钟差值才能直接对齐)。
2. **气泡落点(B 阶段)** → **候选甲:`StdHost` 加方法**(见 `addendum-01` §3.6(b) 的
   三候选代价对比)。理由:气泡的本质是**替换掉成员原本直读的时钟**,而这个替换
   **不能是全局可变状态**(否则测试之间互相污染、结果顺序相关,违反 D12-006 同族的
   「无隐藏全局状态」纪律),它必须是**宿主能力**。`StdCtx` 加字段更省事(连 trait
   都不用改)但会把调度器级概念混进「运行上下文」。
3. **`TIMEOUT` 的失败形态** → **`ERR([kind: "Timeout"])` 值**。仓内已有同款先例:
   `AWAIT` 一个被取消的任务返回 `Value::Err(Dict { kind: "Cancelled", .. })`;
   超时是可预期的**运行期结果**,调用方多半要 `IS_ERR` 分支,而原生诊断会终止运行。
4. **`TEST_BUBBLE` 的归属** → **`std.time`**(与 Go 一致:气泡是**时间形态**,不是
   测试形态),`std.test` 不新增成员。
5. ~~与 `STEP` 的关系~~ → **前提不成立**:`STEP` **不存在**(附录 G 的 90 个全局内建、
   语言规范、实现里都没有;规范 §14 曾误述,已更正)。改问「气泡与 `SCOPE` 嵌套的
   关系」:**气泡内不再开气泡**(嵌套 = 两层虚拟时钟,语义面翻倍而收益近零);
   `RUN_TESTS` **不默认开气泡**(默认开会让既有测试的时间语义突然变可复现,那是
   breaking 级行为变化)。

### 6.4 顺带确认:开放问题 2 已经免费拿到

§5 开放问题 2 要求「真死锁与『等时钟』必须可区分」。调查结论:现有
`detect_deadlock_l1`(`runtime.rs:848`)**只把 `ReceivingOn` / `SendingOn` 当死锁
候选**,并在注释里明确排除「纯 `YIELD`」与「等子任务」。所以「等时钟」若**单列为
一个新的 `YieldReason`**,就天然不进死锁候选集 ⇒ 这条不需要额外机制,只需要纪律
(新增变体时不要把它加进那个候选集)。

### 6.5 「谁拥有时钟」在代码里只留一个答案

`RANDOM_BYTES` 的先例已经立过一次:熵源归 `std.encode`,`std.rand` 单向消费它
(`addendum-04` §3.3 的 W-02 裁决)。**时间同理**:`std.time` 是时间的源;B 阶段
**绝不能**给 `RANDOM_*` 或 `std.time` 的成员加「可注入时钟」后门 —— 那等于让
CSPRNG 成员可被降级成可预测源。同族纪律,同一条理由。

> 本节只改**范围与裁决**,不含实现。⚠️ **上面 Consequences 里那句「本批(v0.11.3)不实现
> 任何时间成员」到此作废** —— 它写于本 ADR 还是草案时(那时 `std.time` 整份排在
> v0.11.3 之外)。本节批准后,A1 / A2 / B **全部落在 v0.11.3 的追加批次 M6 内**
> (`addendum-01` 是 M6 的八份之一),按 W-01 ~ W-05 推进。
