## Context

`addendum-10` 要给 `std.math` 补任意精度 / 分数 / 统计 / 近似比较四块能力。它在
§6 写下**第一条**风险,并要求「**先算清楚再写**,不要用成员数衡量工作量」:

> ⚠️ **裁决点 §3.6 可能砍掉整块统计需求**。若 `MEAN` 等价于 `REDUCE`,加成员就是冗余。

本 ADR 就是那份「先算」。结论:计划 §2 的 **25 个候选成员要砍掉一批**,另有**三处
计划的前提被实测推翻**。

## 1. 基线(先数真值)

| 项 | 计划写的 | 实测(2026-10-13) |
|---|---|---|
| `std.math` 成员 | 32 | **32** ✓(`wl/std/math.wll` 的 `EXPORT`,R1 门面 + `kernels.rs` 的 R2 浮点内核) |

## 2. §3.1 数据形状:**(a) `DICT`** —— 维持计划建议

实测 `["sign": 1, "digits": "123", "scale": 2]` 是普通 `DICT`(`TYPE` = `DICT`,
`LEN` = 3),零语言变更即可承载。⚠ **`DICT` 构造不是免费的** —— 与 D11-012 的
数组平方级是同一族成本;`DECIMAL_ADD` 每次要构造一个新 `DICT`,所以整族必须
**归 R2**,R1 版本在规模上不可用。

⚠ **固有的「用户能造非法状态」缺陷照旧存在**(手写一个 `{sign: 0, digits: "abc"}`)。
口径:**非法 `DICT` → `E0030`,不修复、不报错**。这不是干净的形状,是**明码标价的
妥协** —— 规范必须原样写明,不能装作它没有。

## 3. §3.6 **`MEAN` 是冗余的 —— 砍掉**

计划问的是「`MEAN` 是不是 `REDUCE(arr, 0, ADD)` 的糖」。实测比那更干脆:**`SUM`
已经是一个现成成员**,而

```wlwl
SUM([1.5, 2.5, 3.5])                                  // 7.5
/(SUM([1.5, 2.5, 3.5]), 3)                            // 2.5
/(SUM([1, 2, 3, 4]), 4)                               // 2   ← 整数截断!
```

⇒ `MEAN` 的**算法**没有任何东西是 `SUM` + `/` 给不了的。按 §3.6 的裁决规则
(完全等价则不加,在 skill 里教),**`MEAN` 不加**。

⚠ **但整数数组会静默截断**,这是真陷阱:wlwl 的 `/` 在两个整数操作数上是**截断除法**
(规范 §2.2),`/(10, 4)` 得 **2** 而不是 2.5。这条**必须**进 skill 的反模式,
否则用户写 `/(SUM(xs), LEN(xs))` 会拿到静默错值 —— 而 `REDUCE` 版(计划 §3.6 原本
的提法)同样截断,所以这不是「加个 `MEAN` 就能解决」的问题,而是**语言层缺提升**。
⚠ 同理 `MEDIAN` 的偶数长度情形也必须先 `/ 2.0` 再算,否则整数数组下同样截断。

## 4. §3.4 混装口径:**计划的前提被推翻**

计划建议「`ARRAY[INTEGER]` 与 `ARRAY[FLOAT]` 混装即 `E0030`」。实测:

```wlwl
SUM([1, 2.5])    // 3.5 —— 静默提升到 FLOAT,不报错
```

⇒ **既有的 `SUM` 是静默提升的。**若统计族改用 `E0030`,就会与既有成员**分裂**
——「`SUM` 收得下、统计收不下」,而分裂意味着其中一处是错的(与 ADR-0030 里
`HTML_SANITIZE_URL` 那条同款推理)。

**建议:沿用静默提升,不引入 `E0030`**,并在规范里写明统计族沿用 `SUM` 的口径。
真要禁止混装是**破坏性变更**,归 ADR-0023 的范围,不在本批。

## 5. §2.4 `IS_NAN` / `IS_INF`:**都要,但理由要改**

计划说它们「现在只能靠 `==(x, x)` 绕」。实测:

| 表达式 | 结果 |
|---|---|
| `LN(0)` | `-inf` |
| `-(LN(0), LN(0))` | **`NaN`** |
| `*(0.0, LN(0))` | **`NaN`** |
| `==(NaN, NaN)` | **FALSE** ✓ 有绕法 |
| `==(LN(0), LN(0))` | **TRUE** ✗ **绕不出来** |
| `IS_INF` / `IS_NAN` | **不存在**(E0020) |

⇒ `NaN` **可达**(inf−inf、0×inf 两条路都通),且有 `x != x` 这个经典绕法;
而 **`±inf` 没有任何数值绕法** —— `x == x` 对它为真,只能靠 `STR(x)` 字符串匹配。
⇒ `IS_INF` 的价值**比计划说的更强**,`IS_NAN` 则是有价值的便利。

⚠ 附带一条计划没写的实测:`/(1.0, 0.0)` 给的是 **E1003 除零**(原生诊断),
而 `LN(0)` 给 `-inf`。**同一个「产生无穷」有两套行为。** 见 D5。

## 6. 顺带钉住:`APPROX_EQ` 的必要性成立

```wlwl
STR(+(0.1, 0.2))            // "0.30000000000000004"
==(+(0.1, 0.2), 0.3)        // FALSE
```

经典浮点陷阱在**本库**同样成立 ⇒ `APPROX_EQ` 与 skill 反模式「浮点用 `==` 比」
都有实测依据。

## Decision

> **Proposed**,待裁决:

- **D1 · 任意精度 / 分数用 `DICT` 承载**,形状是公开契约,字段名变更即 breaking;
  非法 `DICT` → `E0030`,不修复。整族**归 R2**(`DICT` 构造成本)。
  - **精确形状恰三字段**:`{"sign": INTEGER, "digits": STRING, "scale": INTEGER}`
    表示 `sign × digits × 10^-scale`。规范形式:`digits` 无前导零(零为 `"0"`),
    `scale ≥ 0`,`sign ∈ {-1, 1}`,且**零恒为 `{1, "0", 0}`**。
  - ⚠ **计划 §3.2 的「在结果里保留『是否精确』的标记」不另设第四字段** ——
    `exact` 对另外五个运算是无意义的,而把公开 `DICT` 契约撑宽的代价是永久的。
    取而代之:`DECIMAL_DIV` 的 **`scale` 必填**本身就是那条「不许静默截断」的保证
    (调用方必须显式声明要几位),舍入一律 **`HALF_EVEN`**(银行家舍入,与
    Python `decimal` 的默认 `ROUND_HALF_EVEN` 对齐),语义写进规范。
  - `scale` 是**有意义的**(不是规范化掉的):`DECIMAL("1.00")` 渲染回 `"1.00"`。
- **D2 · `MEAN` 不加**(§3.6)。`SUM` + `/` 已覆盖。⚠ 但**整数截断**要写进 skill
  反模式,并在规范里点名。
- **D3 · 统计族沿用 `SUM` 的静默提升**,不引入 `E0030`(§4)。禁止混装是破坏性变更,
  归 ADR-0023。
- **D4 · `IS_NAN` / `IS_INF` 都保留**,理由按 §5 改写(`IS_INF` 无数值绕法)。
- **D5 · 记录 `/(1.0, 0.0)` = `E1003` 而 `LN(0)` = `-inf` 的不一致**,作为**规范澄清**
  条目落地;**不改行为**(改 `E1003` 是破坏性变更,归 ADR-0023)。

⇒ 成员表从计划的 **≈25** 收敛到 **≈20**(砍掉 `MEAN`,其余按 §3 的形状裁决定型)。

## Consequences

**能拿到的**:§6 的头号风险(「§3.6 可能砍掉整块统计需求」)**确实发生了** ——
不是砍掉整块,而是砍掉 `MEAN` 这一个,并连带发现整数截断这个**比 `MEAN` 更值得
写进文档**的问题。

**要付出的**:

- ⚠ **D3 与计划相反**,而且理由是实测的「既有 `SUM` 就是静默提升」。这是**降低**
  严格度换一致性,不是提高。若业主认为静默提升本身就该被禁(它确实会丢精度),
  那就是**一次 breaking change**,应单独立项而不是塞进本批。
- ⚠ **D2 的整数截断**在 `MEAN` 与 `MEDIAN` 两处都存在,且 `REDUCE` 绕法同样中招 ——
  根因是语言层 `/` 的整数语义,不是本批能补的。
- ⚠ **`DICT` 承载的非法状态**是明码标价的妥协,规范必须原样写明。
- **明确不做**:复数 / 矩阵与线性代数 / 新内建数值类型 / 任意精度超越函数 /
  改现有 32 个成员的返回值。
