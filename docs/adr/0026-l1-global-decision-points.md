## Context

追加批次总纲 §3 立了 **G1–G6** 六个全局裁决点,并写明「开工前业主可否决,否则视为接受」。
本 ADR 的作用是把六问各自**取证到可裁决的程度** —— 每问给:① 相关事实(带出处);
② 建议答案;③ 理由;④ 若不采纳的代价。**六问都是「共享前提」,任何一条改了,
受影响的多份方案都要跟着改**,所以它们必须在 M6 开工前一起定完。

## G1 · Unicode 版本跟哪个(影响 addendum-03;`addendum-02` 若做 `\p{…}` 连带)

**事实(2026-10-06 查证)**:The Unicode Standard **18.0.0 已于 2026-09-16 发布**
(unicode.org/versions/ 与 unicode.org/history/publicationdates.html 两处一致),
新增 13,007 个码位(主要为小篆 11,328 字与女真文字),总数到 172,808;
18.0 的发布公告明确 **「No new algorithms have been introduced in this release」** ——
只加字符与数据文件(含新附件 UAX #60),**没有新算法**。
⇒ **总纲现在建议的 17.0(2025-09-09)已落后一版。**

**建议:钉 Unicode 18.0.0。**

理由: 18.0 **没有新算法** ⇒ NFC / NFD 的规范化算法与 17.0 完全相同,跟随最新版
在**规范化语义上零风险**;多出来的 13,007 个码位只影响覆盖面(小篆/女真的
NFC 组合),而这正是我们要「全量 UCD」的那部分。**反过来选 17.0 没有任何好处**
——落地当天就会显得过时,且下次升版又是一次改动。

**连带**:① `std.sanitize` 的实体表来自 WHATWG `entities.json`,那是 **HTML 规范
自己的数据、与 Unicode 版本无耦合** ⇒ 本决策**不影响**已冻结的 `HTML_UNESCAPE`
全表,别顺手去动它;② `addendum-02` 若决定做 `\p{…}`,须与 03 **共用同一版
生成器与同一份 UCD**,故一并钉 18.0.0。

## G2 · 「半张表」怎么办(影响 addendum-03)

**事实**:D12-004 早已写明「⚠️ 已知限制 —— UCD 四成员合成一块推迟,**明确不做
半张表**」;规范 §12.1 的原话是「只覆盖 Latin-1 的 NFC **比没有 NFC 更糟**」
(`UNIQ`/`DEDUP_BY` 那次已经吃过「半张表 = 给调用方错误数据」的亏,见 D13-008)。

**建议:维持「不做半张表」,且不作废 —— 改为「要么全量,要么不做」。**

理由同 D12-004,不必重开辩论。**但要补一条现在缺的东西**:`addendum-03` 把这四
个成员复活了,所以「全量」的**规模**得在动工前量一次,而不是拍脑袋 ——
UCD 数据文件体积、生成器自检跑全量官方测试文件的耗时、生成产物体积。
⇒ **增一条开工前动作**:M6-03 动工前先量这三个数并记入检查点;若全量生成不可
接受,那就按 §12.1 老实**不做**,而不是缩成半张表。

## G3 · `std.rand` 的播种模型(影响 addendum-08;连带 addendum-01、addendum-04)

**事实**:D12-006 = 「`std.rand` 因『可复现 vs 全局状态』未裁决」→ ⚠️ **本批已否决
—— 要动先出 ADR**;§14.1 的否决原话:「一个**默认播种**的 RNG 会削弱这个卖点
(可复现),而一个**要求显式播种**的 RNG 需要先裁决『全局状态 vs 显式传递』——
那是**设计决策**,不是加几个函数」。ADR-0024 的 `Related` 也把它列为同族。
D12-006 的解锁条件就是**这份 ADR**。

**建议:显式 seed 的 RNG 对象 + 可注入的确定性源,不设全局隐式状态。**

理由:
1. 「必须显式播种」**不等于**「不能用隐式状态」——真正的争点只有一个:
   **熵从哪来、能不能换掉**。只要熵源可注入,测试要确定性就有路可走。
2. **这个形态已经存在了**:ADR-0024 的假时钟气泡确立的正是「生产用真源、
   测试注入假源」,rand 沿用**同一套注入机制**即可,不需要另起一套哲学
   (⇒ 与 G6 合并,见该问)。
3. Rust 把 `rand` 放在 std 之外,理由是**默认播种**,不是「对象化」。
   我们否掉默认播种、保留对象化,正好站在 Rust 的反面且守住自己的卖点。
4. 总纲 §1 已定 `RANDOM_BYTES`(熵源,读 OS)与 `std.rand` 是**单向依赖** ——
   `std.rand` 消费熵源,反过来会成环。

## G4 · KDF 选型(影响 addendum-04)

**事实**:规范 §11.5 **已否决**对称/非对称加密与密钥生成(理由:标准库给了 AES
就会有人自己攒 TLS —— 误用重灾区;密钥生成需要系统随机,与 `std.rand` 同族)。
⇒ G4 只在**单向** KDF 里选,不触碰该否决。

**建议:Argon2id 为主 + PBKDF2 兼容,两者皆为单向。**

理由: ① Argon2id 是当前推荐的密码哈希(取代 bcrypt / scrypt 的地位),内存硬;
② PBKDF2 **不是「弱算法」而是互操作刚需**(RFC 8018,大量既有系统只有它),
所以必须留 —— 它的弱点是参数选择而非构造,靠下面那条约束补;③ 两者都是单向,
不违反 §11.5。

**增一条约束(addendum-04 §3.5 只提了一半)**:**参数上界必须钉死,且无参默认** ——
理由与本仓既有先例同款:可调参数 + 攻击者可调 = 迟早有人调到不安全值。
故:`PBKDF2` / `Argon2id` 的迭代数与内存**超上界报 `E0030`**,而不是静默接受。
(与 §11.5 的 `UNWRAP` 同族教训:配置项要有边界,否则「能跑」就等于「不安全」。)

## G5 · 同步原语归内建还是归 `std.sync`(影响 addendum-12 的头号裁决)

**事实**:附录 G —— `SCOPE` / `SPAWN` / `AWAIT` / `YIELD`(v0.7,§17.1)与
`CHANNEL_SEND` / `CHANNEL_RECV`(v0.7,§17.2)**全是全局内建**;
ADR-0023 **§v0.x 4** 明禁「新增命名空间重导出全局内建同名成员」。

**建议:归 `std.sync`,但只用新名字 —— 不搬并发原语。**

- `MUTEX` / `CONDITION` / `ONCE` / `SEMAPHORE` / `WAIT_GROUP` 进 `std.sync`
  (附录 G 里**没有**这些名字 ⇒ 不撞内建,合规);
- `SCOPE` / `SPAWN` / `AWAIT` / `CHANNEL_*` **留在语言面**。

理由: ① 搬并发原语 = 改语言面,而 ADR-0021 说混合模块以门面为对外契约层;
② §v0.x 4 禁同名重导出,而 `MUTEX` 这类不撞 —— 于是「结构化并发」
(`SCOPE`/`SPAWN`,调度原语,语言面)与「同步原语」(锁 / 条件变量,库能力,
`std.sync`)分工清楚,互不越界。③ 这也让 addendum-12 §3.1 那条「若叫
`SPAWN`/`SCOPE` 就违规」的判断有了确定的解法:**不叫那个名字**。

## G6 · `std.time` 的假时钟是否影响生产代码(影响 addendum-01;连带 addendum-12)

**事实**:[ADR-0024](0024-time-fake-clock-bubble.md)(Status **Proposed**)第 1/3/5 条
已经给了答案:时间成员**只进气泡语义**;**气泡外**用真实系统时钟且「不可复现是
使用者的明确选择」;可复现口径**由规范在成员行上显式声明,不由运行时检测**。
归层 R2(触系统资源,ADR-0021 机械规则第 1 条),气泡机制在调度器(R0)开小口。

**建议:采纳 ADR-0024 的形态 —— 「影响,但只以可注入的形式影响」。**

即:生产代码走真实时钟(这是使用者的明确选择,规范如实文档化);测试通过气泡拿
虚拟时钟;**不**在生产代码里塞任何「检测是否在测试里」的时间戳分支。
**与 G3 是同一个形态** —— 可注入的确定性源。⇒ 实现批次**共用同一套注入机制**,
别做两套(熵源注入与时钟注入应是同一根管子)。

## 待业主逐条裁决

| # | 问题 | 建议 | 不采纳的代价 |
|---|---|---|---|
| **G1** | Unicode 版本 | **18.0.0**(17.0 已落后一版;18.0 无新算法 ⇒ 零规范化风险) | 落地即过时,下次升版又是一次改动 |
| **G2** | 半张表 | **不做半张表**:要么全量要么不做;且动工前先量全量生成的三个数 | 回到 D12-004 已判「更糟」的口径 |
| **G3** | `std.rand` 播种 | **显式 seed 的 RNG 对象 + 可注入确定性源**,无全局隐式状态 | D12-006 继续挂着,`std.rand` 无法进 M6 |
| **G4** | KDF | **Argon2id 为主 + PBKDF2 兼容**,并钉死参数上界(超界 `E0030`) | 互操作刚需缺失(PBKDF2)或留下「迟早被调到不安全」的参数 |
| **G5** | 同步原语归属 | **归 `std.sync` 但只用新名字**;`SCOPE`/`SPAWN`/`CHANNEL_*` 留语言面 | 触碰 §v0.x 4 或改语言面 |
| **G6** | 假时钟 | **采纳 ADR-0024 形态**(只以可注入形式影响);与 G3 共用一套注入机制 | 时间可复现性无处落地,或做两套注入机制 |

## 明确不在本 ADR 范围内

- **不**逐条重开各 addendum 的**成员表**与**算法**设计(那是它们自己的 §2/§3)。
- **不**动已冻结的 `std.sanitize` 实体表(G1 明确不牵连它)。
- **不**给 `DICT` / 数组表示类问题开口(那些已在 ADR-0025 结清或外派)。
- **不**替业主回答「五份不在规范 §14 清单者是否立项」—— 那是**立项**问题,
  与本 ADR 的**技术裁决**正交,可并行推进。
