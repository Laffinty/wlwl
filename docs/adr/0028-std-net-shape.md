## Context

wlwl 至今**没有任何网络成员**。这不是「少几个函数」—— `addendum-05` §3.1
把它标成**头号风险**是有实据的:在单线程协作式调度下,一个阻塞的 HTTP 调用
会把**整个 `SCOPE`** 冻住,而那比没有网络更糟——它会让人误以为并发可用。

**四条已核实的事实**(全部可回源):

1. **运行时自述单线程。** `wlwl-eval/src/lib.rs` 里 `TIMEOUT` 的 `E0030` 消息
   原话:「the runtime is single-threaded and nothing suspends, so there is
   nowhere to check the deadline」。
   ⚠ **这句自述已经部分过时,别当成全貌**:`nothing suspends` 是 v0.8.1 静态
   分段时代的措辞,而 `ADR-0017` Step 2 之后**通道是真挂起的**(见事实 2)。
   准确的说法是「单线程,且**可挂起的位置**有限且都在运行时已知处」——
   这正是事实 2 / 3 要分两层讲的原因。
2. **任务级挂起点有 4 个,且通道是真挂起。** `wlwl_value::YieldReason` 的四个
   变体是 `Explicit`(`YIELD()`)、`AwaitingChild`(`AWAIT`)、`ReceivingOn` /
   `SendingOn`(通道 send / recv),并各自有对应的 `Tag`(WasmFX 风格)。这是
   `ADR-0017` **Step 1–2 已落地**的成果(`addendum-12` §0.1 表:Step 2 把
   `yield_split.rs` 换成 thin wrapper,通道已有真挂起 + `E0065` / `E0064`)。
3. **但原生 `StdFn` 无法在函数内部制造可续跑的挂起点。** 上面四个挂起点都是
   **运行时已知**的位置;分段器 `yield_split::split_body_for_yield` 静态地只
   认 `YIELD()` 这一个名字,而任何非分段任务体被挂起再唤醒,重入走
   `invoke_closure` **整段重跑**(绑定重来、副作用重放)⇒ 原生函数只能
   **返回**,不能把调用栈切成可续跑的分段。
   ⇒ 缺的正是 `ADR-0017` 的 **Step 3(真 state-machine 续跑)**,它
   **从未落地**,三条证据(`addendum-12` §0.1):`wlwl-eval/src/effect.rs`
   **不存在**;`yield_split.rs` 仍是静态分段器 **338** 行(ADR 计划重写为
   ~100);`run_task_segments` 仍**只对 `Yield(Explicit)` 保存 env**,其它
   signal 一律丢弃。
   ⚠ 业主 **2026-10-08 已裁决**:`addendum-12` 与 `ADR-0017` Step 3 **一并
   往后放**,先做不需要任务挂起的那几份。这条**直接决定** §4 的取舍。
4. **仓里已经有一个网络成员,而它本来就是阻塞的。** `std.ai` 的 `real-ai`
   路径用 `reqwest::blocking::Client`(`std/ai.rs`),在运行时线程上内联调用,
   池与握手跨调用复用。它受 `real-ai` feature 门控,默认构建不含,且 CI 有一道
   专门的 `cargo check --features wlwl-std/real-ai` 守着。

第 4 条的分量常被低估:「阻塞会冻住运行时」在本仓**不是 `std.net` 引入的新
问题**,而是已经存在、已被 feature 门控、已被 CI 隔离的既有行为。`std.net`
要回答的是「要不要把这个形态**提升为默认成员面**」,而不是「要不要第一次
引入阻塞」。

**`SLEEP` 已有裁决先例(2026-10-06 业主方案 E)**:它**不挂起**,直接阻塞调用
线程。理由正是事实 3 —— 挂起路线会让 `Sleeping` 唤醒后**再次执行同一个
`SLEEP`**,实测 8 秒打了 79 次 `tick` 仍不终止。该代价**原样写进规范**:
「`SLEEP` 期间不调度」。

**零依赖这一侧则比预想的容易**:HTTP/1.1 明文所需的 TCP 与 DNS 都在 **std**
里(`std::net::TcpStream`、`ToSocketAddrs`),仓内当前**没有任何一处**用到
`std::net`。⇒ 手写明文 HTTP 客户端是**新增零个第三方依赖**,连
`gen-entities` 那种「生成器 + 产物」的间接依赖都不需要。CI 只构建原生目标
(`cargo build --release --bin wlwl`,无 wasm),所以 `std::net` 在
`wasm32-unknown-unknown` 上不存在这一点**目前不构成构建问题**。

## Decision

> **✅ [2026-10-09 业主采纳 A]** —— D1–D5 生效。采纳时附加一条**条件**:
> D1 不无条件冻结,它冻结在「`ADR-0017` Step 3 仍未落地」这个前提上 ——
> 理由与触发条件见 §6。

### D1 · `HTTP_*` 是**阻塞原语**,与 `SLEEP` 同族

**挂起不是「还没做」,是当前架构下做不到**:要让一个原生调用挂起,需要在调用
边界上开一个调度器挂起点,那是**语言层变更**(ADR-0023 的稳定策略范畴),
不是加一个命名空间成员的代价。

⇒ 后果与 `SLEEP` 同款并**原样写进规范**:`HTTP_*` 执行期间**不调度任何其他
任务**,整个 `SCOPE` 冻结。

⚠ **这条必须写在成员表的显眼位置,不能藏在小节里**。理由不是免责,而是它
**直接改变调用方的并发写法**:

> **不要在同一个 `SCOPE` 里并发发多个 HTTP 请求。** 它们不会并发,只会
> 串行阻塞 —— `SPAWN` 了也还是排队。

### D2 · 超时**必填且有保守默认**,不允许无限阻塞

D1 的直接后果:阻塞的时长由**墙钟**决定,不像 `SLEEP` 有虚拟时钟可测。忘写
超时就是永久挂起整个程序。

⇒ `timeout` 可选实参,**缺省 30 s**,可覆盖;规范写明默认值。超时是
`ERR([kind:"HttpError", op, reason:"timeout"])`,**不是**原生诊断。

### D3 · 明文 `http:` + **手写 HTTP/1.1 最小子集**,零新增依赖

走 `std::net::TcpStream`,DNS 走 `ToSocketAddrs`(系统解析器)。**不引入
`ureq` 一类小型 crate** —— 那会破 ADR-0022 的零第三方依赖画像,而代价只是
自己写一个受限客户端。

⚠ **不支持的写法一律返回 `ERR`,绝不「尽力解析」。** 这是 §6 那条风险的正面
回答 —— 请求走私 / 响应拆分的根因都是「宽容地解析有歧义的框架」。最小子集:

| 情形 | 处置 |
|---|---|
| `Transfer-Encoding: chunked` | `ERR`(**不解码**;这是走私向量) |
| 既无 `Content-Length` 又无 `Connection: close` | `ERR` |
| 多个 / 冲突的 `Content-Length`,或两者并存 | `ERR` |
| 头块超出大小上限 | `ERR` |
| 响应体超出大小上限 | `ERR`(**不是** OOM) |
| 观测折行(obs-fold)、头行含裸 CR/LF | `ERR` |

### D4 · **不自动跟随重定向**

3xx 原样返回给调用方。自动跟随可能把请求带到非预期 host(SSRF 面),而
「跟随几次、跨 host 跟不跟」是一串本来就该由调用方按业务决定的事。规范与
`addendum-05` §6 的「明确不做」清单一致。

### D5 · 与 06 的边界:DNS / 连接池 / 代理归 05;进程 / 文件 / 环境归 06

`addendum-05` §3.6 的建议直接采纳 —— 两者覆盖面不重叠,`05` 尚未动工,
现在划比将来划便宜。

## Consequences

**能拿到的**:

- wlwl 第一条网络能力,且**不新增任何第三方依赖**—— 与 §0 的「零依赖最小面」
  目标一致,连 `real-ai` 那条可选路径也用不上。
- `URL_PARSE` / `URL_JOIN` 是**纯函数**,可对 RFC 3986 §5.4 参考解析器用例
  **全量冻结**,与 `std.net` 的阻塞问题完全无关 ⇒ 即便 §4 选了 B,这两条
  仍可单独落地。

**要付出的**(全部写进规范,不藏):

- **并发写法要改**:§4 选 A 之后,「`SPAWN` 多个 HTTP 请求」是**错的写法**,
  不是低效的写法。skill 的反模式条目必须点名。
- **冻结整个程序**:一次 30 s 超时 = 整个程序 30 s 无响应。D2 的默认值是
  **唯一**的兜底,所以它不是「建议」而是契约。
- **只支持明文**:会被真实用户抱怨。规范必须把它写在**成员表第一行**
  (`addendum-05` §6 原话),调用方自备隧道 / 反代。

## 4. 开放问题(**已裁决**:选 A)

| | A · 引入(阻塞原语) | B · 推迟到有真挂起 |
|---|---|---|
| 成员面 | +3 HTTP +2 URL(URL 两条**无论如何**都能做) | +2 URL |
| 新依赖 | 0 | 0 |
| 代价 | 并发写法要改;阻塞期间全程序冻结 | 无 |
| 风险 | 用错写法(以为并发) | 没有网络;`real-ai` 那条可选路径仍是唯一出路 |

**✅ 采纳 A。** 理由三条:

1. **阻塞不是新问题**(§1 事实 4)。`real-ai` 那条路径已经阻塞、已经默认构建
   关闭、已经被 CI 隔离。`std.net` 做的只是把一个**已经存在的行为**用成员
   形式、连同它的契约与代价一起**摆在明面上**。
2. **B 的等待条件是一份已被排序推后的工程,不是一句空话,但也正因如此它不会
   自己到来。** 「有真挂起」= `ADR-0017` Step 3,那份 ADR 2026-09-25 就
   **Accepted** 了(选项 A:真挂起 + 代数效应状态机),Step 1–2 已落地,只差
   Step 3。但业主 **2026-10-08 已裁决把它往后放**(与 `addendum-12` 一并)。
   ⇒ 选 B 等于把 `std.net` 绑在一个**已被明确推后**的工程上;而它在等待期间
   不会产出任何东西 —— wlwl「连一次 HTTP 都发不出去」这个现状不变。
3. **代价是可写下来的,不是不可控的**:D2 的超时兜底 + 规范的显式告警 +
   skill 反模式三条一起,足以让调用方**知道自己该写什么**。而 B 让人连写都
   写不了。

⚠ **若选 A**,D1 的告警是本 ADR 的**首要交付物**之一 —— 它比成员本身更容易
被忽略,也更容易造成「并发可用」的误解。

## 6. D1 的冻结条件(采纳时附加,2026-10-09)

**D1 不是无条件裁决。** 它冻结在这个前提上:

> **`ADR-0017` Step 3(真 state-machine 续跑)仍未落地。**

前提一旦不成立,D1 **必须重新裁决** —— 因为阻塞的全部代价(冻住整个 `SCOPE`、
必须配 D2 的超时兜底、「别在 `SCOPE` 里并发发请求」这条反模式)在挂起形态下
**一个都不必承担**。届时 `HTTP_*` 可以直接是挂起的。

### 复核触发器(可观测,不是「有空再说」)

| 判据 | 现状(2026-10-09 实测) |
|---|---|
| `impl/crates/wlwl-eval/src/effect.rs` 存在 | ❌ **不存在** |
| `src/channel.rs` 里「只有 `Yield(Explicit)` 保存 env」这句消失 | ✅ **还在**(`channel.rs` §300-301) |

⚠ 判据刻意**不**取「`yield_split.rs` 行数降到多少」这类代理指标。代理指标会
为了「看起来该变了」而误报,而**误报的守卫会被人加豁免,加了豁免就等于没有
守卫**。(顺带:`addendum-12` §0.1 记的「338 行」现已过时,实测 **365 行**,
但如上所述这条**不作为判据**。)

### 绑定靠测试,不靠散文

守卫在 `impl/crates/wlwl-eval/tests/adr_conditional_guard.rs`:
`adr_0028_d1_freeze_condition_still_holds` 在前提不成立时**转红**,并直接
写出该做什么(重裁 D1 + D2 / 更新本 ADR / 同步 `addendum-05` W-01 行)。

⚠ 这条绑定是**双向失效**的:「提一句等真挂起有了就更好」很容易,难的是
**在前提已经不成立时仍当它成立**。散文承诺挡不住这个,只有会红的测试挡得住。

## 5. 明确排除的选项(以及为什么)

| 选项 | 排除理由 |
|---|---|
| `reqwest`(或 `ureq` 等)做 `std.net` | 破 ADR-0022 零第三方依赖画像;且 std 的 TCP + DNS 已够用,引入 crate **换不到能力,只换得到依赖** |
| 原生函数内挂起 / 等 fd 可读 | 需调度器挂起点 = 语言层变更(ADR-0023);`SLEEP` 实测证明挂起路线当前走不通(8 s / 79 tick 不终止) |
| 自动跟随重定向 | SSRF 面(D4) |
| 解码 `chunked` 以求「完整」 | 请求走私 / 响应拆分向量(D3) |
| 把阻塞藏起来(成员文档不写) | 那就把一个会冻住整个运行时的行为,伪装成普通函数 —— `addendum-05` §6 的头号风险会原样复现 |
| 「顺手」加 TLS | TLS 实现不是能顺手写对的东西(§0 非目标) |
