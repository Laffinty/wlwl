# ADR-0021 — 标准库分层模型(R0 / R1 / R2 与双轨实现)

| | |---|
|---|---|
| **Status** | Accepted(2026-10-01) |
| **Date** | 2026-10-01 |
| **Deciders** | Li (project lead) |
| **Related** | **ADR-0022**(值直通边界,本 ADR 的实现前提)、ADR-0023(稳定性政策)、`docs/stdlib/wlwl-stdlib-spec-v0.11.md`、spec v0.11 §9.3 / §10.1 |

## Context and Problem Statement

v0.10.4 的标准库全部由 Rust 实现:`wlwl-std` 的命名空间模块 + `wlwl-eval`
的 106 条注册表(86 内建 + 20 词法宏)。`wlwl-std` 以 `serde_json::Value`
(别名 `StdValue`)为跨界类型 —— 见 `crates/wlwl-std/src/lib.rs:11-17` 的
既有契约「std 边界拒绝闭包值」—— 迫使 `std.collection` / `std.test` 的
实现寄居 `wlwl-eval`(`src/collection.rs`、`src/test.rs`)。由此产生四个
结构性问题:

1. 纯 wlwl 实现通道不存在,语言没有被自己的库 dogfood 过;
2. 值过界即降维(函数/闭包不能过界),「同一名义、两种实现事实」;
3. 治理四件套(规范条目 / `.wll.sig` / 注册表镜像 / ERR 消费者注册)只对
   Rust 侧闭环;
4. wlwl 程序员无法读 stdlib 源码学语言。

业主 2026-10-01 裁决:标准库按「非性能敏感、不触系统调用 → 纯 wlwl;
性能敏感、底层调用 → Rust(或混合)」双轨实现,且**代码调用这些库的方式
必须完全一致**。

## Decision Drivers

- **调用面一致是硬要求**:实现语言对调用者不可见(OCaml `external` 与
  modular FFI 先例:契约在声明处定型,调用方只见签名);
- **层间单向依赖**(Rust `core`/`alloc`/`std` 先例:按「实现需要什么」分层,
  不按功能主题分层);
- **契约先行**(Dehnert & Stepanov《Fundamentals of Generic Programming》:
  先定对行为的要求,实现可替换);
- **主体用语言自身实现**(Julia Base / Chez Scheme 先例):纯语言实现持续
  暴露语言缺陷,反哺编译器;
- **归属变更必须有数据**:性能判定不经直觉,经基准(人日纪律,ADR-0011 先例)。

## Considered Options

### A. 维持全 Rust,不做分层

零迁移成本。但双轨目标无从谈起,边界失真继续存在,collection/test 无法
归位。**拒绝**。

### B. 按功能主题分层(io 层、数据层、AI 层……)

直觉好懂,但层的依赖方向说不清:JSON 要不要依赖 io?格式化要不要依赖
集合?主题分层必然出现横向依赖网。**拒绝**。

### C. 按「实现的环境/能力要求」分三层(采纳)

Rust `core`/`alloc`/`std` 的分层轴心:一层 = 一组实现前提。层与层之间只有
单向依赖,归属判定可机械执行。**采纳**。

## Decision

**三层定义**

- **R0 内建层**(纯 Rust,编译器/运行时内部):语言自身无法表达、或语义与
  编译器强耦合的原语 —— 类型系统、错误模型、并发、OOP 构造与既有全局
  内建。对应语言规范附录 G 全部 106 条,本版不动。
- **R1 语言层**(纯 wlwl):不触系统调用且非性能敏感的库。`.wll` 源码随
  实现分发,`include_str!` 嵌入二进制。**非敏感库的默认归宿**。
- **R2 原生层**(纯 Rust,`wlwl-std`):触系统调用、性能敏感、或需复用
  成熟 Rust crate 的库。

**归属判定(机械执行,写入 stdlib 规范总则)**

1. 触系统调用 / OS 资源 / 进程·网络·时间·随机 → R2;
2. 语言核心语义 → R0;
3. 其余 → R1。仅当基准证明热点且解释器短期无优化空间时下沉 R2(数据驱动);
4. R2 成员必须有不依赖实现细节的规范级语义描述,保证随时可被 R1 等价替换。

**归属总表(v0.11 起)**

| 命名空间 | 层 | v0.11 动作 |
|---|---|---|
| 全局内建(附录 G) | R0 | 不动;不移动、不重导出 |
| `std.collection` | 混合 | 自 `wlwl-eval` 迁回并以纯 wlwl 重写;**M5 裁决:`RANGE` 单独沉回 R2**(基准实测 R1 版每元素成本超线性,使语言规范 §6.6 的符合性负载跑不完),其余 16 成员仍纯 R1。基准与偏差见 D11-012 |
| `std.str`(新) | R1 | 新建,首批成员见 stdlib 规范 §6 |
| `std.math`(新) | 混合 | 新建:纯 wlwl 门面 + R2 浮点内核(`SQRT`/`POW` 依赖浮点指令,纯 wlwl 不可表达);首批仅基础函数,无超越函数 |
| `std.test` | 混合 | R1 门面 + R2 原生内核 |
| `std.io` / `std.fs` / `std.json` / `std.format` | R2 | 维持 |
| `std.ai` / `std.agent` | R2 | 维持;「降为官方包」仅记演进方向 |

**层间规则**:R1 可以调用 R0 与 R2;R2 默认禁止调用 R1(保持单向;确需时
走白名单并登记偏差)。**混合模块**以门面(R1 侧)为其归属层 —— 门面层 =
对外契约层。

**R1→R2 的机制:私有注入通道 `StdSource::kernels`**
(D11-001 承诺在此补的机制说明,v0.11.1 补上;此前它只活在 rustdoc 与台账里)

1. **何时注入**:eval 侧 `load_std_lang` 在 `new_with_loader` 之后、
   `eval_module`(求值 R1 源码)**之前**,把清单里点名的 R2 实现绑进子求值器
   的**局部**环境。
2. **可见面从哪来**:交回 `IMPORT` 方的模块 env **只**由 AST 的
   `collect_exports`(`EXPORT` 名单)构建 ⇒ 注入的 kernel 不在导出面里。
3. **不外泄的三条约束**:kernel 名必须带 `_` 前缀(全大写)、不进 `EXPORT`
   声明、不与任何全局内建同名。门面要把它变成成员只能**改名导出**
   (`LET(RANGE, _RANGE);`),不改变 kernel 本身。
4. **两条守卫**:正向「注入面不外泄」,反向「清单里每个 kernel 都得有人
   注入」—— 反向那条是必需的:只查「被注入」抓不到「注入了没人用」的死
   注入(v0.11 就有过一个:`RANGE` 沉 R2 后 `_DIAG_E0038` 成了死注入)。
5. **它解决的是两类纯 wlwl 表达不出的东西**:浮点指令(`SQRT` / `POW`),
   以及**指定码的原生诊断**(`E0020` / `E0022` / `E0030` / `E0038` 等)——
   纯 wlwl 只能给出 `ERR` 值或固定措辞的 `E0030`,给不出带函数名前缀的
   指定码诊断。

**分发**:release 二进制默认嵌入全部 R1 源码,解压即用、运行时不读外部
文件;release 压缩包另附 `stdlib/` 参考副本(运行时不读取)。开发期源码
覆盖仅经显式 flag / debug 环境变量,属非稳定实现细节,**不得**改变任何
成员的名字、签名与语义(锁测试守护)。

> **[v0.11.1 / D11-019 补充裁定]** 「debug 环境变量」此前只是**文档措辞**,
> 实现无条件生效 —— 于是发布版二进制可被 `WLWL_STD_SRC` 重定向去加载
> 任意 R1 源码目录,与上一段第一行冲突。现按文档本意裁定:`WLWL_STD_SRC`
> **只在 debug 构建下生效**,release 构建无条件忽略;release 下的覆盖轨
> 只能经显式 `--std-src` flag。

**文档**:标准库 API 契约独立成册(`docs/stdlib/wlwl-stdlib-spec-v0.11.md`),
与语言规范相互独立、分别版本化;语言规范只保留语言表面(全局内建)与机制。

## Consequences

- **正面**:dogfooding 通道建立;混合实现成立(以 ADR-0022 为前提);治理
  四件套对全部实现形态(R0/R1/R2/混合)统一闭环;用户安装形态不变。
- **代价/风险**:R1 性能依赖解释器 —— 以 M5 基线为闸,热点按数据下沉,
  调用面不动;新增「清单 + 镜像生成器 + 锁测试」治理成本;既有
  `std.io`/`std.format` 对全局内建同名成员的重导出与新规则(不重导出)
  冲突,处理为**冻结例外**:维持现状、不扩充,新命名空间一律不得重导出。
- R1 成员用 wlwl 编写本身即是语言符合性测试,缺陷直接反哺编译器(预期收益)。
