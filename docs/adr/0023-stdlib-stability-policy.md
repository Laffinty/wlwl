## Context and Problem Statement

标准库此前没有成文的稳定性政策:成员的增删改走哪条流程、破坏性变更如何
申报、1.0 后承诺什么,均无明文。v0.11 起标准库进入双轨实现(R1 语言层
成员以纯 wlwl 交付),可见面扩张(`std.str` / `std.math` 新建),政策缺口
被放大。

## Decision Drivers

- v0.x 必须保留快速演进权(语言未到 1.0,破坏性变更不可全禁);
- 但每一次可见面变更必须**显性化、可审计**(Go 1 兼容承诺的核心不是
  「永不变」,而是「变更永远有据可查」);
- 执行机制必须已存在:四件套(规范条目 / `.wll.sig` / 注册表镜像 / ERR
  消费者注册)+ 锁测试 + CHANGELOG。

## Decision

**适用面**:全局内建(语言规范附录 G,106 条)与 `wlwl:std.*` 全部命名
空间。第三方包不受本政策约束,按自身 semver。

**v0.x 期间**

1. 任何可见面变更(新增成员、改签名、改语义、移除、弃用)**必须**在同一
   批次内完成四件套同步,并在 CHANGELOG 留条目;
2. 破坏性变更允许,但必须申报:CHANGELOG 明标 **breaking** + stdlib 规范
   对应成员标注「自 vX.Y 变更」;
3. 弃用走两步:先以弃用别名 / 警告(W 码)标记并保留至少一个次版本,到期
   方可移除(沿 `DEL` / `OR_DIE` / `POP` + `W0051` 先例);
4. **不重导出规则**:新增命名空间不得重导出全局内建同名成员;既有
   `std.io` / `std.format` 的同名成员冻结为例外,不扩充;
5. 层归属变更(R1↔R2 下沉/上浮)**不算**破坏性变更(调用面不动),但必须
   附基准数据并登记构建计划。

**1.0 起(冻结承诺,Go 1 式)**

- 不移除已发布成员,不改成员签名,不改可观察语义;
- 新增成员、新增命名空间、纯内部实现替换(含 R1↔R2 迁移)不受限;
- 例外仅两项:安全修复;实现行为偏离规范时的 bug 修复(以规范为准绳)。

## Consequences

- **正面**:变更成本显性化,「改面必须过四件套」成为可机械检查的流程;
  1.0 的承诺在 1.0 前即可彩排 —— 本政策自 v0.11 起按 1.0 规则的精神执行
  申报,但保留破坏自由;
- **代价**:每个可见面变更的清单变长(四件套 + CHANGELOG + 镜像重生成 +
  锁测试),由镜像生成器与锁测试兜底自动化。
