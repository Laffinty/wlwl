## 1 背景

v0.11 §8.5 有一条**已知限制**:作为表达式语句被求值并丢弃的 `ERR`,**只有当它是最后一条语句时**才走顶层逃逸(`E0102`);更早出现的 `ERR` 被**静默丢弃** —— 不产生任何诊断。

这不是理论洁癖。**`D11-019` 就是它造成的真实缺陷**:`SORT` 的比较器返回 `ERR` 时,错误处理代码把 `ERR` 直接放在 `||` / `IF` 的**条件位**上;按 §8.2 条件位不消费 `ERR`,于是它落进静默丢弃路径 ⇒ **零诊断 + 原序返回**,比较器的错误凭空消失。

v1.0 把这条限制**删掉**了(规范册 总纲 §0.9 的 `D-01` / `D-05` / `D-08`),代之以可判定规则:被丢弃的未消费 `ERR` **必须**报 `E0103`。这是 v1.0 里**影响面最大的破坏性变更**。

## 2 规范要求(实现必须逐条对齐)

规范语言核心册 §8.6 的六根支柱:

| 条款 | 要求 |
|---|---|
| §8.6.1 | **取走型**消费者(`ERR_PAYLOAD` / `UNWRAP_OR` / `OR_DIE` / `TRY` / `UNWRAP` / `WRAP` / `EXPECT_ERR`)取走载荷 ⇒ 解除未消费状态;**观察型**(`IS_ERR` / `IS_OK` / `BOOL` / `TYPE`)**不**解除;`==` / `!=` 按 §2.4 透传该 `ERR` |
| §8.6.2 | 丢弃点**恰好三处**:① 语句值丢弃 ② 绑定被覆盖(重绑定 / `SET`)③ 作用域结束时仍未消费 |
| §8.6.3 | **转发**:读入取走型 ⇒ 已消费;读入观察型 ⇒ 状态留在被读取的绑定;读入其它位置 ⇒ 由接收方承担 |
| §8.6.4 | `LET(_, expr)` 是**唯一**的显式丢弃构造,不产生 `E0103`;实现**不得**提供其它显式丢弃构造 |
| §8.6.5 | 一个 `ERR` **至多**被报告一次 |
| §8.5 | 程序值(顶层最后一条表达式)**不属**丢弃点,仍走 `E0102` |

**遮蔽不构成丢弃点**(§8.6.2 说明):内层 `LET` 建新单元格,外层绑定不受影响。**容器装盛不构成丢弃点**,但构成转发(§8.6.3 说明)。

## 3 设计决策(实现前已定的几条)

### D-01 未消费状态是**随绑定转移的令牌**,不是值的属性

`Value` 是 `#[derive(Clone)]` 的普通枚举,数组 / 字典按值**深拷贝**(`wlwl-value/src/lib.rs:117`)。⇒ 「这个 `ERR` 已被消费」**不能**挂在值上,否则 `LET(a, err); LET(b, a);` 之后消费 `b` 不会清掉 `a` 的副本 ⇒ 误报。

令牌挂在**绑定**上:`Binding { value, mutable, unconsumed: bool }`(`wlwl-value/src/lib.rs:505` 的 `Binding` 是 `Rc<RefCell<Binding>>` = `Cell`)。读绑定时按 §8.6.3 转移。

**「至多报告一次」(§8.6.5)由转移语义天然保证**:令牌在任一时刻只有一个持有者,被消费或被显式丢弃即销毁。

### D-02 读绑定有**三种模式**

| 模式 | 何时 | 源绑定的令牌 | 在途值的令牌 |
|---|---|---|---|
| **取走**(Consume) | 取走型消费者的实参 | 清除 | false |
| **观察**(Observe) | 观察型消费者的实参(`IS_ERR` / `IS_OK` / `BOOL` / `TYPE`) | **保留** | false |
| **转移**(Transfer) | 其余一切位置 | 清除 | 继承源令牌 |

`==` / `!=` 走 **Transfer**:它们按 §2.4 **透传**该 `ERR`(结果值就是那个 `ERR`),状态随结果值转走。

模式经求值器的一个字段传递:在派发消费者时设好,求值完实参后恢复。嵌套调用继承当前模式 —— 这是可接受的近似:最深的那次读拿到该模式,而 §8.6.3 的语义本就以「读到令牌的那一刻」为准。

### D-03 令牌随 `Outcome` 走

`Outcome { value, signal }`(`wlwl-value/src/lib.rs:741`)加一个 `unconsumed: bool`。它是求值结果的天然载体。

**难点**:`Outcome::normal(v)` 在全仓有大量调用点,它们都会**丢掉**令牌。⇒ 令牌只能在**少数几个**产生点被置位,其余调用点保持 `false` 即可:

- `ERR(...)` 字面量 ⇒ 令牌置位(未消费的 `ERR` 诞生);
- 读绑定 ⇒ 按 D-02 的模式;
- 函数返回 ⇒ 函数体最后一条 `Outcome` 的令牌随返回值出函数体(否则函数体作用域结束会误报 —— §8.6.3「读入其它位置 ⇒ 由接收方承担」);
- 其余(`BOOL(x)` 的结果、`PRINT` 的 `NULL`、普通算术……)⇒ 令牌不成立。

### D-04 三个丢弃点的落点

| 丢弃点 | 实现落点 |
|---|---|
| ① 语句值丢弃 | `eval_block`(`wlwl-eval/src/lib.rs:7777`):非末条语句的值若是未消费 `ERR` ⇒ `E0103`。**末条**语句的值是程序值 ⇒ 走 `E0102`(§8.5),**不**报 `E0103` |
| ② 绑定被覆盖 | `Expr::Set` 分支 + 同作用域重绑定:旧单元格令牌为真 ⇒ `E0103` |
| ③ 作用域结束 | `Env::pop_scope`(`wlwl-value/src/lib.rs:578`)前检查该作用域内是否有令牌为真的单元格 ⇒ `E0103`。**函数体例外**:返回值的令牌已随 `Outcome` 带出函数体,函数体作用域内不留令牌 |

### D-05 `LET(_, expr)` 是显式丢弃

`Expr::LetPattern` 的 `Pattern::Wildcard` 分支(`wlwl-eval/src/lib.rs:1158` 附近)不建立绑定 ⇒ 令牌**不转给任何绑定** ⇒ 被显式丢弃,不报 `E0103`(§8.6.4)。

### D-06 诊断码

`E0103`,`ErrorCategory::Internal` —— 与 `E0102`(顶层逃逸)同族:两者都是「未处理的 `ERR`」,分类一致。消息形如
`unhandled ERR was discarded: <payload>`。退出码 1(§11.4)。

> **勘误**:本条初稿写的是 `ErrorCategory::Runtime`。那是写本文时**还没读** `wlwl-error` 的码表 —— 实际 `E0102` 归 `Internal`,W-01 落地时按 `Internal` 注册了。**以 `Internal` 为准**;规范仓的 §11.2 码表只写「错误」严重级,不约束 `error_category` 这一层(那是诊断 JSON 的路由字段),两边不冲突。

### 4.3 W-02…W-06 的结果与三个裁决

**实现落点**

| 文件 | 改了什么 |
|---|---|
| `impl/crates/wlwl-value/src/lib.rs` | `Binding.unconsumed`(令牌挂绑定);`Outcome.unconsumed`;`Env` 新增 `read_binding(name, mode)` / `cell_token` / `scope_unconsumed[_at]` / `set_local[_mut]_with_token` / `set_cell_value_with_token`;新 `pub enum ReadMode { Consume, Observe, Transfer }` |
| `impl/crates/wlwl-eval/src/lib.rs` | `Evaluator.read_mode` + `consumer_read_mode()` **两张分类表** + `eval_in_mode()`;三个丢弃点 + `e0103()`;`Outcome` 带令牌穿过 `RETURN` / 隐式返回;`LET(_, …)` 显式丢弃 |
| `impl/crates/wlwl-std/src/{collection,test_native}.rs` | `Outcome { … }` 字面量补 `unconsumed` 字段(仅编译适配) |
| `impl/crates/wlwl-eval/tests/e0103_contract.rs` | 27 个用例,一个用例 = 一个 `#[test]` |

**读模式的实际行为**

| 位置 | 源绑定令牌 | 在途值令牌 |
|---|---|---|
| **Consume** 取走型消费者的**第 0** 实参(`ERR_PAYLOAD` / `UNWRAP_OR` / `OR_DIE` / `TRY` / `UNWRAP` / `WRAP` / `EXPECT_ERR`) | 清除 | false |
| **Observe** 观察型消费者的**第 0** 实参(`IS_ERR` / `IS_OK` / `BOOL` / `TYPE`) | **保留** | false |
| **Transfer** 其余一切位置(含 `==` / `!=` 透传、`IF` 无 else 的条件位、`&&` / `||` 左操作数) | 清除 | **继承** |

**只有第 0 个实参是「`ERR` 位」。** `UNWRAP_OR` 的默认值 / `WRAP` 的上下文走 `Transfer` —— 若按字面把整个实参列表判成取走,`UNWRAP_OR(ERR(..), d)` 里 `d` 持有的未消费 `ERR` 会被无声销毁,那正是 `E0103` 要根治的那类静默丢失。

**`ERR_CONSUMER_REGISTRY` 不是「取走型」表** —— 它回答「哪些构造**不**触发 §8.2 的透明传播」,与「哪些取走载荷」不是同一件事:`==` / `!=` / `IF` / `&&` / `||` 在注册表里但都不是取走型;`TYPE` / `BOOL` 在注册表里却是观察型。实现用**两张表**合成。

**函数返回怎么带出令牌**:**没有改 `Signal::Return` 的形状** —— 令牌装在 `Outcome.unconsumed` 里、与信号并行上行(信号里装值,令牌装在结果里)。`Expr::Return` 把子表达式的令牌放进 `Outcome.unconsumed`;`invoke_closure` 收到 `Signal::Return(v)` 时转成带令牌的 `Outcome`。隐式返回(体最后一条语句)天然随 `Outcome` 走。

**三个裁决(集成者 2026-10-21 裁定)**

1. **`E0103` 的 `error_category` = `Internal`** —— 与 `E0102` 同族。addendum D-06 初稿写的 `Runtime` 是**勘误**(写本文时还没读码表),已改。**代码不动**。
2. **观察型**不附「仅被观察则不报」的豁免 —— 规范 §8.6.4 的示例**本来就要求**观察后必须显式丢弃:
   ```
   LET(r, ERR("boom"));
   PRINT(IS_ERR(r));          // TRUE — 观察型消费者不解除未消费状态
   LET(_, r);                 // 之后显式丢弃
   ```
   ⇒ 那 22 条既有测试变红是**预期代价**,该改的是**测试**(W-08),不是规范。
3. **两个令牌表示近似本批不收敛**,登记为规范↔实现差异(一致性册 §5.4 的 X-06 / X-07),留给后续批次:
   - ① 一个绑定只有一个 bool 令牌 ⇒ 容器里同时装两个未消费 `ERR` 时只记得住一个(假阴性);
   - ② 标准库回调的实参通道不带令牌 ⇒ 回调内未消费的 `ERR` 不报 `E0103`(假阴性)。

   两者都**只产生假阴性**(漏报),**不产生假阳性**(误报)⇒ 不会把合规程序判成不合规。
