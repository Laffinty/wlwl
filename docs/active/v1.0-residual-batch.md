## 2. 裁决

### 2.1 G-02 / X-22:取走型「取走」的是**哪一个** `ERR`(甲案,2026-10-23)

**规范原文的缺口**:§8.6.1 的取走型名单(`ERR_PAYLOAD` / `UNWRAP_OR` / `OR_DIE` / `TRY` /
`UNWRAP` / `WRAP` / `EXPECT_ERR`)只说「该 `ERR` 被取走」,**没区分**消费者读到的是
「`ERR` 本身」还是「`OK(ERR(..))`」⇒ 实现侧对两者一视同仁 ⇒ 剥壳交还的那一个 `ERR`
**无处可寻**。

**裁决(落进语言核心册 §8.6.1 + §8.6.3)**:

* 读入的值**本身**是 `ERR` ⇒ 取走型消费者取走**那个** `ERR` —— 它不再处于未消费状态
  (被处理掉了,或作为返回值逃逸到 §8.5)。
* 读入的值是 **`OK(ERR(..))`** 且消费者**剥壳交还** ⇒ 交还的是**新生的** `ERR`
  (§8.6.5「值语义即新身份」)⇒ **它自己未消费** ⇒ 它的未消费状态**必须随该结果继续**,
  直到在下一个丢弃点(§8.6.2)被处置并报 `E0103`。
* 这一支**只**适用于会剥壳交还的消费者(`TRY` / `UNWRAP_OR` / `OR_DIE` / `UNWRAP`);
  `ERR_PAYLOAD` / `WRAP` / `EXPECT_ERR` 读到 `OK(..)` 是类型错误 ⇒ 不存在这一支。

⚠ **「源绑定已取走」不得被读成「那个 `ERR` 就此消失」** —— 这是本条的全部要害。

**落地接口**(值层):`ReadMode` 新增 `ConsumeCarry` 变体 —— 取走口径与 `Consume`
**逐字相同**,区别只在 `OK(ERR(..))` 这一种形态上**携带**那一个被取走的 `ERR`;
值**本身**是 `ERR` 时**不携带**(消费者要么处理它、要么让它逃逸)⇒ 否则
`UNWRAP_OR(ERR(x), d)` 会让默认值 `d` 白背一个未消费 `ERR` ⇒ **误报**。

⚠ **`Consume` 的语义一个字节都没改** ⇒ 内建调用路径(`UNWRAP` / `UNWRAP_OR`)自己的
结果承接机制(`attach_result_token`)**不受影响** ⇒ 不会出现同一个 `ERR` 报两条。

### 2.2 X-15:相等是**集合口径**(红线,不可简化)

语言核心册 §2.4:字典相等是**集合口径**、**不看顺序** ⇒
`{"a":1,"b":2} == {"b":2,"a":1}` **必须**为 TRUE。
⇒ 收敛路线只准改**查找路径**(哈希索引把候选缩到 O(1) 条),**不准**把判定简化成
「同序逐位比较」⇒ 否则上式会被判不等。

⚠ **键域封闭**(§2.1):`DictKey` 的域 = `STRING` / `INTEGER` / `INSTANCE`;
含**域外键**(`FLOAT` / 布尔)的字典**不在合法程序里** ⇒ 它们仍走线性回退 ⇒
**O(n) 的承诺只对合法程序成立**。

### 3.2 `UNWRAP` 对照组(证明内建调用路径**本来就对** ⇒ 不许动)

| 程序 | 修前读数 |
|---|---|
| `LET(a, OK(ERR("boom")));` + `PRINT(UNWRAP(a));`(末条) | **E0102 × 1**、**E0103 × 0** ⇒ `UNWRAP` 的结果是 `ERR` ⇒ 传给 `PRINT` 时按透明传播**逃逸出调用** ⇒ 它成了**程序值** ⇒ 按 §8.6.2「程序值不属丢弃点」报 **E0102** |
| 同上 + 末尾再加 `PRINT("done");`(非末条) | **E0103 × 1**(报在第 2 行)⇒ 这才是「语句值丢弃」点 |
| `LET(a, OK(ERR("boom")));` + `LET(b, UNWRAP(a));` | **E0103 × 1**(作用域结束处) |
| `LET(a, ERR("boom"));` + `PRINT(UNWRAP_OR(a, 0));` | **0 条诊断**(打印 `0`)⇒ 被处理掉的 `ERR` **不会**让默认值白背一个 |

### 3.3 X-21(rest 通道)

| 形态 | 程序 | 修前读数 |
|---|---|---|
| **`ERR` 形态**的富余实参(短路路径) | `LET(f, FUN((*args), PRINT("CALLEE RAN")));` + `CALL(f, ERR("boom"));` | **「CALLEE RAN」没有打印** ⇒ 被调方**根本没跑**(`ERR` 形态实参按透明传播**短路**整个调用)⇒ **E0103 × 1**,报在**调用点** ⇒ ⚠ **与 rest 绑定无关** ⇒ 行为**不得**变 |

⇒ ⇒ **判别性读数是「0 条 → 1 条」**,不是「位置变」。
⇒ ⚠ **只有「富余实参不是 `ERR` 形态」那一支会变** ⇒ 发布说明按这个口径写。

## 8. 留给下一个批次的提案(本批**刻意没做**)

**作用域结束处的 `E0103` 报在哪一行。** 现状:报在**调用点**那一行(`invoke_closure`
拿到的 `span` 是调用方给的实参位置)—— 固定形参那条路径**一直**如此 ⇒ rest 位现在与它
**同一口径**。

⚠ **更贴近语义的做法**是把 span 改成**被调方的函数体**(`body.span()`)—— 处置点在
被调方的作用域结束,报在被调方体内才指得准。代价:会**全局**挪动所有闭包的
scope-end 报告位置(固定形参路径也一起)⇒ **超出本项范围** ⇒ 本批**没做**,
留作单独提案(⇒ 需业主点头后再排)。
