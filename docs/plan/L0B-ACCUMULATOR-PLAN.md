## 0. 为什么是 (c):先决条件不是「选哪个数组实现」,是「不破坏语义」

ADR-0032 D4 并入 D1 后,L0-B 的实现绕不开「共享可变 cell」。而**怎么装这个 cell**
有三个选项,`ADR-0025` 与本 PLAN 都没写过:

| | 形状 | 现有数组语义 | breaking |
|---|---|---|---|
| (a) | `Array(Vec<Value>)` → `Rc<RefCell<Vec<Value>>>` | 相等性按**身份**比 ⇒ `[1,2] == [1,2]` 变 **FALSE** | **有** |
| (b) | 同 (a),但相等性**手写深比较** | 保住 | 无,但引入 `BorrowMutError` **panic** 风险 |
| (c) | **新增 `Value::Cell(Rc<RefCell<Vec<Value>>>`**,只让「被识别成累加器」的数组用它 | `Array` 一字不动 | **无** |

⇒ 采纳 **(c)**:`Array` 与它的 244 处用法**完全不受影响**,只在识别成功时
多一个内部变体,而它在**所有可观察面**(`TYPE` / `display` / `==` / 诊断措辞)
上**必须表现得和一个普通数组一样**。

## 3. 实施步骤

### S1 · `Value::Cell` 变体(可观察面必须与 `Array` 一致)

- `wlwl-value/src/lib.rs`:加变体 `Cell(Rc<RefCell<Vec<Value>>>)`。
- ⚠ **四个可观察面逐一对齐**,每条都要有契约:
  | 面 | 要求 |
  |---|---|
  | `TYPE(x)` | 返回 **`"array"`**(变体名不外泄) |
  | `display()` | `[1, 2]`(借出后渲染) |
  | `==` | **深比较**(`a.borrow() == b.borrow()`),不是身份 |
  | 诊断 / `format!` / JSON | 与 `Array` 同分支 |
- `Serialize` / `Deserialize`(若 `Value` 参与)必须**产出 `Array` 而非 `Cell`** ——
  `Cell` 是**运行期实现细节**,不能出现在任何序列化产物里。

### S2 · 识别:「`acc` 是循环局部累加器」

识别是**数据流判据**,不是语法模式匹配。四条否定条件,任一命中即**不识别**:

1. `acc` 被传给任何函数 / `CALL_METHOD`(会逃逸);
2. `acc` 被 `RETURN` / 存进 `DICT` / 赋给另一个变量(会被别名);
3. `acc` 被闭包 `FUN` 捕获(生命周期跨出循环);
4. 循环外还有对 `acc` 的读(跨迭代可见)。

命中识别时:循环第一次求值时把 `acc` 的初值包装成 `Cell`,循环内的
`SET(acc, +(acc,[v]))` / `SET(acc, PUSH(acc,v))` / `SET(acc, CONCAT(acc,[v]))`
走**原地追加**分支。
⚠ **三形态都要识别**(ADR-0032 D2 实测依据:三者成本落在噪声内,都会被用户写出来)。

### S3 · 三个内建的就地分支

`builtin_push` / `+`(数组拼接) / `CONCAT`:第一个实参是 `Value::Cell` ⇒
`borrow_mut().push(...)` / `.extend(...)`,**不 clone**。
⚠ 这三个是唯一需要改的内建;其余 244 处不动。

### S4 · 三件套(D3)

| 件 | 落点 | 形态 |
|---|---|---|
| 计数器 | `wlwl-eval` 里两个 `Cell<u64>` | `acc_optimizer_hit` / `acc_optimizer_miss`,测试专用 getter 暴露 |
| 基准守卫 | `benches/baseline.txt` 的 L0 段 | 用户代码形态四档;断言每元素成本**持平**(容差待定,见 §5) |
| 契约测试 | `wlwl-eval/tests/` | ① 识别成功时输出与不识别时**逐字节相同**;② 识别失败时输出仍**逐字节正确**(D3 第 3 件,比性能更要紧) |

⚠ **不做运行时警告**(D11-022:警告通道无人排空,等于静默丢弃)。

### S5 · 收口

## 5. 风险与未决

**风险(按严重度)**:

1. ⚠ **`==` 的 borrow 冲突**:`Cell` 与自身或与另一别名 cell 深比较时,若此刻
   有人在 `borrow_mut`,`RefCell` 抛 `BorrowMutError` —— **panic**,不是可诊断错误。
   缓解:S1 的相等性分支**先 `Rc::ptr_eq` 短路**(同 cell 直接 `true`),
   再深比较不同 cell。**这一步必须做**,否则 S2 的别名场景会变成崩溃。
2. ⚠ **`Cell` 外泄**:识别漏判导致 `Cell` 逃出循环,循环结束后行为仍像数组
   (可观察面已对齐),但**共享语义**可能与现在不同。缓解:契约测试钉「逃逸用例
   必走 miss」。
3. ⚠ **识别本身的开销**:每次进入循环都要判一次逃逸。缓解:先按 S2 的四条做**廉价
   否定检查**(只看 `acc` 的引用点个数),命中否定就立即返回 miss。
4. ⚠ **`Serialize` 面**:忘了让 `Cell` 序列化成 `Array`,产物就会带实现细节。

**未决(留给实施时定,需要数据)**:

- 基准守卫的**容差数字**:ADR-0032 §1 实测的档间抖动是 5.7%,但那是 3 样本;
  落地前要**采集 10 组重复测量**再定(我在 ADR 里已标注)。
- 逃逸分析的**具体算法**:纯语法模式匹配 vs 轻量数据流。建议先做前者(保守,
  命中少但绝不误判),miss 率由基准守卫量出来再决定要不要上后者。
