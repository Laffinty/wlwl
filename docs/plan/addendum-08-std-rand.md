> **层级** L1(可并行) · **前置** 无 · **共享裁决** 熵源归属(与 04 §3.2 共用)
> **状态** 🟡 W-01 已结(ADR-0027 **Accepted**)· W-02–W-05 未动工
> **规范状态** §14.1 **已否决**「本批不做」—— 本份就是
> **重开那个否决的前置条件**
> → **该前置条件已解除**:`ADR-0026` G3(2026-10-06,Status **Accepted**)定稿
> **显式 seed 的 RNG 对象 + 可注入的确定性源,不设全局隐式状态** —— 这正是
> **D12-006** 的解锁条件,故 `std.rand` 正式进 M6。**与 G6(假时钟)是同一形态**:
> 可注入的确定性源,实现批次**共用一套注入机制**。本份 §2 的 A1–A7 仍要逐条答

## 0. 契约摘要

- **目标**:消掉 §14.1 的那条否决(它是「**没想清楚**」,不是「不重要」),
  给出可复现性与随机性**不冲突**的形态。
- **非目标**(违反即范围事故):
  - **不设全局隐式随机源**。没有 `RAND()` / 没有 `std.rand::SEED()` 这类
    隐式状态。调用方拿不到一个「自己会变的」随机数。
  - 不做分布族(`NORMAL` / `POISSON` / …)。**只有均匀分布**;需要别的分布
    的调用方自己从均匀分布构造(极坐标法 / 逆变换法)—— 那是调用方的算法
    选择,不是标准库该替他定的。
  - **不做密码学随机**。那是 04 的 `RANDOM_BYTES`,两个命名空间、两套用途,
    不合并(见 §3.3)。
  - 不做「测试用固定 seed」的**特殊成员**。可复现靠**注入**同一个
    `RNG` 对象,不是靠一个 `MOCK_RAND()`。
- **为什么不直接写成员**:§14.1 的原文是「两条都不是『不重要』而是
  『**没想清楚**』。要动它们,**先出 ADR**」。

## 2. ADR 要回答的问题(**这是本份的第一产出**)

**在写任何成员之前**,ADR 必须逐条给出结论:

| # | 问题 | 建议默认 | 为什么重要 |
|---|---|---|---|
| A1 | 状态放哪:**值传递**(`rand` 是个普通值,每次调用显式传)还是**引用传递**(`RNG` 是可变的句柄)? | **值传递** | 值传递 ⇒ 天然线程安全 / 无隐藏共享 / 可放进 `DICT` 序列化;引用传递 ⇒ 像 `WINDOW` 那样的易用性,但引入可变共享 |
| A2 | 是不是一个**新内建类型**? | **不是**,用 `DICT`(见 §3.1) | 新类型 = 语言变更 |
| A3 | 种子从哪来? | 显式 `SEED(n)`,**不读系统熵**;要真随机就去 04 的 `RANDOM_BYTES` 取 | 隐式读熵 = 可复现性破口 |
| A4 | 算法? | **PCG32** 或 **xoshiro256\*\***(公开域、线性时间、无状态可跳转、统计质量足够) | Mersenne Twister 不是不行,但它 1998 年的设计在 2026 年没必要 |
| A5 | 与 04 的 `RANDOM_BYTES` 什么关系? | **单向**:`RANDOM_BYTES` 是熵源(读 OS),`std.rand` 消费它做播种,但**不反向依赖**(08 依赖 04) | 两个命名空间职责不重叠 |
| A6 | 放 `wlwl:std.*` 还是 std 之外(像 Rust 的 `rand` crate)? | 见 §3.2 | 若放 std,`std.rand` 就成了「四件套」的一份,契约门禁自动覆盖它 |
| A7 | 怎么保证「同 seed → 同序列」这条**可复现承诺**不被实现漂移破坏? | 契约表 + **向量冻结**(见 §4) | 这是全篇的**核心承诺** |

## 3. 语义裁决点

1. **数据形状**:wlwl 类型系统很小(`INTEGER` / `FLOAT` / `STRING` / `ARRAY` /
   `DICT` / `BOOLEAN` / `NULL` / `OK` / `ERR`)。RNG 状态用 `DICT` 表示?还是
   新增内建类型?→ **新增内建类型是语言变更**,本份建议用 `DICT`,
   代价是每次调用有一次字典构造(性能上要写进基准)。
2. **放 std 还是放包外**(ADR A6)。规范 §14 已登记一条相关方向:
   「`std.ai` / `std.agent` **降级为官方包,移出 `wlwl:std.*`**(业界先例:
   Rust / Julia 的 std 小核心原则)」—— 同一个逻辑可以质疑 `std.rand`:
   如果它进 std,那 std 就同时装了「语言通用设施」与「依赖外部约定的库」。
   → **裁决点**,倾向与 §14 一致(移出),但那需要「官方包」这套机制先存在
   (本批没有)⇒ 实际可能只能先放 std。**这是个真两难,如实记。**
3. **与 04 的名字必须区分**:`std.rand::RANDOM` 与 `std.encode::RANDOM_BYTES`
   并存时,调用方分不清哪个是密码学安全的。→ 命名上要让人一眼看出
   (如 `UNIFORM` / `RANDOM_BYTES`),并在两处文档互相指。
4. **不设分布**(§0 非目标)。但**要不要给「从 RNG 抽一个码点」**?
   Unicode 码点分布是「排除代理区的均匀分布」,不是均匀分布 ⇒ 需要一个
   显式的 `CODEPOINT(rng)` 而不是 `RAND(rng)` 复用。
5. **浮点均匀的边界**:`UNIFORM` 返 `[0, 1)` 还是 `(0, 1)`?以及
   `FLOAT` 的 53 位尾数下如何保证**不出现 1.0**。

### 3.6 裁决落地与两处**实现层实测**(2026-10-06 ADR-0027 **Accepted**)

ADR 已逐条采纳(A1–A7 全采纳 + **三处补强**),正本见
[`ADR-0027`](../../adr/0027-std-rand-shape.md)。**成员面就此冻结为 4 个**:
`SEED` / `UNIFORM` / `INT_RANGE` / `CODEPOINT`。

| 裁决 | 结论 | 落进本份哪一步 |
|---|---|---|
| A1 值传递 | 状态是普通值,成员第一个实参收它,**无 `SET_SEED()`** | W-02 |
| A2 形状 | `DICT`、不加内建类型;键名 **`s0`…`s3`**(扁平四键) | W-02 |
| A3 算法 | **xoshiro256++**;播种走 **SplitMix64**,加**零状态守卫**(全零状态是吸收态,不守卫会静默退化成恒 0 序列而冻结向量照样绿) | W-02 + 契约 |
| A4 熵 | **只**从显式实参;`STRING` 按 **UTF-8 字节**取熵、`ARRAY` 取字节数组 —— 写死这一条,否则「同一个熵」在两种字面量下给出两个序列 | W-02 |
| A5 浮点 | 只给 `UNIFORM`,`[a, b)`,53 bit、**≥ 2^53 重抽** | W-03 |
| **补强 2** | 整数区间是**独立成员 `INT_RANGE(rng, lo, hi)`**(`[lo, hi)`),**绝不让调用方 `FLOOR(UNIFORM(...))` 拼** —— `FLOAT` 只有 53 bit 尾数,浮点中转会引入舍入偏差且对大区间**静默收窄上界**(不报错、只给偏斜序列)。整数侧走无偏拒绝采样,**不经过 `FLOAT`** | W-02 |
| A6 码点 | 显式 `CODEPOINT(rng)`,排除代理区 `0xD800..=0xDFFF` | W-03 |
| A7 落点 | 本批先落 `std.rand`;「降级为官方包」是**过渡形态**,且**必须写进规范** —— 已列为 W-05 硬检查项 | W-05 |

**两个开放问题的答案**:① `UNIFORM` 的单参形态**要**,且与双参是**同一个成员**;
② A7 的过渡句**现在写进规范**(不写则它默认长期住在 `std`,与规范 §14 已登记的
方向互相矛盾)。

#### 实测两条:落成员时才知道的形状约束

1. **`StdFn` 签名层没有「可选形参」这个构造。** `StdFn` 就是
   `fn(&mut dyn StdHost, Vec<Value>) -> Result<Outcome, WlwlError>`
   (`wlwl-value/src/lib.rs:1014`),**元数由每个成员自己 `args.len()` 判**
   (现成先例:`text.rs:38` 的 `arity()` helper 报 `E0022`)。
   ⇒ `UNIFORM` 的单参形态实现成「一个成员内部判 `args.len() ∈ {1, 3}`」;
   ⚠️ **2 参必须是 `E0022` 错误,不能当「`a` 取默认」** —— 这条进契约。
   (语言侧**有**可选形参写法 `IF(cond, then, else?)`,但那是**用户函数**的
   语法糖,不延伸到 `StdFn`;两者的区别别混。)
#### 实测两条:落成员时才知道的形状约束

1. **`StdFn` 签名层没有「可选形参」这个构造。** `StdFn` 就是
   `fn(&mut dyn StdHost, Vec<Value>) -> Result<Outcome, WlwlError>`
   (`wlwl-value/src/lib.rs:1014`),**元数由每个成员自己 `args.len()` 判**
   (现成先例:`text.rs:38` 的 `arity()` helper 报 `E0022`)。
   ⇒ `UNIFORM` 的单参形态实现成「一个成员内部判 `args.len() ∈ {1, 3}`」;
   ⚠️ **2 参必须是 `E0022` 错误,不能当「`a` 取默认」** —— 这条进契约。
   (语言侧**有**可选形参写法 `IF(cond, then, else?)`,但那是**用户函数**的
   语法糖,不延伸到 `StdFn`;两者的区别别混。)
2. **`DICT` 的键是 `Value` 不是 `String`**(`Value::Dict(Vec<(Value, Value)>)`,
   `wlwl-value/src/lib.rs:48`)⇒ `s0`…`s3` 这类**字符串键**当然合法,但
   **不能用整数键 `0..3`** 去表示状态字 —— 键的**表面形态是契约面**,写死字符串键。

### 3.7 实施期撞出的两件事(2026-10-06 业主裁决)

#### (a) **补强 4**:`DICT` 不可变 ⇒ 状态永不前进 ⇒ 抽签成员改返回 `[值, 新状态]`

落地 `rand.rs` 后实测:同一个 `rng` 值反复调 `INT_RANGE`,**2000 次返回同一个数**。

**根因是语言的一条既有事实,不是实现取巧**:`DICT` **不可变**(语言规范 §2.1),
而 `SET_PROP` / `INDEX_SET` 对字典也是「返回**新**字典、**接收者不变**」(§13.4)。
⇒ **值传递 + 不可变状态 = 状态永不前进。**

⚠️ 这不与 A1 冲突(状态确实没藏起来),但 A1 的三条**签名**照字面实现是**不可用的**。

**业主裁决(方案 甲)**:三个抽签成员返回 `[值, 新状态]`,用语言**已有**的数组
模式绑定(§7.3)消费:`LET([v, r1], INT_RANGE(r0, 0, 100));`

**为什么不是「加 `NEXT(rng) -> rng'`」**:那种形态改动更小,但**忘了 `NEXT` 会
静默拿到同一个数,没有任何诊断** —— 对一个把可复现当卖点的语言,「静默错」比报错
更糟。返回 `[值, 新状态]` 让**「忘了推进」不再是可能的惯用写法**。

**为什么不是「推翻 A1 改引用传递」**:那正是 A1 明写「若被否决则本 ADR 整体
失效」的情形,且跨任务共享一个 RNG 会直接摧毁确定性。

⚠️ **这一条是单测没抓到、写测试时才发现的**:当时的单测测的是**内部**
`Xoshiro`(它当然会推进),而**成员路径**每次都从入参字典重新造状态。
⇒ **「单测测了内部而不是被测对象」** —— 与 `std.regex` 那次同族,记在这里。

#### (b) 基准量到了 §6 那句「先测再争」的答案:`DICT` 状态的代价 ≈ 360 倍

`benches/rand.rs` + `baseline.txt` 段九:

| 基准 | 每调用 |
|---|---|
| `rand_draw/int_range_0_1e9`(成员路径,走 `DICT`) | **636 ns** |
| `rand_raw/int_range_0_1e9_no_dict`(同一序列,绕过 `DICT`) | **1.77 ns** |
| `rand_draw/uniform_unit` / `rand_raw/uniform_unit_no_dict` | 697 ns / 1.14 ns |
| `rand_seed/seed_4_bytes` | 341 ns |

**成本在表示方式,不在算法** —— xoshiro 一步本身 1.77 ns,而「把 4 个 `u64` 装进
`Value::Dict`、下次再拆出来」是 635 ns(每次调用要新构造出参字典:4 次键字符串
堆分配 + 8 次 `Value` 装箱 + 4 次键查找)。

**判定:登记,不判决。** §6 原文写「若性能不可接受,就得回 §3.1 去争「新内建类型」
—— 而那是语言变更。**「不可接受」这个前提在本仓不成立**:仓内**没有**已知的
10M 级抽样需求。加内建类型能把 636 ns 降到个位数,但会**放弃** `DICT` 带来的
可序列化(存 JSON、存盘续跑)—— 那正是 A1 值传递的核心回报。
⇒ **先把数字写下来**:将来谁真要 10M 级,带着这个 636 ns 来争,而不是凭直觉争。

### 3.8 实现层的三条实测事实(踩到的坑,写下来免得重犯)

1. **`Value::Dict` 的 `display()` 不带引号**:是 `[s0: 1, s1: 2]`,不是
   `["s0": 1]`。冻结向量按前者写。
2. **`Value::Integer` 是 `i64`,xoshiro 状态是 `u64`** ⇒ 状态字按**位模式**存放,
   显示为**有符号数**(多数是负数),读回时按位重解释。这是 A2「不加内建类型」
   唯一的代价。
3. **`hi as u128 - lo as u128` 会下溢**:`i64::MIN as u128` 是符号扩展后的巨值。
   跨全域区间的偏移量必须走 `i128` 中转(实测过一次 panic)。

## 6. 风险与已知代价

- ⚠️ **ADR A6 是真两难**(§3.2):落 std 就与 §14 的「std 小核心」方向相悖;
  落包外就缺「官方包」这套机制(本批没有)。**本份可能只能先落 std 并显式
  登记这个张力**,留给下一批解决。
- ⚠️ **向量冻结会把算法钉死**。这是**有意的**(可复现是承诺),但意味着
  换算法是一次 breaking —— 要在规范里写明,免得有人以为是 bug。
- ⚠️ 用 `DICT` 表示 RNG 状态会让每次调用有一次字典构造;若性能不可接受,
  就得回 §3.1 去争「新内建类型」—— 而那是语言变更。**先测再争**。
- **明确不做**:全局隐式随机 / 分布族 / 密码学随机 / 测试专用 mock 成员 /
  Mersenne Twister。
