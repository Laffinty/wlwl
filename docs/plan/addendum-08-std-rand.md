# 08 · `std.rand` —— 显式播种的 RNG(**先出 ADR,再谈成员**)

> **层级** L1(可并行) · **前置** 无 · **共享裁决** 熵源归属(与 04 §3.2 共用)
> **状态** 未动工 · **规范状态** §14.1 **已否决**「本批不做」—— 本份就是
> **重开那个否决的前置条件**

## 0. 契约摘要

- **目标**:消掉 §14.1 的那条否决(它是「**没想清楚**」,不是「不重要」),
  给出可复现性与随机性**不冲突**的形态。
- **非目标**(违反即范围事故):
  - **不设全局隐式随机源**。没有 `RAND()` / 没有 `std.rand::SEED()` 这类
    隐式状态。调用方拿不到一个「自己会变的」随机数。
  - 不做分布族(`NORMAL` / `POISSON` / …)。**只有均匀分布**;需要别的分布
    的调用方自己从均匀分布构造(极坐标法 / 逆变换法)—— 那是调用方的算法
    选择,不是标准库该替他定的。
  - **不做密码学随机**。那是 04 的 `RANDOM_BYTES`,两个命名空间、两套用途,
    不合并(见 §3.3)。
  - 不做「测试用固定 seed」的**特殊成员**。可复现靠**注入**同一个
    `RNG` 对象,不是靠一个 `MOCK_RAND()`。
- **为什么不直接写成员**:§14.1 的原文是「两条都不是『不重要』而是
  『**没想清楚**』。要动它们,**先出 ADR**」。

## 2. ADR 要回答的问题(**这是本份的第一产出**)

**在写任何成员之前**,ADR 必须逐条给出结论:

| # | 问题 | 建议默认 | 为什么重要 |
|---|---|---|---|
| A1 | 状态放哪:**值传递**(`rand` 是个普通值,每次调用显式传)还是**引用传递**(`RNG` 是可变的句柄)? | **值传递** | 值传递 ⇒ 天然线程安全 / 无隐藏共享 / 可放进 `DICT` 序列化;引用传递 ⇒ 像 `WINDOW` 那样的易用性,但引入可变共享 |
| A2 | 是不是一个**新内建类型**? | **不是**,用 `DICT`(见 §3.1) | 新类型 = 语言变更 |
| A3 | 种子从哪来? | 显式 `SEED(n)`,**不读系统熵**;要真随机就去 04 的 `RANDOM_BYTES` 取 | 隐式读熵 = 可复现性破口 |
| A4 | 算法? | **PCG32** 或 **xoshiro256\*\***(公开域、线性时间、无状态可跳转、统计质量足够) | Mersenne Twister 不是不行,但它 1998 年的设计在 2026 年没必要 |
| A5 | 与 04 的 `RANDOM_BYTES` 什么关系? | **单向**:`RANDOM_BYTES` 是熵源(读 OS),`std.rand` 消费它做播种,但**不反向依赖**(08 依赖 04) | 两个命名空间职责不重叠 |
| A6 | 放 `wlwl:std.*` 还是 std 之外(像 Rust 的 `rand` crate)? | 见 §3.2 | 若放 std,`std.rand` 就成了「四件套」的一份,契约门禁自动覆盖它 |
| A7 | 怎么保证「同 seed → 同序列」这条**可复现承诺**不被实现漂移破坏? | 契约表 + **向量冻结**(见 §4) | 这是全篇的**核心承诺** |

## 3. 语义裁决点

1. **数据形状**:wlwl 类型系统很小(`INTEGER` / `FLOAT` / `STRING` / `ARRAY` /
   `DICT` / `BOOLEAN` / `NULL` / `OK` / `ERR`)。RNG 状态用 `DICT` 表示?还是
   新增内建类型?→ **新增内建类型是语言变更**,本份建议用 `DICT`,
   代价是每次调用有一次字典构造(性能上要写进基准)。
2. **放 std 还是放包外**(ADR A6)。规范 §14 已登记一条相关方向:
   「`std.ai` / `std.agent` **降级为官方包,移出 `wlwl:std.*`**(业界先例:
   Rust / Julia 的 std 小核心原则)」—— 同一个逻辑可以质疑 `std.rand`:
   如果它进 std,那 std 就同时装了「语言通用设施」与「依赖外部约定的库」。
   → **裁决点**,倾向与 §14 一致(移出),但那需要「官方包」这套机制先存在
   (本批没有)⇒ 实际可能只能先放 std。**这是个真两难,如实记。**
3. **与 04 的名字必须区分**:`std.rand::RANDOM` 与 `std.encode::RANDOM_BYTES`
   并存时,调用方分不清哪个是密码学安全的。→ 命名上要让人一眼看出
   (如 `UNIFORM` / `RANDOM_BYTES`),并在两处文档互相指。
4. **不设分布**(§0 非目标)。但**要不要给「从 RNG 抽一个码点」**?
   Unicode 码点分布是「排除代理区的均匀分布」,不是均匀分布 ⇒ 需要一个
   显式的 `CODEPOINT(rng)` 而不是 `RAND(rng)` 复用。
5. **浮点均匀的边界**:`UNIFORM` 返 `[0, 1)` 还是 `(0, 1)`?以及
   `FLOAT` 的 53 位尾数下如何保证**不出现 1.0**。

## 6. 风险与已知代价

- ⚠️ **ADR A6 是真两难**(§3.2):落 std 就与 §14 的「std 小核心」方向相悖;
  落包外就缺「官方包」这套机制(本批没有)。**本份可能只能先落 std 并显式
  登记这个张力**,留给下一批解决。
- ⚠️ **向量冻结会把算法钉死**。这是**有意的**(可复现是承诺),但意味着
  换算法是一次 breaking —— 要在规范里写明,免得有人以为是 bug。
- ⚠️ 用 `DICT` 表示 RNG 状态会让每次调用有一次字典构造;若性能不可接受,
  就得回 §3.1 去争「新内建类型」—— 而那是语言变更。**先测再争**。
- **明确不做**:全局隐式随机 / 分布族 / 密码学随机 / 测试专用 mock 成员 /
  Mersenne Twister。
