## 3. 待业主裁决(**唯一的阻塞点**)

### D-W3 · 零宽字符(影响 2 750 个码点)

计划 §2 原话「组合记号 = 0」**不是 EAW 的结论** —— 实测:

| 集合 | 码点数 | 按 EAW 映射得 |
|---|---|---|
| `Mn`/`Mc`/`Me` | 2 580 | N→1(2 201)、A→1(368)、W→2(11),**零个得 0** |
| `Cf`(格式字符) | 170 | **169 个 N** ⇒ 按 EAW 得 1 |
| `Cc`(控制字符) | 65 | 全部 N ⇒ 按 EAW 得 1 |

严格按 EAW 会让 **U+200B / U+200C / U+200D / U+2060 / U+FEFF 这些零宽字符
各占一整列** ⇒ `WIDTH` 用来做终端对齐就失去意义。

**我的推荐**:`Mn` / `Me` / `Cf` 计 **0**,`Mc` **不**计(带间距,真实字体占宽度,
这也是 `wcwidth` 的做法)。已提请业主,未答复。

### D-W4 · 要不要做 ZWJ emoji 序列折叠(接口语义变化)

不折叠:`WIDTH("👨‍👩‍👧")` = 2+0+2+0+2+0+2 = **8**。
折叠:得 **2**(一个 emoji 序列 = 一个字形 = 两列)。
主流 `wcwidth` / `unicode-width` 都折叠。**做折叠会让 `WIDTH` 变成簇感知的成员**
(需要 UAX #29 的簇划分),这是接口语义的变化,所以该由业主定。
**我已声明「不反对就按折叠做」,等一个明确答复。**

## 5. 不能靠记忆重建的事实(都是当天实测出来的)

1. **UCD 数据源的字段顺序各不相同**:`DerivedNormalizationProps.txt` 是
   `码点 ; 属性[; 值]`;`DerivedCoreProperties.txt` 的 `InCB` 是
   `区间 ; InCB; Linker` —— 值在**第三**段,取第二段会拿到字符串 `InCB` 本身。
2. **区间型文件必须处理空隙**。`GraphemeBreakProperty.txt` 里没列出的码点
   默认 `Other`;若做 run-length 时只在「属性变了」才断段,`0000..0009 ; Control`
   会一路吞到下一个不同属性,把 `0065 'e'` 记成 `Control`。
3. **`InCB` 只有 3 190 个码点**(Linker 23 / Consonant 913 / Extend 2 254)——
   小得可以直接入库,**真数据比「脚本范围近似」严格**(近似在 853 条里失败 23 条)。
4. **UAX #29 的 GB9c 在 Unicode 15.1 后重编号为 GB9.3**,官方用例注释里写的就是
   `[9.3]`。
5. **EAW 全表 357 226 码点,其中 `A`(Ambiguous)138 739 个 = 38.9%**;
   `A ∩ Emoji_Presentation` 实测 **0**(所以「emoji 覆盖 A」是条不存在的冲突);
   `N ∩ Emoji_Presentation` = **26**,全是 U+1F1E6–1F1FF 区域指示符。
6. **计划 §2 的「emoji = 2」照字面实现是错的**,详见 §3.3。
7. **`stdlib_appendix_a_sync` 抓不到「登记表漏了命名空间」** —— 它对账的两侧
   (镜像 / 生成器输出)读的是**同一份** `NAMESPACE_META`。同源对账只能防
   「实现动了而镜像没动」。已补 `wlwl_std::namespace_paths()` + 守卫的
   反向半边(`5c9df62`)。

## 7. 环境陷阱(会重复踩)

- **PowerShell `>` 重定向会把 stdout 写成 UTF-16LE + CRLF**。生成器产物一律用
  `python -c "subprocess.run(...).stdout"` 抓字节写盘。
- **Python `write_text()` 在 Windows 上做换行翻译** ⇒ 写完必查 `CRLF` 计数,
  并做 `read_bytes().decode("utf-8")` 解码校验。**`git diff` 看不到这个差异**。
- **`git checkout -- <file>` 会连未提交的改动一起 revert**。要还原就用反向补丁。
  (当天因此丢过一次守卫改写,重做了一遍。)
- **PowerShell here-string 会吃掉内容里的反引号** ⇒ 含反引号的 Python / Rust
  片段写成文件再执行,不要内联。
- **控制台是 GBK** ⇒ 脚本输出含中文时写 UTF-8 文件再看,别直接 `Write-Host`。
