# 00 · R0 解释器治本 —— 建数组类成员的平方级成本(D11-012)

> **层级** L0(全局前置) · **前置** 无 · **被依赖** 09 / 10 / 11
> **状态** 未动工

## 0. 契约摘要

- **目标**:把「在语言层逐次构建数组 / 字符串」的**平方级**成本消掉,让
  `std.collection` 的规模可用性回到线性。
- **非目标**(违反即范围事故):
  - **不加任何标准库成员**。本份是纯工程,成员面变化必须为 0。
  - **不改任何可观察语义**。ADR-0023 §v0.x 1:语义变更须明标 breaking。
  - 不动 `PUSH` / `+` / `LET` 的**签名与错误行为**。
  - 不引入 GC / 引用计数 / 写时复制到语言语义层(那是语言变更,不是工程)。
- **为什么必须最先**:L1 的八份里有四份要新增或扩大会构建大数组的成员;
  L2 的三份把本份列为硬前置。**在平方级成本上继续扩 std,等于把同一个坑
  挖得更深。**

## 1. 基线(可核验)

```powershell
cd impl
cargo bench -p wlwl-eval --bench eval_hot_paths -- --warm-up-time 1 --measurement-time 2 --sample-size 10
```

| 项 | 现值 | 出处 |
|---|---|---|
| `CHUNK` 5 000 元素 | **≈ 0.6 s** | `wlwl-skill/SKILL.md` 的 `std.collection` 指针 |
| `WINDOW` 5 000 元素 | **≈ 20 s** | 同上 |
| `MAP` / `FILTER` / `FLAT` / `UNIQ` / `ENUMERATE` / `GROUP_BY` / `JOIN` | 1 000+ 元素仍是**平方级** | `docs/history/20261001.md` D11-012 |
| 语言层符合性工作负载(100 万元素简单循环) | 曾因 `RANGE` 的 R1 化而**跑不完** | D11-012 原表 |
| 已有的正确先例 | M5 裁决:`RANGE` **单独沉回 R2** 即解 | D11-012 处置栏 |

**根因(归档原话)**:`PUSH` 每次复制整个不可变数组。字符串侧同构 ——
`+(s, …)` 逐次全量拷贝、`PUSH` 逐次全量拷贝(见 `std.sanitize` 模块文档
引用的 D11-012 / D12-009)。

## 2. 两条不同的修法(**不要混为一谈**)

| | L0-A 归层 | L0-B 治本 |
|---|---|---|
| 做法 | 把仍在 R1 且平方级的成员**沉 R2**,用 `Value` 直通 + `Vec` 构建 | 修 R0 解释器的 `PUSH` / `+`,让 **R1 成员也受益** |
| 先例 | M5 `RANGE`;M1/M2/M3 的 `HTML_*` 全员 R2 | 无 |
| 覆盖面 | 只覆盖被改的成员 | 覆盖所有 R1 成员,但**需要设计裁决** |
| 风险 | 低(ADR-0021 要求归层附基准,机械可验) | 高(要保不可变语义 + 错误行为不变) |
| 建议 | **本批必做** | 单独立项,先出 ADR |

### 2.1 L0-A 的候选名单(全部现为 R1 门面)

`MAP` `FILTER` `REDUCE` `SORT_BY` `ZIP` `ANY` `ALL` `FIND` `ENUMERATE` `TAKE`
`DROP` `FLAT` `UNIQ` `GROUP_BY` `CHUNK` `WINDOW` `DEDUP_BY` `MIN_BY` `MAX_BY`
`SUM` `PRODUCT` `FOLD_RIGHT` `POSITION` `KEY_BY`

(归层后 `std.collection` 的层列从「混合(R1 门面 + R2 `RANGE`)」收敛为
「全 R2」——**这是规范 §0.2 的层归属变更,须同批走四件套**。)

### 2.2 L0-B 的设计岔路(**要业主裁决,别直接开写**)

不可变数组 + 逐次追加,理论下界就是平方级。能走的三条路:

| 方案 | 做法 | 代价 |
|---|---|---|
| β1 识别式累加器 | eval 侧识别 `LET(a, [])` + 循环内只 `PUSH(a, …)` 的模式,用瞬时可变缓冲承载,循环结束再冻结 | 模式识别漏了就退化成原样(静默的性能回退,不是错误);需要逃逸分析式的保守判定 |
| β2 差分列表(rope) | `PUSH` 返回轻量句柄,求值末尾才物化 | 引入新的运行期表示,与容器相等性、索引、格式化器三处语义要一起对齐 |
| β3 容量超配 + 写时复制 | 内部预留容量,仅在**旧值仍被引用**时复制 | 不可变语义要求旧值永远有效 ⇒ 引用计数 ⇒ 与「无 GC / 无 RC」的语言立场冲突 |

> **建议**:本批只做 L0-A(低风险、机械可验、立刻见效);L0-B 单独立项并**先出
> ADR**。理由与 §14.1 否决 `SORT_UNSTABLE` 同款:β1–β3 都是**语义面**的决定,
> 混在「补标准库」批里做,审不出来。

## 3. 语义裁决点(开写前必须逐条回答)

1. **层归属变更算不算 breaking?** 规范 §0.2 只说「归层须附基准」,没说归层
   要不要申报。ADR-0023 §v0.x 2 的「破坏性变更」定义里**没有**层变更。
   → 建议:明确写进 CHANGELOG「本批无 breaking」,并在规范 §0.2 补一句
   「R1↔R2 迁移**不**属于破坏性变更」(**这是本份要产出的规范补丁**)。
2. **归层后 R1 的 `EXPORT` 面怎么办?** 归层意味着该成员不再出现在
   `wl/std/collection.wll` 的 `EXPORT` 里。§0.5 说 release 二进制默认嵌入
   全部 R1 源码 —— 归层后该成员从嵌入集中消失,**§0.5 第一行的表述要跟着改**
   (它是描述性的,不是门禁,但会被人当契约读)。
3. **已有的契约用例要不要重写?** `collection_contract.rs` 127 条走解释器
   路径。归层不改变可观察行为 ⇒ **一条都不该动**。若发现有用例要动,说明
   归层改坏了语义,回退。
4. **R1 成员还剩多少?** 若 L0-A 做完 `std.collection` 全 R2,`std.str` 7 个
   仍是 R1 —— 那 R1 模块的启动解析成本与 `--std-src` 覆盖轨是否还有存在
   理由?这决定 §5「R1 预编译快照」那条演进方向是否还值得做。

## 6. 风险与已知代价

- ⚠️ **L0-B 若同期开工**,本份从「机械可验」变成「设计未定」,评审成本翻倍。
  强烈建议本批只做 L0-A。
- ⚠️ 归层会**减少 R1 的存在意义**。若 L0-A 之后 R1 只剩 `std.str` 7 个成员,
  整个 R1 机制(嵌入分发 / `--std-src` / 预编译快照方向)的成本收益需要重估 ——
  那超出本份范围,但本份的产出是它的输入。
- **明确不做**:不动 `PUSH` 的签名;不引入 RC/GC/COW;不改任何成员的返回值
  形状;不趁机修 `SORT` 的稳定性语义(§14.1 已否决)。
