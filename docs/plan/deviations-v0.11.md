## 补记:2026-10-01 v0.11.0 审查批次对本台账的四处更正

审查(`docs/review/wlwl-v0.11.0-review.md`)发现台账里有四处**记载与代码不符**,
且都属于「台账说了什么」比「代码做了什么」更乐观的情形。共同形态:每一条都
是**照着注释/推算写下**的,写完没有回到代码与实测对一遍。逐条更正如下。

**D11-003 的处置被 M5 撤销(补记)**
D11-003 的处置写「保留 R1 行为(`E0035`)」,但 **M5 裁决把 `RANGE` 沉回
R2**,而 R2 版正是当初被判为「实现层私货」的 `checked_add` + `break` 饱和版
⇒ 溢出行为随层归属回摆成**饱和**,`E0035` 只在 R1 存在的三个月里存在过。
连带失真的还有两处文字:`collection.rs` 的注释称饱和是「§9.5 的饱和约定」
(语言规范 §9.5 实为「程序入口」,§11 与 W0015 那行明写**没有饱和路径**),
以及 D11-012 / stdlib §5 落地状态段里「导出面 / 签名 / 语义 / 诊断一字未变」
—— 诊断那一项对溢出边界并不成立。
可达性:需循环约 9.2×10^18 次,实际不可达(在此之前已耗尽内存/时间),故
**不改行为**;本条只把三处文字改回与代码一致,并在 stdlib §5 落地状态段
显式写出这条例外。

**D11-004 的根因记载不准确(已修,机制更正)**
台账与静态审查原先都把根因写成「比较结果被放在 `||` / `IF` 的条件位上」,
并给出「修法必须把比较结果先落到变量再判 `IS_ERR`」。实测逐层证伪了这条
叙述的一半:比较结果**早已**落在变量里(`LET(lt, CALL(cmp, a, b))`),真正
的丢失点是更靠前的一处 —— `TYPE(lt)` 是 ERR 消费者,把 ERR 变成字符串
`"RESULT"` 于是判假进 else 分支,而 else 的实参 `_KIND(lt)` **不是** ERR
消费者,ERR 在**算实参时**就传播掉了,`_DIAG_E0030` 一次都没被调用;那个
ERR 才轮到条件位与 §8.5 这条路被静默丢弃。
真实修法两处:`_SORT_LT` 在 `TYPE` 判定**之前**用 `IS_ERR` 拦住并原样交回;
`SORT` 加 `err` 累加器终止循环(与 `MAP` / `FILTER` / `REDUCE` / `SORT_BY`
同一套写法)。另有一处**次生**约束:`||` 的左侧短路(首轮没有前驱可比,
比较器不被调用)在比较结果落变量后必须显式重写,否则比较器会收到
`(首元素, NULL)`。三条守卫钉住:ERR 传播、载荷未被拆包(`ERR_PAYLOAD` 而非
`UNWRAP`)、比较器收不到 `NULL` 前驱。D11-004 随之由「挂账」结清。

**D11-007 的更正前提是错的**
该条以「实现走 `NEG`,一直是 `E0034`」为前提更正了 stdlib §7 的 `ABS`
失败格。实测:名为 `NEG` 的内建用裸 `-i`(release 档溢出检查关闭),
`NEG(INT_MIN)` **静默回绕**打出 INT_MIN 自己,`ABS(INT_MIN)` 因此返回负数
—— 即更正的那一格从未兑现。真正给出 `E0034` 的是 `-` 运算符那条路径
(`builtin_sub` 有 checked 判定),两条路径对同一次取负给出不同结果。
本次把 `builtin_neg` 改走同一判定与同一消息,§7 该格这才成立;
契约表新增 4 条把「门面 `ABS` / 名为 `NEG` 的内建 / 运算符路径 / 边界内侧
一步」钉在同一口径上。D11-007 的**结论**(§7 该格为 `E0034`)不变,变的
是它当时所依据的事实。
