## §0 格式契约(给下一个 agent,先读这段)

本目录的每一份方案都是**可独立执行**的:一个 agent 拿到其中任意一份,不读
其它份也能开工。为此每份的固定骨架是:

| 段 | 内容 | 缺失时的后果 |
|---|---|---|
| `## 0. 契约摘要` | 目标一句 + **非目标**明写 + 前置/被依赖 | 没有非目标 = 范围事故无判定依据 |
| `## 1. 基线` | 可核验数字,**附取数命令** | 数字不可复现 = 不能用来判断是否回归 |
| `## 2. 成员面` | 表:成员 / 层 / 语义要点 / 失败口径 | 层(R1/R2)未定 = ADR-0021 未遵守 |
| `## 3. 语义裁决` | **必须先想清楚才能写**的那些点 | 漏一条就会在实现期反复返工 |
| `## 4. 验收门禁` | 命令 + 期望值,逐条 | 「跑一下看着绿」不是门禁 |
| `## 5. 九处表落点` | 引用 v0.11.2 §5.0,只列本份的**特例行** | 漏九处之一 = CI 红 |
| `## 6. 风险与已知代价` | 含**明确不做**的东西 | 「已知限制」不写 = 下次重新发明 |
| `## 7. 检查点` | 状态表,空状态写「未动工」 | 进度只在 agent 上下文里 = 上下文一丢就丢 |

**纪律三条**(与 v0.11.3 计划同款,不再重复论证):

1. **期望值取自原文,不是实现输出。** RFC 4648 / FIPS 180-4 / WHATWG /
   UnicodeData / Go 官方文档 / OWASP 原文。实现跑出来什么不构成「应该是什么」。
2. **文档声称的东西要先在代码里找到。** 写「已具备 X」之前先 `grep` 到 X;
   找不到就是文档在骗你。
3. **不承诺与浏览器解析器逐位一致。** 安全性由幂等性守护
   (`SANITIZE(SANITIZE(x,p),p) == SANITIZE(x,p)`,规范性)。

**新增一份方案时**:照抄本骨架,文件名 `NN-slug.md`(NN 两位,分层编号),
并在下表登记一行。不改既有编号 —— 编号是引用锚点,重排会让所有交叉引用失效。

## §1 批次分层与依赖图

依赖是**硬**的:L1 的八份可并行;L2 的五份各自声明了它依赖谁;
L0 必须最先。

> ⚠️ **L1 内部还有两处「软共享」**(不是阻塞,但先定省得返工):
> ① **06 与 07 共享「二进制数据形状」裁决**(06 §3.4 / 07 §3.2)——
>    压缩的输入输出必然不是 UTF-8 字节,两份各定一次 = std 里两种字节表示。
>    **裁决归 06,07 只继承。**
> ② **04 与 08 共享「熵源归属」裁决**(04 §3.2 / 08 的 ADR A5)——
>    `RANDOM_BYTES` 是熵源(读 OS),`std.rand` 消费它做播种,**单向依赖**。
> ③ **12 依赖 01**:没有假时钟气泡,同步原语的测试要么真等(慢且脆),
>    要么写得看不出问题。

```
L0  00-r0-foundations          R0 解释器治本(D11-012)   ← 全局前置,必须最先
     │
     ├─ 依赖它(平方级成本会叠加在 L1 之上):
     │    09-json-deep · 10-numeric-extended · 11-result-optional-combinators
     │
L1  01-std-time        02-regex              03-unicode-normalization
    04-crypto-kdf-secrets  05-std-net        06-std-process-env
    07-compression     08-std-rand
     │
L2  09-json-deep       10-numeric-extended   11-result-optional-combinators
    12-sync-primitives 13-sanitize-extend
     │
L3  14-ai-agent-demotion   ← 减法,不新增成员;建议在 L1 全部落地后做
```

**为什么 L0 必须最先**:`std.collection` 27 个成员里,凡是在语言层建数组的
(`MAP` / `FILTER` / `FLAT` / `UNIQ` / `ENUMERATE` / `GROUP_BY` / `JOIN` /
`CHUNK` / `WINDOW`)在 1000+ 元素上仍是**平方级** —— 根因是 `PUSH` 每次复制
整个不可变数组(D11-012,归档于 `docs/history/20261001.md`)。实测
`CHUNK` 5000 元素 ≈ 0.6 s、`WINDOW` ≈ 20 s。先例是 M5 裁决:把 `RANGE`
单独沉回 R2 才让 §6.6 符合性工作负载重新可跑。**在 L0 之前扩 std 只会放大
这个根因**,所以本目录把 L0 排在最前,并在 L2 的三份里写成硬前置。

**三条路径,请业主选一条**(本目录不替业主决定):

- **甲 · 并入 v0.11.3**(tag 尚未推送的前提):本批分 N 个追加里程碑 M5–M8 落地,
  期间**不得发 tag**;收口时 CHANGELOG 的 v0.11.3 条目与规范册首「本版变更」
  整块重写(成员面 / 命名空间两行数字 + 新增成员清单)。

  `wlwl-v0.11.4-build-plan.md` 收编 15 份方案。**推荐这条** —— v0.11.3 已经
  跑绿 CI 并被 CHANGELOG 宣告收口,再往里塞 55 个成员会让「已收口」这句话
  名不副实,而 tag 一旦发出去就撤不回。
- **丙 · 分两版**:L0 + L1 八份走 v0.11.4(都是新命名空间 / 新能力,边界清楚),

## §5 明确**不列入**本批的 §14 条目

`docs/stdlib/wlwl-stdlib-spec-v0.11.md` §14 还有三条,本次**不**写方案,
理由随附 —— 免得下次又被重新提起:

| §14 条目 | 不列入的理由 |
|---|---|
| `SORT_UNSTABLE` / 选择类原语 | §14.1 **已否决**:现有 `SORT` 的稳定性语义是规范承诺(D11-006 的 D-6 刚写清),引入不稳定排序要同时处理比较器一致性检测与「择序策略决定组间次序」的新口径 = **语义变更**,与「不改可观察语义」冲突,收益(大数组常数因子)不抵一次 breaking |
| R1 预编译快照(替代启动解析) | 属**运行时工程**,不是标准库成员面;应单独立项,且它的价值取决于 L0 完成后 R1 成员还剩多少 |
| 全局内建弃用别名(`DEL` / `POP` / `OR_DIE`)到期移除 | 属**移除**,ADR-0023 §v0.x 1 要求走两步(警告码 + 至少保留一个次版本),与本批的纯新增不同轨 |
