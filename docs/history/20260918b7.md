## 范围 (spec v0.4 §15.9)

| 函数 | 签名 | 行为 |
|------|------|------|
| `TEST(name, body)` | `name: STRING`, `body: FUNCTION` | 注册测试用例到 `Evaluator.test_registry`，返回 `NULL` |
| `ASSERT(cond, msg?)` | `cond: ANY`, `msg: ANY?` | truthy → `OK(TRUE)`；falsy → `ERR(E0046, {code, kind, cond?, msg?})` |
| `ASSERT_EQ(a, b, msg?)` | `a, b: ANY`, `msg: ANY?` | `values_equal` → `OK(TRUE)`；否则 `ERR(E0047, {code, kind, actual, expected, msg?})` |
| `ASSERT_NEQ(a, b, msg?)` | 同上 | 反向 |
| `EXPECT_ERR(expr)` | `expr: ANY` | 是 `ERR` → `OK(payload)`；否则 `ERR(E0049, {code, kind, cond})` |
| `RUN_TESTS()` | | drain registry，运行每个 body，返回 ARRAY of DICT（per §15.9 row 6 schema: `["name", "passed", "duration_ms", "error"?]`）|

**§12.6 ERR 透明传播**：所有 6 个函数对 ERR 输入短路（同 §15.9 §12.6）；assertion ERR 也通过 `RUN_TESTS` 的 `invoke_closure` 路径捕获（`Signal::Return(Err)` 在 closure body 内被 `invoke_closure` 提取为 normal value）。

## 关键设计决策

### 1. Name catalog vs full std module（架构层）

`wlwl:std.test` 走「name catalog + eval-internal BUILTINS」（B6 P4-B6-001 同款）：

- `wlwl-std::test::SPEC.functions` 是**空数组**（path 探测通过即可）
- 真实 6 个 impl 在 `wlwl-eval/src/test.rs::BUILTINS`
- `Evaluator::load_std` 检测 path == "wlwl:std.test" 时绕过 `spec.functions` 循环，从 `wlwl_eval::test::BUILTINS` 表（`NativeInvoke::Builtin(BuiltinFn)`）绑定

原因：`TEST` body 是 closure（必须 invoke_closure），`RUN_TESTS` 也是 closure（drain + invoke）。std 边界（B5 P4-B5-006）拒绝 `Value::Closure` 转 E0030。

**6 个函数都放 eval**（包括 `ASSERT` / `ASSERT_EQ` / `ASSERT_NEQ` / `EXPECT_ERR` 这 4 个无 callback 的），理由同 collection B6：避免「ASSERT works, TEST doesn't」类部分成功部分失败的 surprise。

### 2. `EXPECT_ERR` 加入 §12.7 ERR consumer registry

`EXPECT_ERR(expr)` 是 spec §15.9 row 5 的「期待这个表达式失败」原语。**不加 ERR-consumer 状态，它要 inspect 的 ERR 本身会被 §12.6 在 builtin dispatch 前短路**，产生 top-level E0102 而不是 spec 承诺的 E0049。

把 `EXPECT_ERR` 加进 `ERR_CONSUMER_REGISTRY`（9 → 10 项）：

```rust
const ERR_CONSUMER_REGISTRY: &[&str] = &[
    "IS_OK", "IS_ERR", "OR_DIE", "UNWRAP_OR", "TRY",
    "UNWRAP", "ERR_PAYLOAD", "WRAP", "TYPE",
    "EXPECT_ERR",  // Phase B7 / §15.9
];
```

spec §12.7 末段：「Adding a new entry requires a spec upgrade (§18 / appendix D)」—— 这是 §15.9 §12.7 联合扩展点。

### 3. `Evaluator.test_registry` 字段（per-evaluator state）

```rust
pub(crate) test_registry: Vec<crate::test::TestEntry>,
```

每个 `Evaluator` 实例独立持有测试用例列表：
- `TEST(name, body)` push 一个 `TestEntry { name, body: Value }`
- `RUN_TESTS()` drain（`std::mem::take`）—— 这样 TEST 内 nested 测试也能正确处理（虽然不推荐）

`pub(crate)` 让 `wlwl_eval::test::BUILTINS` 模块能 push，`test::TestEntry` struct 也暴露让外部构造。

### 4. RUN_TESTS 的 `Signal::Return` 处理（**关键陷阱**）

`invoke_closure` 在 line 3081-3089 处理 signal：
- `Signal::Return(v)` → 转成 `Outcome::normal(v)`（**关键**：`Signal::Return(Err(payload))` 会被解包为 normal `Value::Err(payload)`）
- `Signal::Break` / `Signal::Continue` → E0014

也就是说，ASSERT 在 closure body 内返回 `Value::Err(payload)` 时：
1. body eval 结束 → `Outcome { value: Value::Err(payload), signal: None }`（因为 ASSERT 是 call 不是 TRY，没 emit Return）
2. invoke_closure 直接返回这个 outcome
3. RUN_TESTS 读 `outcome.value == Value::Err(payload)` → 判 failed

**TRY 不在 top-level 捕获 Value::Err** —— TRY 是 §12.7 的「early-RETURN from the enclosing function」，emit `Signal::Return(Err)`。顶层无 consumer 时变 E0102。所以「`TRY(ASSERT(FALSE, ...))`」在顶层**不能**捕获 ASSERT 的 ERR。

**正确的捕获载体是 `RUN_TESTS`**（它内部走 invoke_closure，已经解包 Return signal）。`RUN_TESTS` 的 ERR-catch 通过 `invoke_closure` 内部的 `Signal::Return(Err)` → `Outcome::normal(Err)` 转译实现 —— 这就是 spec 「RUN_TESTS 用 TRY 捕获每个 TEST」的实际含义。

锁测试：`b7_assert_false_is_e0046_via_run_tests`（失败 case 走 RUN_TESTS 验证 E0046 payload）。

### 5. ERR payload schema

每个 assertion 失败时返回 `Value::Err(DICT)`，payload 字段：

| 错误码 | kind | payload 字段 |
|--------|------|--------------|
| E0046 | `test_assertion_failed` | `code, kind, cond?, msg?` |
| E0047 | `test_assertion_eq_failed` | `code, kind, actual, expected, msg?` |
| E0048 | `test_assertion_neq_failed` | `code, kind, actual, expected, msg?` |
| E0049 | `test_expect_err_failed` | `code, kind, cond` |

锁测试：`b7_assert_eq_unequal_is_e0047_with_actual_expected`（actual/expected 字段锁定）。

### 6. RUN_TESTS result DICT schema

每个测试结果 DICT 至少含 `name` / `passed` / `duration_ms`：
- failed → 加 `error` 字段（assertion ERR payload）
- passed with non-NULL return → 加 `return_value` 字段

`passed` 是 BOOLEAN；`duration_ms` 是 INTEGER（`as_millis()` 截断到 i64）；其他字段是 spec §15.9 row 6 schema。

### 7. TRY 不被加进 ERR_CONSUMER_REGISTRY 的原因（防止回归）

TRY 是 lexer keyword（`Expr::Try`）—— 不走 `Expr::Call` 路径，根本不进 `eval_call`。所以 TRY 在 ERR_CONSUMER_REGISTRY 也无用（registry 是 for `Expr::Call` names）。TRY 通过 `eval_expr` 的 `Expr::Try` arm 自己消费 ERR —— 见 `wlwl_eval/src/lib.rs` `Expr::Try` arm。

### 8. RANGE-style `step.checked_add` 饱和策略

`RUN_TESTS` 用 `Instant::now()` 记录开始时间，`as_millis()` 截断到 i64。不可能 i64 溢出（~292M 年才饱和），无需饱和处理。
