## 3. 交叉验证与发现

静态声称与动态读数**逐条对得上**的项记「对齐」（§1–§2 表中 ✅）。  
排除夹具后仍对不上的，记为发现：

### F1（新发现）— `E0103` 报告 span 在「绑定 + 裸实参」形态下退化为 `1:1` ✅ **已修（2026-10-24）**

| 形态 | 程序 | 期望 span | 修前 | 修后 |
|---|---|---|---|---|
| 容器形参 + 绑定 | `LET(x, CALL(f, [ERR("boom")]))` | 调用点 `2:8` | **`2:8`** ✅ | **`2`** ✅ |
| 容器形参 + 语句 | `f([ERR("boom")])` | 调用点 | **`2:1`** ✅ | ✅ |
| **裸实参 + 语句** | `f(1, ERR("boom"))` | 调用点 | **`2:1`** ✅ | ✅ |
| **裸实参 + 绑定** | `LET(_r, f(1, ERR("boom")))` | 调用点 `2:8` | **`1:1`（dummy）** ❌ | **`2`** ✅ |

- **诊断条数始终为 1**（无假阳性/假阴性）；仅 **span 错误**。
- 契约表 `x21_rest_param_token_contract.rs` **只覆盖容器形** `[ERR(...)]`，未钉「裸实参 + 绑定」⇒ **覆盖缺口**。
- 与既有的「span 归位提案」（报在被调方函数体）**不同源**：这里是**回退到 dummy span**，更伤工具链/LSP。
- **严重度**：中低（语义正确，定位错误）。

**修法（已落地）**：`Binding` 新增 `origin_span`（值表达式位置 / 形参的调用点）⇒
`report_pending_unconsumed` 优先钉它。新契约 `e0103_span_contract.rs` 7 例（四象限全覆盖）；
负向验证退回块 span ⇒ 4 条绑定形态红 / 3 条回归绿。

### F2（边角）— 插值内 `\"` 转义引号触发 `E0002` ✅ **提示已补（2026-10-24）**

- `PRINT("T ${AT_K(mp, \"k\", \"?\")}")` → `E0002`（现附修复提示：`${}` 内是表达式上下文，用 `"` 不要 `\"`）
- `PRINT("T ${AT_K(mp, "k", "?")}")` → **正常**
- 规范 §1.8 写明 `${}` 内是**完整 Expression**、词法阶段按括号配对定界；`\"` 是**外层字符串**的转义写法，用在表达式上下文本身不合法。  
  **判定**：非语义缺口；错误提示已改进。**严重度**：低。
