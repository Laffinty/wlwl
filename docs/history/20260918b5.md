## 三个待决项的裁定（B5 报告 Q1/Q2/Q3）

### Q1：`STR` 是全局 builtin 还是 std.format only？→ **全局 builtin**

裁定依据：spec 附录 G（行 3663 起标注"规范性"）的全局内建注册表里 `STR` 是独立一行——
`STR | STR(x) → STRING | ERR 消费者 ❌ | 宏函数 ❌ | 引入 v0.2`。它不在 §15.8 std.format 的
暴露表里；§10.6 行 1283 说 FORMAT 的插入值"STR 语义见 §10.3"，即 STR 属于 §10.3 字符串操作族。
plan §3 B5 行 435 的"`args[i]` 非 STRING / 非 DICT → `STR(args[i])` 转换"依赖的正是这个全局 STR。

实现：`builtin_str(x) = Value::display()`——与 `PRINT` 对非 STRING 参数的渲染同源
（appendix G PRINT 行："args 不是 STRING → STR(args)"），保证 STR / PRINT / FORMAT 三者渲染一致。

### Q2：FORMAT 走 builtin call（路径 A）还是 lex keyword + AST variant（路径 B）？→ **路径 A**

裁定依据：附录 G 的 FORMAT 行（行 3707）：`FORMAT | FORMAT(template, args...) → STRING | ERR 消费者 ❌ | 宏函数 ❌ | v0.4`。
**宏函数列 = ❌** 是规范性答案——路径 B（lex keyword + `Expr::Format` variant）会把 FORMAT 变成
宏函数，直接违反注册表。plan §4.2 行 1034 的 `Format(Box<Expr>, Vec<Expr>)` AST sketch 是示意
性质，与 spec 冲突时以 spec 为准（§10.6 行 1264 也只定义函数形式 `FORMAT(template, args...)`）。

路径 B 的理论收益（compile-time 解析 template）由运行时 `format_cache` memoization 替代——
plan §5.5 行 1192 本来就要求"相同 template 复用解析结果"，缓存后循环场景每次迭代只剩一次
HashMap 查找 + 渲染。

顺带收益：走 `Expr::Call` 通用路径意味着 §12.6 ERR 透明传播、E0022 arity、E0020 未定义名
全部免费获得，零新机制。

### Q3：E0038 / E0039 / E0033 是否允许 B5 顺手补？→ **补，且必须补**

裁定依据：§14.4 类型段（行 2016-2029）把 **E0030-E0039 十个码整段钉在 type bucket**，
每个码都有语义、retryable=FALSE、引入版本 v0.4。当前 enum 跳号（缺 33/38/39）是历史增量
问题，不是 spec 留白。补号后 type bucket 无洞，AI 工具按码路由不会遇到"未知码"。

- `E0039`（FORMAT 模板解析失败）→ 本批启用
- `E0038`（RANGE step=0）→ 码注册，发射点 B6
- `E0033`（strict_types 违例）→ 码注册，发射点 Phase E

## 关键设计决策（与 B3 / B4 同密度）

### 1. 模板语法单点化：`wlwl_std::format::parse_template`

FORMAT 有两条入口（全局 builtin 渲染 `Value`；std.format 模块渲染 `StdValue`），
但语法只有一份——`parse_template(&str) -> Result<Vec<FormatSegment>, StdError>` 放在
wlwl-std，builtin 侧直接调用。`FormatSegment` 三变体：

```rust
pub enum FormatSegment {
    Literal(String),      // 占位外文本；游离的 `}` 也是字面量
    Positional(usize),    // {012} 全 ASCII 数字
    Named(String),        // {name} 非空非全数字
}
```

parse 与 render 分离：**"未匹配"是 render 期概念**（取决于 args），只有"无法解释"才是
parse 期 E0039（unclosed `{` / 空 `{}`）。全数字但超出 `usize` 的占位（如 `{99999999999999999999999}`）
永不匹配，parse 期折叠为 `Literal`——不报错（它语法上合法），render 时自然保留原样。

### 2. named 查找扫"第一个 DICT"，不是字面 args[0]（deviation P4-B5-004）

§10.6 行 1268 字面说"从 `args[0]`（必须是 DICT）按 key 取值"。但 spec 自己的 mixed 例子
（行 1269）`FORMAT("hi {0}, age {age}", "alice", ["age": 30])` 里 dict 在 args[1]——
字面 args[0] 会让规范自己的例子输出 `{age}` 字面。实现为扫 format args 找第一个 DICT：

- 纯 named pattern（行 1277 例子）：第一个 DICT 就是 args[0]，与 §10.6 完全一致
- mixed pattern（行 1269 例子）：扫描是让该例子产生合理输出的唯一解释

eval 侧用 `dict_lookup`（值相等查找，与 B1 INDEX_GET 同款）；std 侧用 `serde_json::Map::get`。
DICT 键的相等性语义两边一致（STRING 键）。

### 3. E0039 走 B4 `current_span` 机制定位到 call site

`builtin_format` 里 parse 失败时，diagnostic 的 location 取 `ev.current_span`（B4 引入的
save/restore 机制，原本只有 `builtin_unwrap` 用）——E0039 指向 FORMAT 调用处而非
`<runtime>` 占位。`b5_format_unclosed_brace_is_e0039_span_aware` 断言 `location.file == "t.wl"`。

### 4. `Evaluator.format_cache`（plan §5.5 缓存要求）

```rust
format_cache: HashMap<String, Rc<Vec<wlwl_std::format::FormatSegment>>>,
```

key 是 template 全文，value 是 `Rc` 共享的 parse 结果——cache hit 是一次指针 clone。
unbounded 设计，与 module cache 同一取舍（运行格式化 N 个不同 template 就留 N 个小
segment 向量）。`b5_format_in_loop_with_constant_template`（FOR 循环 + 常量 template）和
`b5_format_cache_same_template_different_args`（同 template 不同 args 不串值）锁定。

### 5. 双入口渲染的两条已知差异（deviation P4-B5-006）

| | 全局 builtin 路径 | IMPORT 路径 |
|---|---|---|
| 值世界 | `Value` | `StdValue` (serde_json) |
| 闭包 / native fn | 渲染 `<fun(x)>`（STR 语义） | E0030（std 边界既有契约，invoke_std 统一拒绝）|
| DICT 键序 | 插入序 | serde_json::Map 序（BTreeMap，未开 preserve_order）|

可渲染值的输出两边逐字节一致（`b5_format_global_and_std_paths_agree` 用 spec mixed 例子锁定）。
闭包差异是文档化行为，不是 bug——std 边界对**所有**模块都拒绝闭包。

### 6. `builtin_str` 不进 ERR consumer registry

附录 G 两个码的 ERR 消费者列都是 ❌ → §12.6 默认透明传播在 `eval_call` 入口生效，
`STR(ERR("e"))` / `FORMAT("{0}", ERR("e"))` 都在 arg eval 阶段短路，顶层表现为 E0102
（与 B4 顶层陷阱同款，测试直接断言 E0102）。

## 反思（本次踩到的坑 / 决策复核）

1. **B5 报告的"3 个待决项"其实是伪问题**：Q1/Q2 的答案都在附录 G 这个**规范性**注册表里
   （STR v0.2 行、FORMAT 宏函数 ❌ 行），Q3 的答案在 §14.4 整段表里。教训：plan 的示意性
   sketch（§4.2 `Expr::Format`）与 spec 规范性条文冲突时，先查附录 G 再发问卷。
2. **E0102 顶层陷阱依旧**：`FORMAT("{0}", ERR("e"))` 直接顶层断言会得到 E0102 而非 E0030——
   这不是 bug，是 §12.6 的正确行为（FORMAT 不是 ERR consumer）。测试按 B4 经验直接断 E0102。
3. **serde_json Map 无序 vs Value::Dict 插入序**：双入口渲染 DICT 时键序可能不同（未开
   preserve_order feature）。`b5_format_global_and_std_paths_agree` 特意用单键 dict 的 mixed
   例子避开键序敏感断言；多键 dict 的键序差异记录在 P4-B5-006，v0.5 若开 preserve_order
   feature 可消除。
4. **wlwl-toml / lexer / parser 的 7 个既有 warning** 与本批无关（基线 diff 验证零新增，
   `/tmp/base_warns.txt` vs `/tmp/cur_warns.txt` 逐行相同）。
