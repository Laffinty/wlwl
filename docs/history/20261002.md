### 四块扩展要点

**M1 `wlwl:std.encode`(6 成员,R2)**:base64(RFC 4648)/ hex / percent-encoding
(RFC 3986),零第三方依赖。**失败口径分两类**:编码永不失败;解码失败返 ERR **值**
(`kind = "DecodeError"`,带 op / reason)—— 不叫 DomainError,「`SQRT(-1)`」和
「base64 少一个字符」必须可分。解码不做有损替换(非 UTF-8 报错,不换 U+FFFD);
base64 收 `+/` 与 `-_` 两张字母表;`URL_DECODE` 的 `+` 不折空格(form-urlencoded
的规则不是 RFC 3986 的)。契约 39 条,**期望值取自 RFC 原文而非实现输出**。

**M2 `wlwl:std.text`(`TO_UPPER` / `TO_LOWER`,R2)+ `std.str` 检索**:
完整 Unicode 简单大小写,**零 Unicode 数据文件**(走 Rust `char` 内置查表)。
修的是静默错误结果:全局 `UPPER("straße")` = `STRAßE`。全局 `UPPER`/`LOWER`
**不动**(替换是 breaking;契约测试专门钉住它们仍是 ASCII-only)。长度会变
(`ß`→`SS`;希腊词尾 `Σ`→`ς`)。计划里的第三个成员 `COUNT_SUB` 是重复的,已撤
—— 起草时把「无字符串检索」记成 GAP-3 的依据探错了名字(`FIND` 是**数组**成员,
`std.str::COUNT` 早就是非重叠计数);空 `sub` 三个成员统一 `E0030`。

**M3 `std.collection` +10 成员(R1)**:`CHUNK` `WINDOW` `DEDUP_BY` `MIN_BY`
`MAX_BY` `SUM` `PRODUCT` `FOLD_RIGHT` `POSITION` `KEY_BY`。`CHUNK`/`WINDOW` 的
`n < 1` 报 `E0030`(**0 会让循环不终止**,不照 `TAKE` 的「负数给 `[]`」);两者在
`n > LEN(arr)` 时方向相反(一块 vs 零块)。`FOLD_RIGHT` **迭代实现**而非递归
(递归深度 = 数组长度,十万级直接 `E0101` 爆栈)。`DEDUP_BY` 用 DICT 记已见键
(真 O(n),不照抄 `UNIQ` 的线性扫);键按 `STR` 渲染,`1` 与 `"1"` 撞键。
`MIN_BY`/`MAX_BY` **借用 `SORT_BY` 的比较原语 `_SORT_LT(NULL, …)` 做单遍扫描**
—— 口径与 `SORT_BY` 逐字相同,成本从「不可用」降到可用。`POSITION` 0 起下标、
pred 必填(可选谓词会滑向真值语义)。成本剖面首次有实测数字(debug 档):`CHUNK`
n=5000 0.6 s,`WINDOW` n=5000 20.5 s(输出本身 Θ(n·k) + `PUSH` 拷贝)。

**M4 `std.math` +21 成员(16 R2 内核 + 5 R1 门面)**:超越函数族
(`LN` `LOG2` `LOG10` `EXP` `SIN` `COS` `TAN` `ASIN` `ACOS` `ATAN` `ATAN2`
`SINH` `COSH` `TANH` `TRUNC` `POW_MOD`)与整数数学(`SIGN` `DIV_CEIL` `GCD`
`LCM` `IS_SQRT`)。**`TRUNC` 与全局 `INT` 的差别只在界外**(`|x| ≥ 2^53` 时
`TRUNC` 原样返回,`INT(1e20)` 抛 E0035 中止)。`LN(0)` 返 `-inf`(与 C/Python/Go
及 §7「±inf 原样」一致);域违例返 `ERR([kind: DomainError])` **值**。
`POW_MOD` 归 R2:门面算不出中间积是否溢出(平方-乘中间值可达 `m²`,`m` 可以是
`2^61-1`),内核用 i128;**用欧几里得余数而非 Rust `%`**(后者符号跟左操作数走,
成员名是 mod 不是 rem)。`DIV_CEIL` 只收整数(浮点 `E0030` 不悄悄提升);
`SIGN` 恒返回 INTEGER;`IS_SQRT` 二分上界取 `MIN(n, 3037000499)`
(= floor(sqrt(i64::MAX)),否则 `n = 2^62` 时 `mid*mid` 溢出)。本册**只发
`LN`/`LOG2`/`LOG10` 三个固定底**,不发带基数参数的 `LOG`(契约册专门断言
`LOG` 不是成员)。

**M5 裁决(均已登记)**:不加 `SORT_UNSTABLE`(引入不稳定排序是语义变更,与本批
非目标冲突);不做 `std.rand`(默认播种削弱可复现卖点,显式播种需先裁决
「全局状态 vs 显式传递」,要出 ADR)。

**明确推迟清单(§5.6)**:NFC/NFD 规范化(UCD 数据成本,「明确不做半张表」——
只覆盖 Latin-1 的 NFC 会让 `==(NFC(a), NFC(b))` 在部分输入上返 TRUE,调用方据此
建索引然后在 CJK 上炸);`std.iter` 惰性迭代(等批次 B);`std.rand`(等 ADR);
`std.time`(参照 Go 1.24 `testing/synctest` 的「假时钟气泡」出 ADR —— **本语言
最该抄的一个标准库形态**);`SORT_UNSTABLE`(单独提案)。

## 2026-10-01 · v0.11.0 多维度审查报告(原 wlwl-v0.11.0-review.md)

> 方式:静态四路并行源码审查(wlwl-std + R1 源码 / wlwl-value 值直通 / 双轨机制与
> CLI / wlwl-skill 文本)+ 动态 25 个 `.wll` 测试程序(发布包实测)。静态与动态
> 冲突处一律以实测为准。

**总体判定:批次 A(M1/M2/M3/M5)达到设计目标** —— 成员面与规范/附录 A 逐一对齐、
kernel 不外泄、覆盖轨漂移必须 E0023 且绝不静默回退、`ASSERT` 八假值 breaking 落地、
100 万次循环 0.575 s(预算 30 s);无 P0。

**四个 P1(均不在偏差台账)**:
1. `ABS(INT_MIN)` 静默回绕 —— `builtin_neg` 用裸 `-i`,release 下溢出检查关闭;
   `E0034` 只在 `-` 运算符路径实现。连带推翻 D11-007 的更正前提(「实现走 NEG,
   一直是 E0034」)。
2. `real-ai` 特性编译必炸 —— M2 搬 `StdCtx` 时丢 `http_client` 字段,CI 不跑该
   feature 照不出来。
3. `call_callable` 吞 `Signal::Yield`,违反 wlwl-value 自己写明的穿透契约;测试体内
   `YIELD()` 被记成通过。
4. D11-004 的机制查清:SORT 比较器返 ERR 静默返回原序;真实机制是 `_KIND` 不是
   ERR 消费者,`_KIND(ERR)` 短路使 `_DIAG_E0030` 的实参求值整个短路、**调用从未

## 本批最值得带走的两条

1. **契约用例的输入选取可以掩盖实现缺陷**(N-6):`min_by_empty_array_is_null`
   两条用例存在且绿,缺陷照样活着 —— 因为恒等 key 对 NULL 免疫。冻结契约表时,
   每条用例要问一句「这个输入如果实现错了,断言还会绿吗」。
2. **成员面增长会打断「反成员」断言**(D12-012,第二次发生):为「某名字不是
   成员」写的契约用例,要选**不会被将来补上的名字**(本批选了 `LOG`),否则每次
   扩展成员面它都会被打回一次。
