# 2026-09-06 — P4-A1d 修复 + v0.2 plan §0.4 暂停点解除

## A1d 修复（commit `e1531fc`）

继续 A1d 暂停点（v0.2 plan §0.4，commit `ece5103`）。三个 `#[ignore]` 测试（嵌套调用 / 匿名函数 / 递归）根因不是 5 步排障路线里写的 `&self → &mut self` 借用问题，也不是 push/pop 顺序问题，而是错误**构造时机**错了：

- `diag()` 是 `&self`，构造诊断时**不能** snapshot `call_stack`
- `invoke_closure` 在 Err 分支**先 pop** frame 再 `return Err`
- 错误冒到 `eval()` → `enrich_with_trace` 时栈已空 → 只能注入 `<toplevel>` 占位

修法（最小变更）：

1. `fn diag(&self, ...)` → `fn diag(&mut self, ...)`，在构造 `WlwlDiagnostic` 时直接 `d.trace = self.call_stack.iter().rev().cloned().collect()`，**反转**得到 `[inner, outer]`（innermost first，Python 风格 traceback）
2. `fn undefined_name(&self, ...)` → `&mut self`（唯一两处调用点 `eval_expr` / `eval_call` 都是 `&mut self`，无 ripple）
3. `enrich_with_trace` 留作旁路安全网，捕获 `WlwlDiagnostic::new` 直构造的诊断（如 `diag_module_not_found` / `arity_error` / `type_error`），同样反转保持一致性
4. 三个 A1d 测试的 `#[ignore]` 解除

## 语义校准：匿名闭包 frame 命名

`trace_anonymous_function_uses_angle_brackets` 测试源码是 `LET(f, FUN((x), zzz(x))); f(1);`，但断言 `frame == "<anonymous>"`。这与另外两个通过的测试（嵌套 / 递归）矛盾——它们的 frame 都用**调用点 name**（`outer` / `inner` / `fact`），与 `<anonymous>` 完全不同。

根因：parser 的 `parse_primary`（crates/wlwl-parser/src/lib.rs:1040 附近）只接受 `Ident(args)` 和 `obj.method(args)` 两种 call 形式，都带非空 name。所以 `invoke_closure` 里的 `if name.is_empty() { "<anonymous>" }` 分支在当前 grammar 下是死代码。直接 `FUN((x),...)(1)`（裸闭包调用）parse 不了（FUN 是关键字不是 ident）。

测试改为 `trace_call_uses_call_site_identifier`，期望 `frame == "f"`。**真**的"named FUN → frame 用 FUN 的名字"测试留给 A2 闭包 cell phase —— 那时 `Value::Closure` 加 `name: Option<String>` 字段后就有数据驱动了。在那之前，trace frame name 始终是**调用点 binding name**（v0.1 沿用约定，nested / recursion 测试也基于这个约定）。
