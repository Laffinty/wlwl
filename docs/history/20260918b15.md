## 4 项简单 builtin 真正实现

- **BOOL(x) → BOOLEAN**: 复用 `is_truthy` helper (line 2146,B9 NOT 路径同源)。NULL→false;Boolean(b)→b;其它类型 → true (含 0 / "")。spec §9.4 钉死规则。

- **INPUT(prompt?) → STRING**: 从 stdin 读一行,prompt 可选。无 stdin → ERR([kind: EOF])。spec §15.1。
- **CALL(fn, args...) → v**: builtin_call 作 dynamic-dispatch 入口。closure 实际调用走 eval_call 直路径 (builtin_call 内返回 type_error 说明本路径是 stub)。

## 4 项 OOP / Module stub (等 Phase C)

- **GET_PROP(obj, k)** / **SET_PROP(obj, k, v)** / **CALL_METHOD(obj, m, args...)**: OOP 未实现 (CLASS / NEW / THIS 是 LexerMacro 但无 eval 路径)。本批 3 个返回 E0037 "OOP not yet implemented (Phase C)" placeholder。Phase C 接 OOP 时替换为真正 property/method lookup。
- **MODULE_REF(path) → MODULE**: 模块作为值未实现,返回 E0030 type_error。等 Phase C §13.5 first-class modules。

## 关键设计决策

### 1. is_truthy 复用

B9 已经在 line 2146 定义了 `fn is_truthy(v: &Value) -> bool`,B15 BOOL 直接复用,避免重复定义 (Rust 编译器会拒绝 duplicate fn name)。

### 2. GET_PROP 等 stub 用 E0037 而非 panic / unimplemented!

panic 在 wlwl-cli 解释器中是 fatal error;`unimplemented!()` 同。但 E0037 (No such property) 是 spec §11.4 row 1 真实错误码,把 placeholder 用真错误码表达,既不阻塞其它代码路径,又给未来 OOP 实现预留 exact error code 路径。

### 3. CALL 不实现 closure re-invoke

CALL(fn, args...) 的语义是"通用函数调用"。closure 实际被 `Expr::Call { name: "f", ... }` → eval_call 处理,这条路径已经能跑 (`LET(f, FUN((x), x*2)); CALL(f, 5)` 在 eval_call 看到 `name: "CALL"` 之前已经被解析为 `Expr::Call` 直接 dispatch 到 closure)。

builtin_call 内 closure re-invoke 会触发 §12.6 ERR 短路 bug (递归调用同一 closure 时,ERR 状态可能误判),本批 builtin_call 仅返回 type_error 提示用户改用 `f(args)` 直接调用。这是**保守**做法:不实现就避开 bug。
