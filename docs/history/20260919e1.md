## 三、E1.3(wlwl-eval):Evaluator 字段 + `invoke_closure` 边界检查 + 8 测试

| 项 | 详情 |
|---|---|
| 新字段 | `Evaluator.strict_types: bool`(默认 false) |
| builder | `Evaluator::with_strict_types(on: bool) -> Self`(链式) |
| getter | `Evaluator::strict_types() -> bool`(测试用) |
| 初始化点 | `new()` + `new_with_loader()` 都填 `false` |
| 边界检查位置 | `invoke_closure` 入口,arity 检查之后、captured-cell 升级之前 |
| 比较策略 | case-insensitive(annotation.text.to_ascii_uppercase() vs `value_type_name(v)`) |
| 失败行为 | 仅构造 `E0033` 错误返回;**不**触碰 caller env、不修改 `call_stack`、不修改 captured cells |
| wlwl-eval 测试 | 550 → **558**(+8) |

新测试:
- `e1_strict_types_default_off_no_check` — 默认 off,STRING-for-INTEGER 不报
- `e1_strict_types_on_integer_param_accepts_integer` — 匹配
- `e1_strict_types_on_string_for_integer_param_is_e0033` — 失配,带 related[2]
- `e1_strict_types_unannotated_param_passes_through` — 无 `: Type` 跳过
- `e1_strict_types_mixed_params_only_annotated_checked` — `(x: INTEGER, y)` 中只检查 x
- `e1_strict_types_recursion_checks_each_call` — 自递归每次都查
- `e1_strict_types_uses_uppercase_type_names_case_insensitive` — `: integer` 小写也接受
- `e1_strict_types_builder_round_trip` — `with_strict_types(true/false)` + getter

## 六、未完成 / 推迟到后续 sub-phase

1. **嵌套泛型比较**(`ARRAY[INTEGER]` / `OK[ERR[STRING]]` 等):本批只做顶层 `IDENT` 比较。spec §2.7 钉死"边界检查不强制内层代码",所以本批已 spec-合规。完整 Hindley-Milner 比对是 §17.5 议程。
