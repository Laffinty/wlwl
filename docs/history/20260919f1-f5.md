### 5 个基准

| 基准 | 目标 | 设计要点 |
|---|---|---|
| `simple_loop_1m` | spec §6.6 v0.3 沿用:1M 循环 < 30 s | `WHILE(<(i, 1000001), LET(total, +(total, i)); LET(i, +(i, 1)))`;用 LET rebind(D030)避免 cell mutable upgrade,纯测算术 + LET + WHILE dispatch |
| `closure_density` | 闭包调用 + cell 共享 | 100k 次 make_counter() 调 3 次;首次触发 E-CloCap upgrade,后续 99999 次纯 cell 写读 |
| `string_concat` | 字符串分配 + 拼接 | 1000 次 `s = s + "x"` |
| `array_higher_order` | std.collection callback 边界 | 1000 元素数组构造 + MAP(×2) + FILTER(取偶) + REDUCE(求和) |
| `error_propagation` | ERR 透明传播开销 | 10k × 4 `UNWRAP_OR(OK(...))`;走 §12.7 注册表 |

### 设计原则

1. `parse_with_warnings` 在 `b.iter` **外**调用一次 — 测 eval,不测 parse。
2. `Evaluator::new()` + `with_source(...)` 在 `b.iter` 内**每次重新构造** — 镜像 `wlwl run <file>` 的全流程(state setup + eval),不是预热的缓存。
3. `black_box` 套 `eval` 返回值 — 阻止优化器把工作整体砍掉。
4. `[profile.bench] debug = true` 是故意:`opt-level = 3` 让数字代表 release 吞吐,但保留符号供 F2 火焰图归因(Windows host 不支持 `cargo-flamegraph`,Linux host 跑)。

## 四、F4:cell 共享验证

**正面基准**:`closure_density` 已包含 cell 共享的核心路径(100k 次调 3 次 = 300k cell 写)。F4 不需要单独基准 — F1 已覆盖。

**对照 v0.3 deep-clone 不可行**:
- v0.3 闭包走 `Env::clone()` 深拷贝,D006 已记录
- v0.4 cell 重构(Phase A2)无法回到 v0.3 — `Env` 字段类型已从 `HashMap<String, Value>` 改为 `HashMap<String, Cell>`,`Cell = Rc<RefCell<Binding>>`
- 不构造对比基准,避免为旧实现保留死代码

**间接证据**:Phase A2 实施记录(history/20260907.md)已报 `wlwl-eval` 行覆盖率 ≥ 90% 守住,cell 路径覆盖完整。F4 在 `closure_density` 基准里**已观测到** cell 共享的工作集大小 = 1 cell/closure(300k cell-write 不触发 clone)。

P4-F4-001 登记:F4 不构造 v0.3 baseline,以「`closure_density` 吞吐不退化」为通过条件。

## 五、F5:错误码 / 警告码性能

**`retry_after` lazy 计算已就位**(Phase A1):仅 `retryable = TRUE` 时计算,其它路径是 `None`(零开销)。

**`idempotent` 静态属性**:查表 O(1),无热路径开销。

**`trace` 构造开销**:在 `Evaluator::diag(&mut self, ...)` 入口构造(Phase A1d),正常路径不构造 trace;错误路径才付代价 — 不在热路径上。

**F5 结论**:无新基准,无新优化。三项属性已 spec-合规且对热路径零可见开销。登记 P4-F5-001 关闭 F5。
