## 关键设计决策

1. **Warning 数据通道**:`Evaluator.warnings: Vec<Warning>`,新增 `pub struct Warning { code, message }` + `emit_warning` / `take_warnings` 方法。`Outcome` 故意不携带 warnings——溢出饱和是 evaluator-level 而非 expression-level 现象,绑在 evaluator 上更纯。
2. **`builtin_error` helper**(原 `runtime_error` 重命名):支持 Runtime **和** Type 两类 category——E1003 (Runtime) / E0034 (Type) / E0035 (Type) 都用它构造。`debug_assert!` 放宽到这两类。
3. **`NEG(INTEGER_MIN)` 特判**:`builtin_sub` 检测 `i1 == 0 && i2 == i64::MIN` 时直接抛 E0034(spec §9.5 row 4 显式区分)。其他 INTEGER sub 溢出仍走 W0015 饱和。
4. **饱和方向**:`+` 用 `signum()` 决定正向/负向;`*` 用 `i1.signum() * i2.signum()`;`-` 用 `i1.signum() > 0 || (i1 == 0 && i2 < 0)`。边界 case 都过单元测试。
5. **INT builtin 错误契约**:
   - INTEGER → INTEGER 直传
   - FLOAT → INTEGER 截断;`!is_finite() || |f| > i64::MAX as f64` → E0035
   - STRING → INTEGER parse;失败 → `ERR(["kind": "ParseError", "input", "reason"])`(与 std parse-error 约定一致)
   - 其他 → E0030
6. **INT 不进 §12.7 注册表**:与其他 normal builtin (`+` `-` `*` ...) 一样 ERR 透传。`INT(ERR("e"))` → §12.6 默认 ERR 透传(顶层 → E0102 promotion)。
7. **跨类型相等**:既有 `values_equal` line 1366-1367 已支持 `Integer ↔ Float` 比较;只补了单元测试。无 source 改动。
8. **E0035 当前 dead branch**:lexer 不接受 `1e308` / 无 INF 字面量 / f64 精度在 `i64::MAX as f64` 边界饱和——所以 source-level 无法构造 "FLOAT > i64::MAX"。`int_builtin_float_out_of_range_is_e0035` 测试断言**当前不可达**,登记 E0035 触发路径等 Phase B4 引入 INF/科学计数法。

## 已知 limitations / 后续 phase 工作

- **`E0035` 当前 dead branch**:INT(FLOAT) 在 source-level 无法触发越界,因 lexer 不接受 `1e308` / 无 INF literal。Phase B4 引入 scientific notation 或 INF 字面量后可达。
- **`NEG(x)` 独立 macro**:当前 `NEG(INTEGER_MIN)` 只能通过 `-(0, INT_MIN)` 触发 E0034。Phase B4 引入 `NEG(x)` macro 后可直接写 `NEG(INT_MIN)` 并保留 E0034 路径,文档化更清晰。
- **Warn 暴露给 caller**:`Evaluator.warnings` 内部积累,`take_warnings()` 暴露。当前**没有** CLI / REPL 接通 warning → stderr 输出。Phase E (CLI polish) 时加 `--warn-format=json` 之类。
