# 2026-09-15 — P4-A6: ERR 消费者注册表 (spec v0.4 §12.7)

A4 (MATCH) 收尾后接 A6,本批按 plan v0.2 §3 Phase A6 的"建议 A → F → 收 G"顺序推进。
A6 是 Phase A 的"白名单→注册表"机制落地,改动局部但语义关键——后续 Phase B4
(WRAP cause 链) 和 Phase D (std.ai 真实集成) 都依赖它先把"哪些函数消费 ERR"
钉死。本批改动 ~80 行 + 6 个新测试 + 文档同步。

## 范围 (spec v0.4 §12.7)

把 v0.3 的**封闭 4 项白名单**(`IS_OK` / `IS_ERR` / `OR_DIE` / `TRY`)升级为
v0.4 的**注册表机制**:

- v0.3 §19.4 定理 19.1"仅 4 个函数消费 ERR"失真(v0.4 §E.4.7 修订说明:
  v0.3 定理漏了 UNWRAP,矛盾)
- v0.4 §12.7 改为注册表模型 + 钉死 9 项,新增函数需"消费 ERR"时必须**经 spec 升级**
  加入注册表;实现不得在注册表之外消费 ERR

## 注册表 9 项 (按 spec §12.7)

| 名称 | ERR 时行为 | 实现状态 |
|------|-----------|----------|
| `IS_OK` | 返回 `FALSE` | ✅ 已实现(lexer keyword → Expr::IsOk) |
| `IS_ERR` | 返回 `TRUE` | ✅ 已实现(lexer keyword → Expr::IsErr) |
| `OR_DIE` | 返回 default | ✅ 已实现(lexer keyword → Expr::OrDie)+ builtin_or_die alias |
| `UNWRAP_OR` | 同 OR_DIE | 🆕 本批加 alias 入口(spec §12.7 主推名,Phase B3 完整化) |
| `TRY` | 早 RETURN | ✅ 已实现(lexer keyword → Expr::Try) |
| `UNWRAP` | PANIC E0100 | ⚠️ **注册表钉死,函数未实装**(Phase B4) |
| `ERR_PAYLOAD` | 取载荷 | ⚠️ **注册表钉死,函数未实装**(Phase B4) |
| `WRAP` | 包装 | ⚠️ **注册表钉死,函数未实装**(Phase B4) |
| `TYPE` | 返回 `"RESULT"` | ⚠️ **注册表钉死,函数未实装**(Phase A5 范畴) |

> **未进注册表**: `=` / `!=` / `IF` 三个 spec §12.7 表格里也列出,但脚注明确
> "**不**消费 ERR"(走 §12.6 默认透明传播)。本批在 doc comment 里说清楚:这三项
> 走默认传播,**不**短路 ERR——这与 spec 表格的"明确不消费 ERR" 一致。

## 关键设计决策

1. **数据结构**:从 `matches!(name, "IS_OK" | ...)` 改为 `const ERR_CONSUMER_REGISTRY: &[&str]`
   + `is_err_consumer(name) -> bool` 用 `contains` 查表。Phase B4 / Phase E 扩展时
   改一个 const slice 即可,无需改 lookup 逻辑。
2. **`UNWRAP_OR` alias**:在 `resolve_builtin` 加 `"UNWRAP_OR" => Some(builtin_or_die)`。
   错误消息本批**保持** `"OR_DIE"` 字符串(减少 ripple),Phase B3 统一换名 + emit W0051
   时再改。
3. **未实装函数(UNWRAP / ERR_PAYLOAD / WRAP / TYPE)**:注册表钉死,但 `resolve_builtin`
   仍返回 `None`——调用得 `E0020` 未定义。`eval_call` 第 1803 行 `let whitelisted =
   is_err_consumer(name)` 让 ERR 传到调用点(走消费路径),但最终落到 `undefined_name`
   报 E0020。这是**已知 known gap**,Phase B4 实现 UNWRAP / ERR_PAYLOAD / WRAP 后即关闭。
   `registry_unwrap_not_yet_implemented` 测试作为 tripwire,Phase B4 落地时改断言为
   新行为。
4. **`IS_OK` / `IS_ERR` / `OR_DIE` / `TRY` 在注册表但实际不通过注册表**:
   这 4 个是 lexer keywords(parser 把 `OR_DIE(...)` 转成 `Expr::OrDie` 而不是
   `Expr::Call { name: "OR_DIE" }`),它们走自己独立的 `Expr::*` 分支,**永远不到**
   `eval_call`,所以 `is_err_consumer` 这条 lookup 实际上对它们无效。但 spec §12.7
   把它们列为"注册表成员"——本批把它们留在 const slice 里以**符合 spec 列表**,在
   doc comment 里说明"实际行为由 Expr::* 分支承载,注册表项是为 spec 一致性"。
5. **=` / `!=` / `IF` 不进注册表**:这三个虽出现在 spec §12.7 表格,但表格脚注明确
   它们**不消费 ERR**(走 §12.6 默认透明传播)。不进 const slice,**默认传播**就是正确
   行为。`err_consumer_registry_excludes_equality_and_if` 测试钉死这一行为。

## 实现摘要

### wlwl-eval
- 删除 line 989-997 的 4 项 `matches!`,替换为:
  - `const ERR_CONSUMER_REGISTRY: &[&str] = &["IS_OK", "IS_ERR", "OR_DIE", "UNWRAP_OR", "TRY", "UNWRAP", "ERR_PAYLOAD", "WRAP", "TYPE"]`
  - `fn is_err_consumer(name: &str) -> bool` 用 `ERR_CONSUMER_REGISTRY.contains(&name)`
  - doc comment 解释 §12.7 spec 表格的双层结构(真消费者 vs 行为登记项)
- `resolve_builtin` 加 `"UNWRAP_OR" => Some(builtin_or_die)` 别名入口。
- +6 个 tests(全部在 `wlwl-eval/src/lib.rs` 的 §12.6 ERR transparent
  propagation 段末尾追加):
  - `err_consumer_registry_contains_all_9_names` — 数据结构锁定(HashSet 比较)
  - `err_consumer_registry_excludes_equality_and_if` — `=` / `!=` / `IF` 不进
  - `err_consumer_registry_unknown_returns_false` — `+` / `-` / `PRINT` / `LEN` / `PUSH` / `NOSUCH` 不进
  - `unwrap_or_alias_calls_or_die_impl` — ERR → default / OK → inner / 非 RESULT → E0030 / arity → E0022 四路径
  - `unwrap_or_alias_propagates_through_user_function` — UNWRAP_OR 包用户函数,验证 §12.6 不短路
  - `registry_unwrap_not_yet_implemented` — UNWRAP 注册但未实装 → E0020(B4 tripwire)

### 不在本批改动的文件
- `wlwl-parser`: `OR_DIE` keyword 不动(沿用 Expr::OrDie 路径),`UNWRAP_OR` 不是 keyword
  (由 Expr::Call + resolve_builtin alias 入口承接)
- `wlwl-error`: 无错误码新增(注册表是常量表,不触发新错误码)
- `wlwl-ast`: 无 AST 改动
