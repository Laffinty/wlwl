# 2026-09-15 (续B2) — `DEL` alias + W0051 (spec v0.4 §10.2 / §14.5)

B1 (commit `96639fa`) 把 `REMOVE_KEY` 定为 v0.4 主推名但保留 `DEL` 待 B2 补齐。
spec v0.4 §10.2 行 1193 要求 `DEL` 在 v0.4 是 v0.3 兼容别名,使用触发 `W0051`
弃用警告,v0.5 移除。§14.5 行 2130 定义 `W0051`: "使用 v0.3 已弃用别名
(`DEL` / `OR_DIE`)"。本批 0 行 lexer/parser 改动,1 个新 warning code +
1 个 alias dispatch + 9 个新测试。Phase B 入口第二张牌收口。

## 范围 (spec v0.4 §10.2 + §14.5)

| 项 | 行为 |
|----|------|
| `DEL(d, k)` | v0.3-compat alias of `REMOVE_KEY`;每次调用 emit `W0051` |
| `W0051` | 新 warning code; spec §14.5 "使用 v0.3 已弃用别名(`DEL` / `OR_DIE`)" |
| `REMOVE_KEY` | 不变 (v0.4 主推名,不 emit `W0051`) |

非 spec 范围内(留后续 phase):
- `OR_DIE` → `W0051` 发射 → Phase B3(plan §3 顺序)
- 完全删除 `DEL` → v0.5

## 关键设计决策

1. **ERR 短路先于 alias dispatch**:`eval_call` 在 line ~2405 的 ERR
   short-circuit (`if !whitelisted { ... return Err }`) 先于 builtin
   dispatch,所以 `DEL(ERR("e"), "k")` 透明传播 ERR 且**不**emit `W0051`。
   `del_alias_propagates_err_without_warning` 测试用 `w.is_empty()`
   锁定该行为 — 否则 legacy 调用方会被 ERR 流上的每条 `DEL`
   spam 一份伪警告。
2. **W0051 路由到 Name bucket**:虽然语义是"名字",但 spec §14.4
   给 `W0001` / `W0010` / `W0011` / `W0012` / `W0030` 都是 Name bucket,
   `W0051` (deprecated alias name) 同属 Name。snapshot fixture 加在
   `codes_name.snap`,而不是单独建 `codes_warning.snap`。
3. **3 段 error message**: `` "`DEL` is a v0.3-compat alias; use
   `REMOVE_KEY` instead (will be removed in v0.5)" `` — 三段均包含,
   便于 grep (`grep DEL`) + AI 自动 apply (`s/DEL(/REMOVE_KEY(/g`)
   + 提醒 v0.5 deadline。`del_alias_warning_message_mentions_remove_key`
   测试锁定。
4. **复用 `builtin_remove_key`**:`builtin_remove_key_compat` 是个 5 行
   wrapper,emit 警告后直接调 `builtin_remove_key(ev, args)`。无新逻辑
   path,所有语义与 arity / non-DICT / noop 行为 100% mirror `REMOVE_KEY`。
   `builtin_remove_key` 签名保持 `_ev: &mut Evaluator`(不变),别名 wrapper
   拿到的 `ev` 直接传透。
5. **W0051 = 1 per call**:`del_alias_warning_exactly_once_per_call`
   测试用两条 `DEL` 调用 → 验证 `w.len() == 2`,确保不在循环或递归里
   double-fire。
6. **不动 `W0051` 一侧的 `OR_DIE`**:Phase A6 (commit `9f0c0f6`) 已加
   `OR_DIE` 主推名 `UNWRAP_OR` 的 dispatch alias,**不**触发警告,error
   消息仍 surface as "OR_DIE"。B3 按 plan v0.2 §3 顺序处理
   `OR_DIE` 警告发射 + canonical name 统一化 (`OR_DIE` → `UNWRAP_OR`
   全栈替换)。

```rust
/// v0.4 §10.2 + §14.5 — `DEL(d, key)` is the v0.3-compat alias for
/// `REMOVE_KEY`. Per spec §14.5, every call emits `W0051`. v0.5 will
/// drop this alias entirely.
fn builtin_remove_key_compat(ev: &mut Evaluator, args: Vec<Value>) -> WlwlResult<Outcome> {
    ev.emit_warning(
        ErrorCode::W0051,
        "`DEL` is a v0.3-compat alias; use `REMOVE_KEY` instead (will be removed in v0.5)",
    );
    builtin_remove_key(ev, args)
}
```

紧挨 `REMOVE_KEY` arm,带 spec §10.2 注释。

## 已知 limitations / 后续 phase 工作

- **`WlwlDiagnostic::new` 总是 `severity: Severity::Error`**:`W0051`
  snapshot 因此 render as `"severity": "error"` (尽管 `code.is_warning()`
  返回 `true`)。AI 工具通过 `is_warning()` boolean 区分 warning vs
  error,不影响 routing。修复路径:在 `WlwlDiagnostic::new` 加
  `if code.is_warning() { Severity::Warning }`,跨多 crate 影响面广,
  留 Phase G7 错误信息质量 pass 统一处理 (deviations B2-003)。
- **`OR_DIE` → W0051**:留 Phase B3(plan §3 顺序 + 依赖 A6 已实装
  的 `UNWRAP_OR` dispatch alias)。
- **`DEL` 完全删除**:留 v0.5。
