# 2026-09-07 — P4-A2 闭包 cell 语义落地 + spec v0.4 §6.4 全部对齐

## A2 修复(commit pending)

A1d trace 收尾后接着推 A2,这是 Phase A 的**最大风险项**(plan v0.2 §1.3 评级),目标是把 v0.3 闭包 deep-clone 行为替换为 spec v0.4 §6.4 cell-based capture,实现 `SET` 宏函数和 E0024 错误码。

### 设计要点

1. **Cell 模型**:`Env` 从 `HashMap<String, Value>` 改为 `HashMap<String, Cell>`,`Cell = Rc<RefCell<Binding>>`,`Binding { value, mutable }`。每次 `LET` 创建一个 IMMUTABLE cell。
2. **E-CloCap**(spec 附录 E.4.6):闭包**调用时**升级 captured cells 为 MUTABLE。`invoke_closure` 在安装 captured_scopes 之前,先 walk 一遍 `for cell in captured_scopes.iter().flat_map(|s| s.values()) { cell.borrow_mut().mutable = true; }`。升级一旦发生**永久保留**(同一 cell 后续被其他闭包共享时也已是 MUTABLE)。
3. **Env::clone 走 Rc 浅克隆**:`#[derive(Clone)]` 自动展开,HashMap 克隆时每个 cell 是 `Rc::clone`,O(1) 摊销。这就是 spec "闭包捕获 cell 引用" 的实现基础。
4. **`SET(name, value)` 宏函数**:在 `eval_call` 入口特判(`if name == "SET" { return self.eval_set(...) }`),第一参必须是 `Expr::Var` 不求值,第二参正常求值。`set_cell_value` 走一次性 mutable 检查:`Ok(true)` 写值、`Ok(false)` → E0024、`Err(())` → E0020(走 `undefined_name` 复用 "did you mean?")。

### 关键语义校准(3 个初版测试写错)

初版写了 3 个错误的预期值,跑测试才发现 spec 细节,逐个修正:

1. **`fun_closure_shares_via_cell` → `fun_closure_param_scope_fresh_per_call`**:`LET(mk, FUN((v), FUN((), v))); LET(a, mk(1)); LET(b, mk(2)); +(a(), b())` 的预期是 3 而非 4。**Cell sharing 只针对 persistent outer scope**;`v` 在 mk 的 param 作用域里,每次 mk 调用是 fresh scope,所以两次 mk(1) 和 mk(2) 的 inner closure 各捕获各自的 v cell。这是 v0.3 deep-clone 行为在 param-scoped binding 上的**保留**,不是 bug。spec §6.4 说的 "同一词法位置" 指 closure 创建**当时**所处的 scope,不是该 scope 的"逻辑位置"。
2. **`p4_a2_closure_shared_cell`** 初版用了 `INDEX_GET`(Phase B1 的 builtin,本阶段没有),改用直接 outer-scope 闭包共享 cell 的写法(`LET(s, "init"); LET(get, FUN((), s)); LET(set, FUN((x), SET(s, x))); ...`),不依赖 array 下标语法糖。
3. **`p4_a2_let_set_read_roundtrip`** 初版用 `WHILE` + `SET(i, ...)` 其中 `i` 在外层 LET scope 但没被任何闭包捕获 → E0024(spec 正确!)。改成 `LET(loop, FUN((), ...))` 把 loop 体包成闭包,`i` 被 loop 捕获 → E-CloCap 升级 → SET 合法。
