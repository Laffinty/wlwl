## 关键设计决策

### 1. BuiltinSpec 是 pub const BUILTIN_REGISTRY,零运行时开销

不是 Vec,不是 HashMap —— 是 const slice。lookup() 走 iter().find() 线性扫描 (B11 90 条目,不是瓶颈)。优势:
- 编译期固化,无法运行时漂移
- 注册表大小变化会触发 b11_registry_count_matches_spec_table 锁测试挂掉,任何 spec 升版都要显式 bump 数字
- 不引入 hash 冲突风险 (e.g. PRINT_ERR vs PRINT 不能 hash collision)
- const 数据可以直接在 generate_appendix_g_md() 里用

### 2. 4 个 DispatchStatus 变体,而不是 bool is_dispatched

信息密度高:
- ResolvedBuiltin (clean path,42 个)
- ResolvedCompat (W0051/W0054 警告路径,3 个:DEL / OR_DIE / !)
- LexerMacro (parser 层降为 Expr::*,24 个)
- Deferred (impl 未接,24 个)

未来 Phase B12+ 把 Deferred 项转成 ResolvedBuiltin 时,只需改这一行的 dispatch 字段,锁测试会自动通过。

### 3. generator 与 lock test 共生

- pub fn generate_appendix_g_md() -> String —— 单源真相的渲染函数
- cargo run --bin gen-appendix-g —— cargo bin target,把渲染结果写到 docs/appendix_G.md
- 锁测试 generated_md_includes_all_entries —— 检查生成的 markdown 包含所有 builtin name plus group label

修改流程:
1. 改 BUILTIN_REGISTRY 表
2. cargo run --bin gen-appendix_g
3. cargo test -p wlwl-eval --lib registry 跑锁测试
4. commit

如果忘记跑 (2),lock test 会挂(markdown 还包含旧表)。

### 4. compat alias 显式标 ResolvedCompat

DEL (v0.3 DICT delete,W0051) / OR_DIE (v0.3 alias,W0051) / ! (v0.3 logical not,W0054) 都是 ResolvedCompat:
- 它们的 resolve_builtin(name) 返回 _compat 函数
- _compat 函数先 emit W0051/W0054,再委托 canonical fn
- 锁测试 b11_resolve_builtin_covers_registry 确认 resolve_builtin(name).is_some()
- 未来 v0.5 移除 compat 时,只需把 dispatch 从 ResolvedCompat 改为 Deferred,然后所有 use 都会进 b11_registry_count_matches_spec_table 锁 plus E0020 路径

### 5. 4 个 LexerMacro ERR 消费者不进 ERR_CONSUMER_REGISTRY 运行时表

IS_OK / IS_ERR / TRY / EXPECT_ERR 这 4 个都是 LexerMacro(parser 降为 Expr::IsOk 等),它们在 parser 层就消费 ERR,不走 eval_call 的 §12.6 入口短路。

ERR_CONSUMER_REGISTRY (eval 内 const slice,9 → 10 条 in B7) 是**运行时**白名单,只覆盖 canonical fn 路径的 ERR 消费者 (UNWRAP_OR / UNWRAP / ERR_PAYLOAD / WRAP / TYPE / OR_DIE + EXPECT_ERR)。

锁测试 b11_err_consumer_registry_consistent 双向断言:
- ERR_CONSUMER_REGISTRY 每条 entry 的 err_consumer = Yes ok
- 注册表每个 err_consumer = Yes 且 ResolvedBuiltin/Compat 必须出现在 ERR_CONSUMER_REGISTRY (LexerMacro 例外列白名单)
- 注册表每个 err_consumer = Yes 且 LexerMacro 必须在白名单 {IS_OK, IS_ERR, TRY, EXPECT_ERR}
