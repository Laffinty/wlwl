# Phase G2 实施记录 — cargo-deny 许可证 + 公告门禁(基线版)

> **状态**：Phase G2 基线就位,CI 强制门禁,本地 exit=0(2026-09-19)
> **前置**：Phase G1 完成(clippy zero warning + CI gate)
> **范围**：G2.1（deny.toml 起草 + 0.20 schema 修正）/ G2.2（CI step + version bump）/ G2.3(本地 baseline 跑通)
> **关键决策**:
>   - cargo-deny 版本从 `^0.16` 升到 `^0.20`(0.16 无法解析 RustSec 2026-Q3 新增的 CVSS v4.0 条目;0.20 起 rustsec/cratesio 的 adapter 升级了)
>   - SPDX `GPL-2.0` 是 deprecated 标识符(SPDX 3.11),workspace 全部 14 处(`Cargo.toml` + 9 个 `*.bak3` / `license.workspace = true`) 升到 canonical `GPL-2.0-only`
>   - workspace path 成员依靠 `skip = [{crate, reason}, ...]` 抑制 `wildcard` lint;`allow-workspace = true` 只针对 deny-list 不针对 wildcard,g2.4 测试验证
>   - `allow` 接受 strict short-id + `WITH` 表达式;复合 `OR` / `AND` 走 `exceptions` 逐项声明(ver 在 0.20 不再接受 compound `OR` 在 `allow` 中)
>   -r-efi 的 `LGPL-2.1-or-later` 子句仅在 wasm target 上被 fed-in 到 dep graph,默认 native build 不需要;exception 保留 ahead-of-time 以免未来加 wasm cross-target 后补条

## 三、G2.2 — CI step(已升级到 v0.20)

文件:`.github/workflows/ci.yml`,插入在 clippy 后 / build 前

```yaml
- name: cargo-deny check
  working-directory: impl
  run: |
    if [ ! -f Cargo.lock ]; then
      echo "::group::generate Cargo.lock (first run)"
      cargo generate-lockfile
      echo "::endgroup::"
    fi
    cargo deny --locked --all-features check
```

- `--all-features` 是 cargo-deny 顶层 flag,不是 `check` 子命令 flag(踩过)
- `--locked` 同样在顶层;依赖 `Cargo.lock` 存在
- `cargo install cargo-deny --locked --version "^0.20"` 在本地预测 0.20.2(本地安装 log:13:43 最终 `Installed package cargo-deny v0.20.2` )·CI 也走同一 `^0.20`
