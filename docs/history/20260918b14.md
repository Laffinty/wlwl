## 关键设计决策

### 1. MERGE key 冲突 → b-wins

`MERGE(a, b)` 把 a 的所有 (k, v) 复制到结果 dict,然后遍历 b:
- b 中新 key → 按 b 的顺序追加到末尾
- b 中已有 key → 覆盖 a 的值,**但保持 a 的位置**(不重新排序)

锁测试 `b14_merge_basic_and_key_override` 守住:
```
MERGE(["x": 1, "y": 2], ["y": 99, "z": 3])
= ["x": 1, "y": 99, "z": 3]  // y 在原位置 (a 的顺序),值被覆盖;z 追加到末尾
```

### 2. DICT() 0-arg 不支持

DICT 是 LexerMacro,parser 把 `DICT()` 当 0-token 流,**没有 0-arg arm**。本批测试改用单 key dict 验证 "空" 行为:
- `KEYS(["only": 42])` → `["only"]` (验证 KEYS 正常工作)
- `VALUES(["only": 42])` → `[42]`
- `MERGE(["a": 1], ["b": 2])` → `["a": 1, "b": 2]`

真正的 0-arg DICT() 字面量留 v0.5 (parser LexerMacro 加 `parse_dict_macro` 0-arg arm)。

### 3. 出现顺序保留

KEYS / VALUES 按 dict 内部 Vec<(Value, Value)> 顺序返回,即插入顺序。锁测试 `b14_keys_preserves_order` 守住 3 个 key 的有序返回。
