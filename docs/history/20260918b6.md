## 关键设计决策

### 1. Name catalog vs full std module（架构层）

`wlwl:std.collection` 的 `ModuleSpec.functions` 是**空数组**，真实 17 个 impl 在 `wlwl-eval/src/collection.rs` 的 `BUILTINS` 表。原因：

- `wlwl-std` 整个 crate 不依赖 `wlwl-eval`（避免 cycle），所有 std 函数走 `serde_json::Value`
- `value_to_std_value` 把 `Value::Closure` / `Value::NativeFn` 转成 **E0030**（B5 P4-B5-006 钉死的边界契约）
- 9 个 callback-taking 函数（MAP / FILTER / REDUCE / SORT / SORT_BY / ANY / ALL / FIND / GROUP_BY）的 callback 必须直接 invoke_closure —— std 路径不能跨边界
- 8 个 callback-free 函数（RANGE / ZIP / ENUMERATE / TAKE / DROP / FLAT / UNIQ / JOIN）技术上能放 std，但「同模块部分函数走 std、部分走 eval」会引发「MAP works, SORT doesn't」类意外，把全部 17 个放 eval 更安全

实现：`wlwl-std::resolve("wlwl:std.collection")` 仍返回 `Some(&SPEC)`（path 探测通过），`Evaluator::load_std` 检测 path == "wlwl:std.collection" 时绕过 `spec.functions` 循环，从 `wlwl_eval::collection::BUILTINS` 表（`NativeInvoke::Builtin(BuiltinFn)`）绑定。

### 2. `NativeInvoke::Builtin(BuiltinFn)` 新 variant

```rust
pub(crate) type BuiltinFn = fn(&mut Evaluator, Vec<Value>) -> WlwlResult<Outcome>;
pub enum NativeInvoke {
    Std(wlwl_std::StdFn),                 // 既有
    Builtin(crate::BuiltinFn),             // 本批新增：callback-aware
}
```

`eval_call` dispatch 加新 arm（与既有 `NativeInvoke::Std` 同样 save/restore `current_span`），让 callback 跨 std 边界的诊断保持 call-site span-aware。**这是 std 与 eval 架构的扩展点**：未来需要 callback 的 std 模块（如 B7 `std.test` 的 `RUN_TESTS`，第 1 阶段可能也要走这条路径）可以重用。

### 3. SORT 实现 — `sort_by` 不能 `?`

`Vec::sort_by` 接受 `FnMut(&T, &T) -> Ordering`，没有 `Result` 通道，闭包内不能用 `?`。`SORT` 用 `RefCell<Option<WlwlResult<Outcome>>>` 把失败"park"起来：
- 每次 comparator 失败（ERR / 类型错 / diag）写进 `pending`
- 后续 compare 看到 pending 非 None 直接返回 `Equal`（无副作用）
- `sort_by` 退出后 `pending.into_inner()` 决定正常返值还是短路 ERR

锁测试：`b6_sort_with_custom_comparator_descending`。

### 4. GROUP_BY DICT key 必须 STRING

`wlwl-eval::Value::Dict` 用 `Vec<(Value, Value)>` 表示（v0.3 §10.4 决策，保留插入序）；DICT key 必须是 STRING。GROUP_BY 的 key fn 返回非 STRING 时走 `STR` 语义 coerce（与 FORMAT/PRINT「非 STRING → STR」约定一致）。

测试：`b6_group_by_returns_dict_of_arrays`（key 是 `%(x, 2)` 整数，自动 coerce 到 STRING `"0"` / `"1"`）。

### 5. ANY/ALL truthiness（无 callback 时）

§10.5 row 8/9 说「任一满足（默认恒真）」。我们实现 §9.4 truthiness：
- `Boolean(b) = b`
- `Null = false`
- 其他（Integer / Float / String / Array / Dict / Closure / NativeFn / Ok / Err）= true

锁测试：`b6_any_without_predicate_uses_truthiness`（`ANY([NULL, FALSE, 1, 2]) = TRUE`）。

### 6. UNIQ 用现有 `values_equal`

不去重新实现 §10.4 structural equality —— 直接调用 `crate::values_equal`（与 UNWRAP_OR / = 操作符同源），保证 `UNIQ` 行为与 `= a b` 一致。

### 7. RANGE `step=0` → E0038

E0038 码在 B5 已注册（type bucket, retryable=FALSE）。本批是**首次启用点**。测试：`b6_range_step_zero_is_e0038`。

边界处理：`RANGE` 在 step > 0 时正向，`step < 0` 时反向；`step.checked_add` 饱和（避免 `RANGE(0, MAX, 1)` 死循环），饱和发生在 `i64` 边界，符合 §9.5 overflow-saturation 惯例。

### 8. ENUMERATE / FLAT / UNIQ 的「占位 match」清理

第一次提交里有 `let arr = ...; let _ = arr; let arr = ...;` 的双重 match 模式（borrow checker hack）。重写为单次 match（要么 clone，要么 unreachable!()），更干净。
