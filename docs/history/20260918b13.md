## 关键设计决策

### 1. SUB 重命名为 builtin_substr (避免命名冲突)

旧 `fn builtin_sub` 在 line 1903 已有(早期 SUB 实现,与 B13 SUB 重叠)。为避免冲突,**新 SUB 重命名为 `builtin_substr`**:
- 函数定义: `fn builtin_substr(_ev, args) -> WlwlResult<Outcome>`
- dispatch: `"SUB" => Some(builtin_substr)`

旧 `builtin_sub` 函数保留(向后兼容 dead-code 不影响运行),可在 v0.5 清理。

### 2. ASCII-only case fold

UPPER / LOWER 用 Rust `str::to_ascii_uppercase()` / `to_ascii_lowercase()`:
- a-z → A-Z (lowercase)
- A-Z → a-z (uppercase)
- 非 ASCII char 原样保留 (例如 é / ö / 中 等)

spec §10.3 row 4 "非 ASCII case-fold 是 implementation-defined",我们采取保留策略。完整 Unicode case-fold 留 v0.5。

### 3. SUB / SLICE 都用 chars() 而非 bytes()

Python-style 半开区间切片:
- `SUB("héllo", 1, 4)` → `"éll"` (codepoint-aware)
- `SLICE("héllo", -2)` → 末尾 2 个 char → `"lo"`

不是按字节切 (UTF-8 多字节 char 中间切断会破坏编码)。

### 4. REPLACE 空 old → E0030 / SPLIT 空 sep → E0030

避免运行时死循环 / 未定义行为:
- `REPLACE("hello", "", "x")` 永不收敛 → E0030
- `SPLIT("hello", "")` split 行为未定义 → E0030

spec 表 row 5/6 没说,但 v0.2 已有约定。
