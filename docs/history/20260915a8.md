# 2026-09-15 (续A8) — 比较返回类型规则 (spec v0.4 §9.2)

A7 (commit 1852d42) 收尾后接 A8——把 spec §9.2 的"v0.4 重大修订"落地为
**0 impl 改动 + 测试 lock-down**。v0.3 同时声明"比较返回类型总是 BOOLEAN"
和"= 不在白名单 → =(ERR, 1) 返回 ERR"——矛盾。v0.4 §9.2 钉死消除矛盾,
A6 (commit 9f0c0f6) 的 §12.7 注册表已合规: `=` / `!=` 不进注册表, 走 §12.6
默认 ERR 透明传播, 行为符合 spec §9.2。A8 工作边界 = 0 impl 改动 +
8 个测试 lock-down + 文档同步。

## 范围 (spec v0.4 §9.2)

| 场景 | 行为 |
|------|------|
| 两个操作数**均非 ERR** | `=` / `!=` / `>` / `<` / `>=` / `<=` 返回 `BOOLEAN` |
| **任一**操作数是 ERR | 比较函数**透明传播** ERR (§12.6); **不**返回 BOOLEAN |

## v0.3 → v0.4 矛盾修复 (spec §9.2 line 1059-1068)

v0.3 同时声明两个互相矛盾的规则:
1. `比较运算符的返回类型**总是** BOOLEAN`(v0.3 §9.2)
2. `=` 不在白名单 → `=(ERR, 1)` 返回 ERR(走 §12.6 transparent propagation)

这两条在 `=(ERR, 1)` 上打架——`=` 不能既"总是返回 BOOLEAN"又"返回 ERR"。
v0.4 §9.2 通过"按入参情况分情形"解决矛盾: 仅当两操作数**均非 ERR** 时
返回 BOOLEAN, 否则透传 ERR。**白名单扩展为零判定**: 比较函数对 ERR
透明, 仅当入参全部 OK 时返回 BOOLEAN。

## 关键设计决策

1. **A8 = 0 impl 改动**: A6 (commit 9f0c0f6) 把 `=` / `!=` / `IF` 标注为"不进
   ERR_CONSUMER_REGISTRY, 走默认传播"。`>` `<` `>=` `<=` 同样不在注册表
   (`ERR_CONSUMER_REGISTRY` line 1091 显式列出 9 项不含比较符)。`eval_call`
   line 1935-1944 的 §12.6 short-circuit 自动处理 ERR 透明传播——无需
   spec §9.2 单独改动。
2. **测试 lock-down 范围**: 加 8 个测试覆盖 (a) 6 个比较符 × ERR 透传路径
   (每个 op 两个方向: ERR 左侧 / ERR 右侧); (b) `==(ERR, ERR)` leftmost-
   ERR-wins 验证; (c) happy path 8 个 BOOLEAN 返值确认。
3. **顶层 ERR → E0102 promotion 的测试模式**: ERR 顶层 promote 到 E0102,
   测试用 `IS_ERR(...)` 消费 ERR 返回 TRUE 验证 ERR 透传(与 A5 的
   `err_payload_validation_only_runs_when_arg_evaluates_ok` 同模式)。
4. **跨文档 cross-ref**: §9.2 与 §9.5 row 10 (跨类型相等) 协同——`=(1, 1.0)`
   视为相等是 §9.5 钉死的, §9.2 钉死的"两操作数非 ERR 时返回 BOOLEAN"
   把 `=` 与其他比较符的 ERR 处理统一了。deviations P4-A7-003 已 lock-down
   跨类型相等测试。
