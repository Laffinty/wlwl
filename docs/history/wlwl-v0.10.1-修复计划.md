## 2 批次 A · 阻断性

### 2.1 R10-010 · 清单缺 `[package]` 时静态层静默失效

**根因**(`impl/crates/wlwl-cli/src/main.rs:620-622` 与 `:640-642`,两处同款)

```rust
let Ok(manifest) = wlwl_toml::manifest::parse(&src) else {
    return GradualTypingSetting::default();   // ← 静默
};
```

`wlwl-toml/src/manifest.rs:198` 的 `validate()` 要求 `package.name` / `version` / `entry` 齐备,
缺任一项 → `parse` 返回 `Err` → 回落 `Off`。

**实测**

| 清单 | 输出 | rc |
|---|---|---|
| 只有 `[features]` | `OK: parsed main.wll (39 bytes)` | 0 |
| 只有 `[features]`,值写错 `"sideways"` | `OK: parsed main.wll (39 bytes)` —— **连 `W0001` 都没有** | 0 |
| 完整 `[package]` + `"error"` | `error[E0110]: annotation mismatch` | 1 |
| 完整 `[package]`,值写错 | `OK` + `warning[W0001]` | 0 |
| 无清单 | `OK` | 0 |

这正是 ADR-0020 自己在注释里写的纪律「不静默吞笔误」的反例,而且比动态 REVIEW 描述的更严重:
**整个清单层无声,不只是特性值没被读到**。

**影响**:①用户严格按 `CHANGELOG.md:20-22` / `SKILL.md:41-43` / spec §9.4 写清单 → 静态层永不执行 →
退出码 0 → 误以为「我的类型都对」;②随包发布的 `wlwl-skill/examples/static_contracts.wll`
从不触发任何静态检查;③CI 里项目根只要没有完整 `[package]`,整个静态层就是装饰。

**修法**(待 D-1 裁决,本计划推荐 a + b):
- **a(必做)**:解析失败时发 `W0001`,把静默变成响亮。`main.rs:783-808` 已有现成的
  `W0001` 回执通道(`invalid_value` 分支),新增一个 `manifest_unusable` 变体即可,
  两个 `load_manifest_*` 函数共用一个解析结果,不重复发。
- **b(可选)**:让 `[features]` 可独立于 `[package]` 生效 —— `manifest.rs` 增加一个
  「宽松解析」入口只读 `features` 表,供这两个 loader 使用。

**锁测试**:①`[features]` 单段 + `"error"` → 必须出现 `W0001`;②`[features]` 单段 + 值写错 →
必须出现 `W0001`;③完整清单 + 值写错 → 仍只有一条 `W0001`(不重复发);
④无清单 → 零诊断(守住 ADR-0020 S1)。

**兼容性**:a 不改变任何程序的可观察行为(默认仍 `Off`),只增加诊断;仅当 b 落地时,
原本静默失效的项目会**开始**执行静态层 —— 那是用户显式写了 `[features]` 的本意,
但必须登记为 D10-NNN 并在 CHANGELOG 申报。

### 2.3 R10-012 · `CLASS` / `INSTANCE` 的 `==` 恒 `FALSE`

**规范**:`spec:206` §2.4(v0.9 起,规范性)「`CLASS`/`INSTANCE` 按**对象身份**恒等 … 同一实例与其别名相等」。

**实测**

```wlwl
LET(C, CLASS("C", NULL, []));  LET(a, NEW(C));  LET(b, a);
PRINT(==(a, b), ==(a, a), ==(NEW(C), NEW(C)), ==(C, C));   →  FALSE FALSE FALSE FALSE
```

自反律 `a == a` 都不成立。同段对照 `==(f, f)` / `==(h, h)` / `==(h, h2)` 全部 `TRUE`
—— 身份比较机制存在,只是 `Class` / `Instance` 两个类型没接进去。
`wlwl-skill/SKILL.md:61` 写的是对的,实现是唯一的异类。

**修法**:把 `Value::Class` / `Value::Instance` 接入已有的身份比较路径(句柄 / 闭包那条),
按 `Rc::ptr_eq` 或既有句柄语义二者取一并补 doc。

**锁测试**:①`==(a, a)` → `TRUE`;②`LET(b, a); ==(a, b)` → `TRUE`;
③`==(NEW(C), NEW(C))` → `FALSE`;④`==(C, C)` → `TRUE`、`==(CLASS("C",…), CLASS("C",…))` → `FALSE`;
⑤实例放进 `DICT` / `ARRAY` 当键时,同实例命中、异实例不命中。

**配套**:R10-071(OOP 身份 conformance 夹具)。
**兼容性**:这是修 bug,但对「依赖实例值比较」的既有程序是**行为变更**(原本恒不等)——
必须登记 D10-NNN 并在 CHANGELOG 申报。

### 2.5 R10-014 · 无缓冲通道:生产者先 `SPAWN` 必假死锁

**规范**:`spec:1491`「对端到达或通道关闭时被唤醒」;`spec:1661`「同一通道上互为对端的挂起收发双方**不**构成死锁」。

**实测**(同一个程序,只改 spawn 顺序)

| 顺序 / 缓冲 | 结果 |
|---|---|
| `CHANNEL_NEW(0)` 生产者先 | `E0065: deadlock … 2 task(s) parked on channel op(s) with no peer to wake them` rc=1 |
| `CHANNEL_NEW(0)` 消费者先 | `1` rc=0 |
| `CHANNEL_NEW(1)` 两种顺序 | `1` rc=0 |

**机制**:`p` 先跑,`CHANNEL_SEND` 在无缓冲通道上无等待接收方 → 挂起;`c` 后跑,`CHANNEL_RECV`
有等待发送方(`p`)→ 按 §17.2.1 应**立即唤醒 `p`**,但实现没有唤醒,先做了死锁判定。

**影响**:阻塞型 `CHANNEL_SEND` / `CHANNEL_RECV` 实际上顺序敏感且不可预测,文档里没有任何地方提示;
`wlwl-skill/SKILL.md:382-401` 的 canonical shape 本身就跑不通(在 `SCOPE` 主体里直接 `CHANNEL_RECV`
→ `E0053`;搬进任务里又撞 `E0065`)。

**修法**:唤醒等待对端**之后**再做 L1 死锁判定;补一条「生产者先 spawn」的金标准夹具(R10-072);
修正 `SKILL.md` 的 canonical shape(改用缓冲通道,或把消费侧也 `SPAWN` 且保证接收方先就位)。
`strict_deadlock_detect = false` 的降级档(`W0065` + `E0053`)要一并复验。

**兼容性**:死锁判定的时序变了。这是**修 bug**,但会让一批原本假死锁的程序开始正常完成 —— 申报 D10-NNN。

### 2.6 R10-015 · §17「挂起对程序文本透明」未兑现

| 1452 | `LET(x, YIELD()); x` | `NULL` | `error[E0020]: undefined name 'x'` |
| 1456 | `LET(y, YIELD); y()` | 等价于 `YIELD()` | `error[E0020]: undefined name 'YIELD'` |

## 3 批次 B · 实现缺陷

### 3.1 R10-020 · `wlwl fmt` 产出不可重解析源码

**实测**(注意 `wlwl fmt <file>` 默认只输出到 stdout,不写盘)

```
输入  : LET(d: DICT<STRING>, 1); PRINT(d);
        → check rc=0(可解析)
fmt   : LET(d: < STRING >[], 1);
        PRINT(d)
落盘  : → error[E0010]: expected type expression, got `<`   rc=1
```

`DICT<STRING>` 解析成 `Generic{name:"< STRING >", args:[]}`,formatter 把空 `args` 的
`Generic` 渲染成 `< STRING >[]`,再解析即失败。**空 `args` 的渲染形是输出非法输入的唯一路径。**

**修法**:`Generic { args: [] }` 不渲染成 `name[]`,而是按 `Named` 的形态渲染 `name`。
补幂等 / 往返测试(fixed P0-1 那轮只补了 match default 一条)。
**锁测试**:每一种 `TypeExpr` 变体各一条「fmt 输出再 parse 必须成功」。

### 3.2 R10-021 · `SEALED` 出现在任意表达式位置

`PRINT(SEALED(["x"]))` 被接受为模块声明并求值为 `NULL`,而 `spec:1760` 明写
「`ModuleDecl` 只出现在模块顶层,**不作为 `Expression`**」。

**注意取舍**:`c0d8652` 修 R10-003 时明确选择了「没有任何 `SEALED` 形态会让 parser 硬失败」,
理由是反过来硬判错会破坏「任何 v0.9 程序默认可观察行为不变」。位置校验属于**位置**约束而非
**语法**约束,收紧它不会破坏这条承诺 —— 但会让 `PRINT(SEALED(["x"]))` 从「运行期得 `NULL`」
变成「编译期报错」。

**修法**:在 `parse_sealed` 成功之后检查当前位置是否在顶层块;不是则回退普通调用
(与 R10-003 的回退路径同款,保持「要么声明要么普通调用」的不变式)。
补一条规范条目说明这个回退语义(R10-003 遗留的「`SEALED` 歧义未写进 §9.1」一并补)。

### 3.3 R10-022 · 密封分支 `E0023` 绕过 `self.diag()`
