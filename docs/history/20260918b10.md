## 范围 (spec v0.4 §15.1)

| 函数 | 输出 | 返回 |
|------|------|------|
| `PRINT(...)` | stdout (`println!`) | NULL |
| `PRINT_ERR(...)` | **stderr (`eprintln!`)** | NULL |
| `INPUT()` | stdin (1 line) | STRING |

`PRINT_ERR` 与 `PRINT` 的语义**唯一差异**是输出流 —— 值格式化（`Value::display()`）、参数 join（空格分隔）、null 返回完全相同。

## 关键设计决策

### 1. 双 dispatch 入口（global + std 同形）

跟 `PRINT` 完全同款：
- **global** (`resolve_builtin` 表) — `PRINT_ERR` 注册为 `builtin_print_err`，用户**不 IMPORT 也能用**
- **std 模块** (`wlwl:std.io::SPEC`) — `PRINT_ERR` 注册为 `std_print_err`，IMPORT 后 `eval_call` 走 user-env binding 优先级

两路径用同一 `eprintln!` + 同一 `Value::display()` + 同一 join。

锁测试：
- `b10_print_err_returns_null`（global）
- `b10_print_err_via_std_module`（std 路径）
- `b10_print_and_print_err_coexist_in_std_io`（两者并存不互相 shadow）

### 2. 不在 §12.7 ERR_CONSUMER_REGISTRY

`PRINT_ERR` 是 **side-effect sink**（往 stderr 写），不是 value observer。ERR 进它毫无意义（你把 ERR 写到 stderr 之后，ERR 仍然存在但被消费了 —— 与 §12.6 默认行为冲突）。

按 plan §5.10 / spec §12.7 末段约定：ERR-consumer registry 扩展需要 spec upgrade（§18 流程）。`PRINT_ERR` 不消费 ERR → 沿用 §12.6 默认透明传播 → input ERR 在 eval_call 短路 → top-level E0102。

锁测试：`b10_print_err_input_err_is_e0102`。

### 3. 不加 `StdCtx.stderr` 字段（deferred to Phase D / E）

`wlwl-std` crate 用 `serde_json::Value` 而非 `Value`，std 边界不带 evaluator 状态。`StdCtx` 现在只持 argv / env vars。

加 `stderr: Box<dyn Write>` 字段（用于测试捕获 stderr 输出）：
- **优点**：跨 std 边界可测试 stderr 字节
- **代价**：跨进程 I/O 的多线程 / 异步语义要重新设计；测试需要构造 mock writer

权衡：本批不加，理由：
- 用户侧用法明确（`PRINT_ERR("x");` 写 stderr，仅此而已）
- 跨 std 边界捕获测试是 Phase F perf / E2E 范畴（plan §6.5）
- 现 `eprintln!` 在测试时会污染 test runner 输出，但**不会导致测试失败**（stderr 与 test stdout 是分开的）

记录为 **deviations P4-B10-001**：未来若需要 stderr 字节测试，加 `StdCtx.stderr` 字段（Phase D / E）。

### 4. stderr 字节实际捕获：未在单元测试覆盖

锁的是**接口契约**（return NULL、arity、接受多参数、std 路径存在、ERR transparent），不锁**字节**。
实际字节流测试需要：
- `assert_cmd` crate（process-level 2>&1 重定向）
- 或 `gag` / 自定义 `dup2` 钩子

这两个是 Phase F (perf benchmarks + e2e .wll) 范畴，本批不引入。记录为 **deviations P4-B10-002**。
