## 0 导言

### 0.1 本规范的构成

本规范定义 WLWL 程序设计语言:词法、语法、类型与值、求值规则、错误模型、模块系统、面向对象与行为类型(§13–§16)、并发(§17)、标准库与诊断。

**规范版本约定**:规范正文采用 `major.minor` 双段。新引入内容追加 patch 段(如 `v0.9.1`)仅用于 errata,不另发规范文件。历史性"不承诺"行的 `[v0.7.0]` 等 `[vN.M.P]` 标记是版本快照,后续修订不动;新写章节使用 `v0.9`(省略 patch 段)。

**章节号冻结**:§13 / §14 / §15 / §16 与 §17.8 的章节号在 v0.9.0 上冻结;后续修订**可以**向既有小节追加子小节,**不得**重新编号或把新内容回填为更低章节号。

WLWL 是一门**动态类型、前缀函数式**的语言:

- **一切都是表达式**。没有语句与表达式的二分;每个构造求值后产生一个值。
- **一切运算皆调用**。没有中缀运算符;算术、比较、逻辑都是具名函数,按 `name(arg, ...)` 前缀形式调用。
- **默认不可变**。绑定一旦建立即指向固定值;容器操作返回新容器而非修改原容器;状态突变只能经由 `LET MUT` 显式声明的单元格进行(对象字段的突变规则见 §13.4)。
- **错误即值**。可恢复错误是 `RESULT` 值,沿调用链透明传播,由显式的消费者函数处理。

### 0.2 读者

本规范面向三类读者:WLWL 程序员、语言工具(格式化器、静态检查器、编辑器)的实现者,以及参考实现本身的维护者。

### 0.3 规范性用语

本规范中的关键词 **必须**(MUST)、**不得**(MUST NOT)、**应当**(SHOULD)、**可以**(MAY)按以下含义使用:

- **必须 / 不得**:实现的硬性约束。违反时实现必须产生一个诊断(第 11 章)并按第 11.4 节终止或报告。
- **应当**:强烈推荐的行为;实现可以偏离,但偏离必须在本规范或实现文档中说明。
- **可以**:真正的实现自由度。

标注为**非规范**(non-normative)的段落、注释与附录不构成一致性要求。

### 0.4 一致性

一个 WLWL 程序是符合本规范的,当且仅当它只使用本规范定义的语法形式与语义,且不依赖任何标注为未定义、保留或实现定义的行为。一个实现是一致的,当且仅当它接受所有一致的程序并产生本规范规定的结果。

### 0.5 记法

语法用扩展巴科斯范式(EBNF)书写,记法约定见附录 A。正文中 `code` 样式表示词法记号、字面代码或诊断码;`name` 斜体表示文法产生式。示例代码以 `//` 注释标出其求值结果。

## 1 词法结构

### 1.1 源文件

一个 WLWL 源文件是一个 **必须** 为 UTF-8 编码(带或不带 BOM)的字节序列。换行可以是 `\n`、`\r\n` 或 `\r`,三者等价。源文件是一个模块(第 9 章)。

### 1.2 注释

- `//` 开始一个**行注释**,延伸到行尾。
- `/*` 与 `*/` 界定一个**块注释**。块注释**必须**正确嵌套。
- `///` 开始一个**文档注释**,延伸到行尾。文档注释只在词法上与行注释相区别,**不得**影响程序语义。

注释中出现的任何字符序列(除上述定界规则外)都是注释的一部分。

### 1.3 标识符

```
identifier = letter { letter | decimal_digit | "_" } .
```

`letter` 含 Unicode 字母类别(含中文)。标识符区分大小写。非 ASCII 标识符是合法的;工具**应当**在诊断中如实回显。

以 `_` 单独出现的标识符是**通配符**,见 3.1 与 7.3。

### 1.4 关键字

```
TRUE    FALSE   NULL    LET     FUN     RETURN
IF      WHILE   FOR     BREAK   CONTINUE
CLASS   NEW     THIS    NOT
```

关键字不得用作标识符。`CLASS`、`NEW`、`THIS` 的语义见 §13 与 §15:它们出现在调用形式 `CLASS(...)`、`NEW(...)`、`THIS()`(或零参引用 `THIS`)中,分别构造类、实例化对象、引用当前实例。

`MUT` 是**上下文关键字**:仅在 `LET` 之后的位置具有特殊含义(3.1);其他位置可作普通标识符使用,不与关键字冲突。

### 1.5 运算符记号

以下记号是内建运算函数名,可用前缀调用形式书写(4.3、4.6):

```
+   -   *   /   %   ==  =   !=  <   >   <=  >=  &&  ||  !
```

`=` 的角色由**文法位置**唯一决定:

1. 出现在 `OpToken` 位置(`=` 后紧跟 `(`)→ 相等函数调用 `=(a, b)`,与 `==` 同义(注册表 `Eq => "=="` desugar,见 §4.3)。
2. 出现在 `Postfix` 形式的 `=` 位置(`... [ Expression ] "=" Expression`)→ `INDEX_SET` 语法糖(见 §4.5)。
3. 出现在形参表 `Param` 内(`name = Expression`)→ 默认值分隔符(见 §5.2)。

三者互不重叠,无需词法前瞻。

`=` 与 `==` 在调用位置同义(都指相等函数);`!` 与 `NOT` 关键字(1.4)同义,两种形式均无警告。

### 1.6 整数字面量

```
int_lit        = decimal_digit { decimal_digit } .
int_literal   = [ "+" | "-" ] int_lit .
```

> **实现注(非规范)**:`lexer` 不消费前导符号;`+x` / `-x` 在解析期被改写为 `+(0, x)` / `-(0, x)`,再走 §4.3 二元运算路径。`NEG(x)` 是独立的 1 元内建(注册表 §4.3),仅按名调用可达,parser 不合成。可观察行为与"前导符号字面量"等价:同 INTEGER_MIN 边界、同 §2.2 溢出语义。

整数值是有符号 64 位整数。运算结果超出该范围的规则见 2.2。

### 1.7 浮点字面量

```
float_lit      = digits "." digits | digits exponent | digits "." digits exponent .
exponent       = ( "e" | "E" ) [ "+" | "-" ] digits .
```

浮点值是 IEEE 754 双精度数。整数与浮点字面量统称**数字字面量**。

### 1.8 字符串字面量

```
string_lit     = '"' { string_element | interpolation } '"' .
string_element = any_char_except_quote_backslash_newline_dollar | escape .
interpolation  = "${" Expression "}" .
escape         = "\" ( "n" | "t" | "r" | "\" | '"' | "/" | "0" | "b" | "f" | "$" ) .
```

字符串是 Unicode 码点的不可变序列。承认的转义:`\n` 换行、`\t` 水平制表、`\r` 回车、`\\` 反斜杠、`\"` 引号、`\/` 斜杠、`\0` 空、`\b` 退格、`\f` 换页、`\$` 字面 `$`。其他转义**不得**出现(`E0001` 或 `E0002`)。

**字符串插值**:`"Hello, ${name}!"` 中 `${...}` 内的表达式按完整表达式语法求值;求值结果以 `STR`(10.3)渲染后嵌入字符串;求值若产生 `ERR` 则按 8.2 透传,整个字符串字面量表达式的结果为该 `ERR`。

### 1.9 布尔与空字面量

`TRUE`、`FALSE` 产生布尔值;`NULL` 产生空值。

### 1.10 分号

处于"语句位置"的表达式**必须**以 `;` 结束。在括号序列(4.7)内部,最后一个表达式的 `;` **可以**省略;该表达式的值即括号序列的值。省略必需的 `;` 产生 `E0013`。

## 2 类型与值

### 2.1 值域

WLWL 是动态类型语言:类型属于值而非名字。值的论域由以下**类型**构成:

| 类型 | 含义 |
|------|------|
| `NULL` | 空值,唯一成员 `NULL` |
| `BOOLEAN` | `TRUE` 或 `FALSE` |
| `INTEGER` | 有符号 64 位整数 |
| `FLOAT` | IEEE 754 双精度浮点数 |
| `STRING` | Unicode 码点的不可变序列 |
| `ARRAY` | 值的不可变有序序列 |
| `DICT` | 从键(STRING 或 INTEGER)到值的插入序映射,不可变 |
| `FUNCTION` | 闭包(5.5) |
| `RESULT` | `OK(v)` 或 `ERR(e)` 变体(第 8 章) |
| `TASK` | **[v0.7 追加]** 任务句柄;`SPAWN`/`TASK_CURRENT` 返回(§17.1) |
| `CHANNEL` | **[v0.7 追加]** 通道句柄;`CHANNEL_NEW` 返回(§17.2) |
| `CLASS` | **[v0.9 追加]** 类对象;`CLASS` 构造器返回(§13.2) |
| `INSTANCE` | **[v0.9 追加]** 类实例;`NEW` 返回(§13.3) |

数组与字典字面量见 4.8;`TYPE(x)` 返回上表名称的字符串(`RESULT` 两个变体都报 `"RESULT"`)。

类型名(`NULL`/`BOOLEAN`/`INTEGER`/`FLOAT`/`STRING`/`ARRAY`/`DICT`/`FUNCTION`/`RESULT`/`TASK`/`CHANNEL`/`CLASS`/`INSTANCE`)是 `TYPE` 返回的字符串,**不**构成标识符绑定。命名空间成员可以与类型名同名(如 `wlwl:std.agent.TASK`),二者在各自作用域中独立解析。`TYPE` 的参数位置不做名字解析 — 它取运行时值,返回字符串,过程中不查任何名字表。

`TYPE` 对句柄报 `"TASK"` / `"CHANNEL"`,对类对象报 `"CLASS"`,对实例报 `"INSTANCE"`。句柄的真值按 2.3「其余一切值为真」;相等按 2.4;显示形态见 2.5。

**键的约束**:字典的键必须是 `STRING` 或 `INTEGER`。NaN(2.2)**不得**作键(`E0031`)。

### 2.2 算术性质

- 整数运算按二进制补码语义进行;`+`、`-`、`*` 溢出时**抛错** `E0035`(`INTEGER` 与 `FLOAT` 越界共用此码)。`NEG` 于 `INTEGER` 下界取负产生 `E0034`。
- `/(a, b)` 当两操作数为整数时是**截断除法**(商向零取整):`/(7, 2)` 为 `3`,`/(-7, 2)` 为 `-3`。两操作数为浮点时是浮点除法,可产生 `Inf`/`NaN`。
- `b` 为零时 `/(a, b)` 产生 `E1003`(整数、浮点皆然,即使 IEEE 754 允许 `Inf`)。
- `%(a, b)` 只接受整数:`a - /(a, b) * b`,符号与被除数一致;`b` 为零产生 `E1003`。任一实参是 `FLOAT` 时产生 `E0030`(类型错)。

### 2.3 真值

**假值**恰为八个:`FALSE`、`NULL`、`0`、`0.0`、`""`、空数组、空字典、`NaN`。**其余一切值为真**,包括非空数字、非空字符串、非空容器、`OK(FALSE)` 之类的 `RESULT` 值、以及 `CLASS` / `INSTANCE` 值。

真值仅由 6.1 的 `IF`、6.2 的 `WHILE`、`&&`、`||`、`NOT`、`BOOL` 以及模式匹配以外的谓词位置消费。

### 2.4 相等

`==(a, b)`(别名 `=`,1.5)与 `!=(a, b)`:

- 数字跨类型比较:`==(1, 1.0)` 为 `TRUE`。
- 字符串按码点逐位比较;布尔、空按恒等。
- 数组按长度与逐元素深度相等;字典按键集与逐键值深度相等(受上一条 NaN 规则影响:含 NaN 的容器与任何值都不等)。
- 函数按闭包实例引用相等。
- `RESULT`:`OK(a) = OK(b)` 当且仅当 `a = b`;`ERR(e1) = ERR(e2)` 当且仅当 `e1 = e2`;`OK` 与 `ERR` 永不相等。
- 任一操作数为 `ERR` 变体时,比较函数**不**求布尔,而是透明传播该 `ERR`(8.2)。
- **[v0.7 追加]** `TASK` / `CHANNEL` 句柄按句柄身份恒等:同一句柄与自身相等,不同句柄不相等。
- **[v0.9 追加]** `CLASS` / `INSTANCE` 按**对象身份**恒等:同一类对象与自身相等,两次 `CLASS(...)` 调用产生的类对象不相等,即使成员相同;同一实例与其别名相等,两次 `NEW(...)` 产生的实例不相等,即使字段值相同。该规则比照句柄的身份相等,不改变上列既有类型规则。

### 2.5 显示

`PRINT`(10.2)与 `STR`(10.3)将值渲染为文本:布尔为 `TRUE`/`FALSE`,空为 `NULL`,数组为 `[e1, e2, ...]`,字典为 `[k: v, ...]`,函数为 `<fun(params)>`。`STR` 对字符串恒等;对浮点保留小数表示(整数产生的浮点显示一位小数,如 `2.0`)。

**[v0.7 追加]** 句柄显示为 `<task handle id=N gen=M>` / `<channel handle id=N gen=M>`。

**[v0.9 追加]** 类对象显示为 `<class Name>`(匿名类为 `<class>`);实例显示为 `<Name instance>[N fields]`(匿名类实例为 `<instance>[N fields]`),其中 `N` 为实例字段个数。显示形态仅供诊断,**不得**作为程序判等或解析依据。

## 3 变量、作用域与单元格

### 3.1 绑定

`LET(name, value)` 在**当前作用域**为 `name` 建立一个**不可变绑定**,并将 `value` 存入新创建的**单元格**(cell)。`LET` 表达式本身的值是 `NULL`。

`LET MUT(name, value)` 建立**可变绑定**:单元格的可变标志在创建时即置为真,允许后续 `SET`(3.4)改写。

```
LET(x, 1);              // 不可变
LET MUT(count, 0);      // 可变
```

`LET` 的第一个实参**可以**是解构模式,此时按模式同时建立多个绑定;模式必须与值精确匹配,失配产生 `E0026`:

```
LET([a, b], [1, 2]);            // a=1, b=2
LET([head, *rest], [1, 2, 3]);  // head=1, rest=[2, 3]
LET(["k": v], ["k": 9]);        // v=9
LET([_, x, _], [1, 2, 3]);      // x=2
```

模式形态的完整定义见 7.3。`LET MUT` 仅接受简单标识符,不支持解构。

### 3.2 作用域与遮蔽

作用域由**函数体、括号序列(4.7)、`FOR` 循环体、`MATCH` 分支体**引入,以及每个模块的顶层。作用域按词法嵌套。

- 内层作用域中的 `LET` **总是**在内层新建单元格;若外层已有同名绑定,内层绑定**遮蔽**外层。
- 同一作用域中对同一名字再次 `LET` 是**重绑定**:旧绑定被替换。
- 读一个不存在的名字产生 `E0020`(附最近候选名)。
- **没有**变量提升:在 `LET` 之前读名字产生 `E0020`。

### 3.3 单元格可变性

每个绑定由一个单元格实现,单元格持有值与一个可变标志。可变标志由绑定形式决定:`LET` 建立的为不可变,`LET MUT` 建立的为可变。该标志一经设定**不再改变**。

当一个闭包捕获某单元格时,捕获环境保留对该单元格的引用;不论该单元格是 `LET` 还是 `LET MUT` 所建立,闭包均按原标志判定是否可写。多个闭包可共享同一单元格。

```
LET(make_counter, FUN((),
    (LET MUT(count, 0);
     FUN((), (SET(count, +(count, 1)); count)))
));
LET(c, make_counter());
c();   // 1
c();   // 2 — count 的单元格在闭包间共享
```

这是 WLWL 中唯一的原位状态突变机制(对象字段的突变是第二条显式路径,见 §13.4)。循环累加等命令式惯用法应当经由 `LET MUT` 与 `SET` 表达,或 `REDUCE`(10.6)。

### 3.4 SET

`SET(name, value)` 将 `name` 当前绑定的单元格改写为 `value`:

- 名字不存在 → `E0020`。
- 单元格不可变(由 `LET` 建立而非 `LET MUT`)→ `E0024`。
- `SET` 表达式的值是 `NULL`。

`SET` 对不可变单元格产生 `E0024`,不论该写入发生在单任务内还是跨任务(§17.1)的共享单元格上;跨任务与单任务路径统一,不存在独立的跨任务错误码。

### 3.5 遮蔽内建

`LET` 或命名函数定义(5.1)遮蔽第 10 章的内建名时:默认产生 `E0025`;当模块清单声明 `[features] allow_builtin_shadow = true` 时允许并产生警告 `W0030`。遮蔽保留关键字(1.4)产生 `W0030`。

## 4 表达式

### 4.1 操作数

操作数是字面量(第 1 章)、标识符、括号序列(4.7)、数组与字典字面量(4.8)、或下文定义的各构造。

### 4.2 调用

```
Call = identifier "(" [ Expression { "," Expression } ] ")" .
```

调用将实参自左向右全部求值后执行被调者。被调者不是函数值时产生 `E0020`。

`CLASS`、`NEW`、`THIS` 以关键字身份出现在调用位置(1.4),文法上按具名调用解析;`THIS` 也可单独作为零参引用出现(§15.1)。

### 4.3 运算符即函数

所有运算符都是具名函数,以 1.5 的记号作前缀调用:

| 调用 | 语义 | 结果 |
|------|------|------|
| `+(a, b)` | 数字相加(整数与浮点混合提升为浮点);字符串拼接;数组拼接 | 同类 |
| `-(a, b)`、`*(a, b)` | 减、乘;类型规则同上 | 数字 |
| `/(a, b)` | 除法,见 2.2 | 数字 |
| `%(a, b)` | 整数取余,见 2.2 | 整数 |
| `NEG(a)` | 取负 | 数字 |
| `==(a, b)`、`!=(a, b)` | 相等、不等(`=` 是 `==` 的别名) | 布尔 / ERR 透传 |
| `<(a, b)`、`>(a, b)`、`<=(a, b)`、`>=(a, b)` | 比较;数字按数值,字符串按码点序 | 布尔 / ERR 透传 |
| `&&(a, b)` | 合取,**短路**:`a` 为 `ERR` 时透传 ERR(不求 `b`);`a` 为假值时不求 `b`,返回 `FALSE`;否则求 `b`,返回 `BOOL(b)`(`b` 为 `ERR` 时透传) | 布尔 / ERR 透传 |
| `\|\|(a, b)` | 析取,**短路**:`a` 为 `ERR` 时透传 ERR(不求 `b`);`a` 为真值时不求 `b`,返回 `TRUE`;否则求 `b`,返回 `BOOL(b)`(`b` 为 `ERR` 时透传) | 布尔 / ERR 透传 |
| `NOT(a)` | 真值取反 | 布尔 |

- `+`、`-`、`*`、`/`、`%`、`CONCAT` 是**严格二元**的;实参数不符产生 `E0022`。
- 任一操作数为 `ERR` 时,所有运算符调用按 §8.2 透明传播 — **包括 `NOT`**。`BOOL(x)` 是单独的 `ERR` 消费者(§8.3 表),与 `NOT` 不对称,但两者都返回布尔真值;`BOOL(ERR(...))` 不传播,`NOT(ERR(...))` 传播。如需安全取反,请先经 `BOOL`:`NOT(BOOL(ERR(...)))` → `FALSE`(短路等价于 `!TRUE`)。`&&`/`||` 短路求值中,未求值那一侧的 `ERR` 不被传播(因为它没被求值)。
- `NOT` 与 `!` 接受任何值并按真值表返回布尔。

### 4.4 括号序列(块)

```
Block = "(" [ Expression ";" ] { Expression ";" } [ Expression ] ")" .
```

括号序列按顺序求值其中的表达式;其值是最后一个表达式的值。空括号序列 `()` 的值是 `NULL`。

### 4.5 下标

```
Index = Expression "[" Expression "]" | Expression "[" Expression "]" "=" Expression .
```

`a[i]` 是 `INDEX_GET(a, i)` 的语法糖;`a[i] = v` 是 `INDEX_SET(a, i, v)` 的语法糖。两者可以与 4.6 的属性链自由组合:`a[0].b`、`a.b[0][1]`。

- `INDEX_GET(coll, k)`:数组接受整数索引(负数自尾部计数,`-1` 为末元素),越界产生 `E0036`;字典按键取值,键类型不符产生 `E0031`,键不存在产生 `E0037`;**字符串接受整数索引**,按码点返回单字符字符串,越界产生 `E0036`。
- `INDEX_SET(coll, k, v)`:接受数组或字典,返回**插入或更新后的新容器**;接收者不变(见 2.1 不可变性与附录 B)。`INDEX_SET` 不接受字符串(`E0030`)。
- 下标链可挂在变量、调用、属性访问、**或数组/字典字面量之后**。`[1, 2, 3][0]` 与 `["a": 1]["a"]` 都是合法表达式,等价于 `INDEX_GET` 对字面量直接求值;`[[1,2][0], 3]` 同样合法。

### 4.6 属性与方法

```
Selector = Expression "." identifier [ "(" [ Expression { "," Expression } ] ")" ] .
```

`a.b` 是 `GET_PROP(a, "b")` 的语法糖;`a.b(args)` 是 `CALL_METHOD(a, "b", args...)` 的语法糖。接收者可以是字典(模块也是字典,9.4)或 `INSTANCE`(§13):

- `GET_PROP(obj, k)`:键不存在产生 `E0037`;`obj` 不是 `DICT` 或 `INSTANCE` 产生 `E0030`。
- `a.b(args)` 调用 `a` 的 `"b"` 成员。当被调成员是**闭包**且其**第一个形参名为 `self`** 时,接收者 `a` 作为首实参自动注入,即等价于调用 `f(self=a, 其余实参...)`;形参命名不影响绑定之外的语义,首个形参**不**叫 `self` 时不注入。`CALL_METHOD` 亦遵守该注入规则,**不得**再显式传入接收者。
- 当被调成员是内建函数值(标准库注入)时,**不**注入接收者:`io.PRINT("hi")` 等价于 `PRINT("hi")`。
- 成员存在但不可调用时产生 `E0030`。

### 4.7 求值顺序

实参、括号序列各元素、数组与字典字面量的各元素,都按源代码顺序自左向右求值;除 6.1、6.2 与 `&&`/`||` 的短路语义外,不存在条件求值。`&&`/`||` 的短路路径只求值被选中的那一侧。

### 4.8 数组与字典字面量

```
ArrayLit = "[" [ Expression { "," Expression } ] "]" .
DictLit  = "[" Key ":" Expression { "," Key ":" Expression } ]" .
Key      = Expression .
```

- 第一项无 `:` 时为**数组字面量**;第一项为 `k: v` 时为**字典字面量**;空字面量 `[]` 恒为空数组。空字典只有一种写法:`DICT()`(10.9)。
- 同一字面量中混用裸值与键值对产生警告 `W0020`。

## 5 函数

### 5.1 定义

```
Function = "FUN" [ identifier ] "(" ParameterList ")" Expression .
```

- `FUN((params), body)` 产生一个**匿名函数值**。
- `FUN(name(params), body)` 产生同样的函数值,**并**在当前作用域将 `name` 绑定到它——与 `LET(name, FUN(...))` 等价。两种形式的函数值相同,表达式的值都是该函数值。

**规范性澄清**:`FUN(name(params), body)` 与 `LET(name, FUN(...))` 等价,二者表达式的值都是该函数值;`LET(name, value)` 的值是 `NULL`(绑定动作已完成,无值可传递)。`LET` 因此**不得**作为实参或运算符操作数(语义上是"声明"而非"值表达式")。如需在表达式位置产生绑定效果,请用 `LET MUT` + `SET` 序列或将值绑定到一个 `FUN` 表达式。

### 5.2 形参

形参列表由以下形态组成(按位置排列):

| 形态 | 含义 |
|------|------|
| `name` | 必需参数 |
| `name = Expression` | 默认参数;缺省实参时求值该表达式。默认表达式在**被调函数的词法帧**内求值,因此可以引用更外层的捕获与排在其前的形参 |
| `*name` | 剩余参数;收集多余的实参为**新数组**。只**可以**出现在末位 |
| `name: Type`、`name: Type = Expression` | 类型注解。运行时忽略,除非模块清单开启 `strict_types`(9.4),此时在调用边界按 `TYPE` 名做顶层形状检查,失配产生 `E0033` |

方法约定:实例方法(§13.2.4)的第一个形参**应当**命名为 `self`;该名字是接收者注入(4.6)的触发条件。

### 5.3 调用与元数

设必需参数数为 `R`、形参总数为 `N`(含默认与剩余):

- 无剩余参数:`R ≤ 实参数 ≤ N`。省略的尾部实参由默认表达式填充;无默认而缺位产生 `E0022`。
- 有剩余参数:`实参数 ≥ R`;超出固定形参的实参收集为剩余数组。
- 违反范围产生 `E0022`,消息形如 `expects R..N argument(s), got A`。

### 5.4 函数是一等值

函数值可以存储、传递、返回、放入容器,没有名与值的区别。递归经由顶层绑定即可实现(调用时解析名字):

```
LET(fib, FUN((n), IF(<(n, 2), n, +(fib(-(n, 1)), fib(-(n, 2))))));
```

## 6 控制流

### 6.1 IF

```
If = "IF" "(" Expression "," Expression [ "," Expression ] ")" .
```

`IF` 在条件位置注册为 ERR 消费者:**条件为 `ERR` 时等价于条件为假**——若存在第三实参(else),求 else 并以其值为结果;否则 `IF` 整体透传该 `ERR`。

条件非 `ERR` 时:条件为真(2.3)求第二实参并以其值为结果,否则求第三实参(若有)并以其值为结果,缺省第三实参时结果为 `NULL`。**未求值的分支不产生任何效果。** 分支表达式自身产生的 `ERR` 正常传播。

### 6.2 WHILE

```
While = "WHILE" "(" Expression "," Expression ")" .
```

条件为真时反复求值体。`WHILE` 表达式的值是 `NULL`。体产生的 `ERR` 终止循环并传播。

### 6.3 FOR

```
For = "FOR" "(" identifier "," Expression "," Expression ")" .
```

对可迭代对象逐项求值体。可迭代对象是:数组(逐元素)、字典(按**插入序**逐键)、字符串(逐码点,绑定单字符字符串)。循环变量在每次迭代是**新绑定**,体结束后即不可见。`FOR` 表达式的值是 `NULL`。

### 6.4 提前退出

- `RETURN(expr?)`:从最内层函数返回,值为 `expr`(缺省 `NULL`)。
- `BREAK()`、`CONTINUE()`:终止/跳过最内层 `WHILE` 或 `FOR`。

三者出现在函数或循环体之外时产生 `E0014`。

## 7 模式匹配

### 7.1 语法

```
Match  = "MATCH" "(" Expression "," ClauseArray [ "," Expression ] ")" .
ClauseArray = "[" [ Clause { "," Clause } ] "]" .
Clause = "[" Pattern "," Expression "]" .
```

`MATCH` 按字面顺序试各子句的模式;首个命中的子句的右值被求值并作为 `MATCH` 的值。无命中且省略默认表达式时,值为 `NULL`。

### 7.2 模式

```
Pattern = identifier | wildcard | Literal | ArrayPattern | DictPattern | VariantPattern .
wildcard       = "_" .
ArrayPattern   = "[" [ Pattern { "," Pattern } [ "," "*" identifier ] ] "]" .
DictPattern    = "[" Key ":" Pattern { "," Key ":" Pattern } ]" .
VariantPattern = "OK" "(" Pattern ")" | "ERR" "(" Pattern ")" .
```

- 标识符模式绑定该名;通配符 `_` 匹配任意值不绑定。
- 字面量模式按 2.4 相等匹配。
- `OK(p)`/`ERR(p)` 匹配 `RESULT` 的对应变体并继续匹配载荷;对非 `RESULT` 值失配。
- 数组、字典模式按结构匹配;数组可捕余(`*rest`),字典可部分匹配(值必须包含全部模式键)。

### 7.3 语义

- 模式匹配必须是**穷尽形状**的:子句或默认表达式终将被选中。
- 模式绑定的作用域**仅为**对应分支;分支体是一个新作用域,绑定在其中遮蔽外层同名绑定,分支结束后不可见。
- 模式与值形状失配不算错误,只是不命中;`LET` 解构(3.1)失配则是错误 `E0026`。

## 8 错误模型

### 8.1 RESULT

`OK(v)` 把任意值 `v` 包装为 `RESULT` 的成功变体;`ERR(e)` 把载荷 `e` 包装为失败变体。`e` **必须**是字符串或字典,否则产生 `E0030`。

推荐以字典载荷携带结构化字段(`kind`、`input` 等),便于程序化消费。

并发与通道产生的结构化 `ERR` 使用字典载荷,`kind` 字段取下列值之一(载荷仍必须是 STRING 或 DICT,不变):

| `kind` | 产生处 |
|--------|--------|
| `"ChannelClosed"` | `CHANNEL_RECV` / `CHANNEL_TRY_RECV` 在通道已关闭且缓冲已读空时(含被 `CHANNEL_CLOSE` 唤醒的挂起接收方) |
| `"Cancelled"` | `AWAIT` 一个已取消的任务;载荷含 `reason` 字段(§17.3) |

**[v0.9]** `ERR(kind="ChannelWouldBlock")` **没有**触发路径:阻塞型 `CHANNEL_SEND` / `CHANNEL_RECV` 在满 / 空时挂起(§17.2),非阻塞形态 `CHANNEL_TRY_SEND` / `CHANNEL_TRY_RECV` 以布尔或 `NULL` 报告,不经 `ERR` 载荷。

关闭信号**必须**用 `IS_ERR` + `ERR_PAYLOAD` 的 `kind` 识别;`NULL` **不得**作为关闭信号。

取消载荷的 `reason` 字段是发起取消时传入的 `DICT`(缺省空字典);旧代码仅按 `kind` 匹配仍然有效。

### 8.2 透明传播

**任何不在消费者注册表(8.3)内的函数调用**——内建或用户定义——若任一实参求值为 `ERR`,则该调用不求函数体,直接以该 `ERR` 为调用结果。传播不消耗、不改写 `ERR`。于是未显式处理的错误沿调用链上浮,直到被消费者处理或逃逸到顶层(8.5)。

`&&`/`||` 短路求值时,未求值的那一侧不产生任何效果(包含副作用与 `ERR` 传播):仅被选中求值的那一侧的 `ERR` 才会沿当前调用链上浮。

**推论(错误处理惯用法)**:检查并消费一个 `ERR` 值必须**在拥有它的作用域内**进行——先以注册表消费者(`IS_ERR`、`ERR_PAYLOAD`、`UNWRAP_OR` 等)提取信息或兜底,再把**提取结果**(字符串、字典等普通值)传给其他函数:

```wlwl
LET(r, risky());                          // r 是 ERR
LET(p, ERR_PAYLOAD(r));                   // 在此处消费,p 是普通值
PRINT(FORMAT("failed: {0}", p));          // 传普通值,安全
```

把 `ERR` 值原样作为实参传给普通函数(包括"渲染函数""检查函数")只会触发传播,函数体永不执行:

```wlwl
// 示例一:ERR 作为实参触发透明传播,函数体不执行
LET(show, FUN((r), IF(IS_ERR(r), "E", "O")));
LET(r, ERR("x"));
LET(y, show(r));          // y = ERR("x") — show 的体永不执行
PRINT(TYPE(y));           // "RESULT"

// 示例二:ERR 逃逸到顶层
LET(r, ERR("x"));
show(r);                  // 表达式值被丢弃 → ERR 无消费者 → E0102,程序终止

// 示例三:OK 包装阻断传播
show(OK(r));              // "O" — OK 包装后不再是 ERR 实参
```

**注意**:`OK(r)` 包装可以阻断传播(此后按 2.4,`OK` 与 `ERR` 永不相等,且 `IS_OK(OK(...))` 为真)。将 `ERR` 装入数组或字典能通过**当前**求值,但取出元素再作实参时会再次触发传播——装盛不是消费。唯一合法的消费路径是 8.3 的注册构造。

### 8.3 消费者注册表

以下构造消费 `ERR` 而不触发 8.2 的传播(它们的**实参位置**是注册的 `ERR` 合法入口;返回值是普通值,可自由传递):

| 构造 | 对 `ERR` 的行为 |
|------|-----------------|
| `IS_OK(x)` / `IS_ERR(x)` | 返回布尔,不消耗载荷 |
| `UNWRAP_OR(x, d)` / `OR_DIE(x, d)` | `ERR` 时返回 `d`;`OK(v)` 时返回 `v`(`OR_DIE` 是弃用别名) |
| `TRY(x)` | `ERR` 时等价于 `RETURN(err)`,`OK(v)` 时取 `v`;只能在函数体内使用 |
| `UNWRAP(x)` | `OK(v)` 取 `v`;`ERR` 产生 `E0100` PANIC |
| `ERR_PAYLOAD(x)` | `ERR(e)` 取 `e`;对 `OK` 或非 `RESULT` 产生 `E0030` |
| `WRAP(x, ctx)` | `ERR(e)` 包装为 `ERR(["original": e, "context": ctx])`;`OK(v)` 原样返回 |
| `TYPE(x)` | 返回 `"RESULT"` |
| `==` / `!=` | 按 2.4,对 `ERR` 操作数透传而非消费 |
| `IF` | 条件位置消费:条件为 `ERR` 时等价于条件为假;若存在 else 则求 else,否则 `IF` 整体透传该 `ERR` |
| `&&` / `\|\|` | 短路消费:左为 `ERR` 时透传 `ERR`(不求右);右为 `ERR` 时按 8.2 透传 |
| `BOOL(x)` | 返回真值化结果(`BOOL(ERR(...))` 与 `BOOL(OK(0))` 等),**不**透传 `ERR` |
| `EXPECT_ERR(x)` | 供测试使用;`x` 为 `ERR` 时返回 `OK(载荷)`,否则返回 `ERR(E0049)` |

**[v0.9]** 本表不新增条目。§13–§17 的内建(`CLASS` / `NEW` / `THIS` / `GET_PROP` / `SET_PROP` / `CALL_METHOD` 与全部并发原语)**均不是**消费者:实参为 `ERR` 时按 8.2 透明传播。

### 8.4 PANIC

`PANIC(msg)`,`msg` 必须是字符串或字典,立即以诊断 `E0100` 终止程序(11.4)。PANIC 不参与透明传播。`UNWRAP` 于 `ERR`、以及 `INTEGER` 下界取负(`E0034`)同样以 PANIC 终止。

### 8.5 顶层逃逸

`ERR` 到达程序顶层而未被消费时,实现以诊断 `E0102` 报告该载荷并以退出码 1 终止。

作为 `ExprStmt` 被求值并被丢弃的表达式(附录 A.2 `Program` 的子句),其值若为 `ERR`,同样按本节(8.2)的顶层逃逸处理;即使该函数实参为非 `ERR`,顶层丢弃本身构成"无消费者"。

## 9 模块与程序

### 9.1 文件即模块

每个源文件是一个模块。模块顶层可以有 `EXPORT(name_array)`;未导出的绑定对外不可见。

### 9.2 IMPORT 与 MODULE_REF

```
Import = 'IMPORT' "(" string_lit "," name_array ")" .
name_array = "[" [ NameItem { "," NameItem } ] "]" .
NameItem = string_lit | string_lit ":" string_lit .
```

- `IMPORT(path, ["a", "b"])` 将模块 `path` 的导出名 `a`、`b` 绑定到当前作用域。
- `["orig": "alias"]` 将导出名 `orig` 绑定为本地名 `alias`(重命名)。
- 路径以 `./`、`../` 开头时按文件系统相对解析(后缀 `.wll` 可省);形如 `wlwl:std.*` 的路径指向标准库命名空间(第 10 章)。
- 模块不存在产生 `E0040`;导出名不存在产生 `E0023`;循环导入产生 `E0041`。
- 同一作用域内重复导入同一名字产生 `E0021`。

`MODULE_REF(path) -> MODULE` 加载并返回**模块字典**(导出名 → 值),**不**把任何名字绑定到当前作用域。其返回字典与 `IMPORT` 展开后可绑定的值集合不可区分;它不是新的模块机制,而是 `IMPORT` 的非绑定形式,供运行时动态加载、测试与自省使用。加载失败(`E0040` / `E0041` 等)原样以诊断形式报告。

模块本身是字典值;模块字典的属性读写按 4.6 的字典规则。

### 9.3 标准库命名空间

`wlwl:std.` 前缀的路径由实现直接提供,不经文件系统:`wlwl:std.io`、`wlwl:std.fs`、`wlwl:std.json`、`wlwl:std.collection`、`wlwl:std.format`、`wlwl:std.test`、`wlwl:std.ai`、`wlwl:std.agent`。各命名空间的成员见第 10 章。

### 9.4 清单文件

模块目录**可以**包含 `wlwl.toml` 清单,声明包名、语言版本与特性开关。本规范定义以下特性:

| 特性 | 默认 | 含义 |
|------|------|------|
| `strict_types` | `false` | 开启 5.2 类型注解的调用边界检查(`E0033`) |
| `allow_builtin_shadow` | `false` | 允许遮蔽内建名(3.5),以 `W0030` 代替 `E0025` |
| `strict_deadlock_detect` | `true` | 死锁检测 L1 的严格模式开关(§11.2 `E0065` / §11.3 `W0065`)。为 `true`(或缺省)时触发即抛 `E0065`;为 `false` 时降级为 `W0065` 并以 `E0053` 报告 |
| `native_channel_close` | `false` | 为 `true` 时,关闭后 `RECV` / `TRY_RECV` 在缓冲读空后改抛硬诊断 `E0054`,而不是返回 `ERR(kind="ChannelClosed")` |
| `channel_large_buf_threshold` | `1024` | `CHANNEL_NEW(buf)` 的软阈值;`buf` 超过该值产生 `W0066`。取 `0` 关闭该警告 |

清单的其余字段(依赖、版本求解、锁文件)属于包管理器职责,不在本规范内。

### 9.5 程序入口

被运行的文件即入口模块;其顶层表达式按顺序求值,最后一个表达式的值被丢弃。顶层求值产生的 `ERR` 按 8.5 处理。

## 10 标准库

### 10.1 约定

- **全局内建**:10.2–10.5、10.7(`FORMAT`)、10.9、10.12 的名字无须导入即可调用。
- **命名空间成员**:10.6、10.8、10.10、10.11 的名字**必须**经 `IMPORT` 导入。
- 除注明外,容器操作都是**非破坏性**的:返回新容器,接收者不变;更新绑定用 `SET`(3.4)。
- 对 `ERR` 实参:全局内建按 8.2 透明传播;集合套件(10.6)的回调抛出的 `ERR` 同样使整个调用传播。

### 10.2 I/O

| 签名 | 说明 |
|------|------|

### 10.7 格式化 — `FORMAT`(全局)

`FORMAT(template, args...) -> STRING`:模板中 `{N}` 以第 `N` 个实参的 `STR` 渲染替换;`{name}` 以首个实参为字典按键取值;两类占位符可混用。未匹配的 `{...}` 原样保留;模板畸形(孤立的 `{`)产生 `E0039`。`wlwl:std.format` 命名空间导出同一函数。

**`{N}` 与 `{name}` 混用规则**:`{N}` 的 `N` 自 `0` 起,指 `FORMAT(template, args...)` 中 `args` 的第 `N` 项(template 是第 `-1` 项,不计入索引)。当模板同时含 `{name}` 与 `{N}`:

- 若首个 `args` 项(`{0}`)是 `DICT`,`{name}` 优先在该 `DICT` 中查键;`{0}` 仍按 `STR` 渲染该 `DICT`(例:`["age": 30]` → `"[age: 30]"`)。
- 若首个 `args` 项是标量,`{name}` 在所有 `DICT` 实参中按位置查找首个 `DICT`;`{0}` 渲染该标量。
- 都找不到则占位符保留原样(`{name}` / `{N}` 不抛错)。

### 10.11 AI 与代理 — `wlwl:std.ai` / `wlwl:std.agent`

下列最小契约是规范性的;各函数依赖外部服务,传输与供应商细节属于实现文档,不在本规范内。

| 签名 | 说明 | 失败 |
|------|------|------|
| `wlwl:std.ai.TASK(name, prompt, ...) -> TASK` | 构造异步 AI 请求任务,返回任务句柄 | `E0080`–`E0083` |
| `wlwl:std.ai.MODEL(name) -> DICT` | 选择模型,返回模型描述字典 | `E0080` |
| `wlwl:std.ai.TOOL(name, schema, fn) -> NULL` | 注册工具 | `E0081`(重复注册或协议不符) |
| `wlwl:std.ai.CALL_TOOL(name, args) -> v` | 同步调用已注册工具 | `E0082` |
| `wlwl:std.ai.CONTEXT(set, get, ...) -> v` | 上下文存取 | `E0083` |
| `wlwl:std.agent.TASK(...) -> TASK` | 高级代理任务 | `E0090`–`E0094` |

错误码语义:`E0080` 请求失败;`E0081` 协议错误;`E0082` 工具错误;`E0083` 上下文错误;`E0090` 网络不可达、`E0091` DNS 失败、`E0092` TLS 错误、`E0093` HTTP 4xx、`E0094` HTTP 5xx。

**示例**(推荐全限定以避免与类型名 `TASK` 混淆):

```wlwl

LET(handle, wlwl:std.ai.TASK("summarize", "long text..."));
```

用户作用域内裸名 `TASK` 也合法(若 `IMPORT` 引入了同名函子);全限定写法仅为阅读清晰度,与同名类型名 `TASK` 不构成运行时冲突(§2.1)。

## 11 诊断

### 11.1 结构

诊断是错误(`E`)或警告(`W`),带四位数字码。错误形式的 CLI 输出包含码、消息、位置(文件、行列)与源行摘录;`--format json`/`jsonl` 产生机器可读结构(含 `error_schema_version`、`errorCategory`、`retryable`、`idempotent`、`suggestion_code`、`trace` 等字段)。死锁检测产生的 `E0065` 的 `errorCategory` 字段值为 `"deadlock"`。

### 11.2 错误码

| 码 | 含义 |
|------|------|
| `E0001` / `E0002` / `E0003` | 非法字符 / 未终止字符串 / 未终止块注释 |
| `E0010`–`E0013` | 语法错误(期望表达式、`)`、`,`、`;`) |
| `E0014` | 控制流构造出现在非法位置:**[v0.9 修订]** `RETURN` / `BREAK` / `CONTINUE` 出现在函数或循环体之外;或 `YIELD` 出现在任何调度驱动的上下文(任务体)之外(§17.1)。v0.7 / v0.8 的"`YIELD` 必须是块直接子项"限制已废止,不再触发 |
| `E0020` | 未定义名字;调用非函数 |
| `E0021` | 同作用域重复导入 |
| `E0022` | 函数元数不符 |
| `E0023` | 名字未被模块导出 |
| `E0024` | 对不可变绑定 `SET`(`LET` 而非 `LET MUT`);单任务与跨任务路径统一 |
| `E0025` | 遮蔽内建名(未开启 `allow_builtin_shadow`) |
| `E0026` | 解构模式失配 |
| `E0030` | 类型错误(含 `ERR_PAYLOAD`/`WRAP`/`CALL` 的误用;`INDEX_SET` 接收字符串;§13 各构造的接收者类型错) |
| `E0031` | 下标/键类型错误;NaN 作键;`CHANNEL_NEW` 的 `buf` 非非负整数 |
| `E0032` | **[v0.9 修订]** 线性 `THIS` 纪律违反(§15),或对只读字段的写入:① `THIS` 在方法体之外求值;② 同一次方法调用内重复消费 `THIS`;③ `THIS` 越出方法体(存入数组/字典字面量、被闭包捕获、作为方法返回值、进入 `SPAWN`、跨 `AWAIT`、作为 `SET_PROP` 的值);④ 在非本方法 self 的上下文中对 `INSTANCE` 调用 `SET_PROP`;⑤ `SET_PROP` 写入类字段(类字段只读,仅实例字段可写) |
| `E0033` | `strict_types` 违例 |
| `E0034` | 对 `INTEGER` 下界取负 |
| `E0035` | 数值越界(整数运算溢出;浮点转整数越界) |
| `E0036` | 数组或字符串索引越界 |
| `E0037` | 字典键不存在;`GET_PROP` / `CALL_METHOD` 的属性或方法不存在 |
| `E0038` | `RANGE` 步长为零 |
| `E0039` | `FORMAT` 模板畸形 |
| `E0040` / `E0041` | 模块不存在 / 循环导入 |
| `E0045` | 依赖约束不可满足(包管理) |
| `E0046`–`E0049` | 测试断言失败(`ASSERT`/`ASSERT_EQ`/`ASSERT_NEQ`/`EXPECT_ERR`) |
| `E0050` | **[v0.9 启用]** 对象模型状态错误(§13 / §14):会话协议表达式畸形;类父链成环或深度超过 64;`init` 成员不是函数;`NEW` 的实参数与 `init` 形参数不符;协议已走完(`end`)后仍调用方法 |
| `E0051` | **[v0.9 启用]** 会话协议步骤违规(§14.3):当前协议状态不提供被调方法(顺序错位、内部选择 `⊕` 未选中该分支、μ 递归展开后的不匹配或展开预算耗尽) |
| `E0052` | `SCOPE`/`SPAWN`/`SHIELD` 的 `fn` 不是函数值 |
| `E0053` | 任务/通道句柄无效(含 `TASK_CURRENT` 在任务外、过期 generation);阻塞型 `CHANNEL_SEND` / `CHANNEL_RECV` 在无活跃任务的上下文中调用;`AWAIT` 的目标任务挂起在通道操作上且无对端可唤醒(软化后的死锁报告,见 §11.3 `W0065`) |

| `E0070` / `E0071` | JSON 解析 / 序列化失败 |

| `E1003` | 除零/模零 |
| 其余注册码 | `E0042`–`E0044`(清单与依赖)、`E0060`/`E0062`/`E0063`、`E0080`–`E0083`/`E0090`–`E0094`(AI/网络子系统,§10.11)、`E0099`(用户错误)、`E0101`(栈溢出)随对应子系统定义 |

**[v0.9 移除]** `E0055` 与 `E0057` **不得**出现在诊断流中,亦不保留注册位:

- 通道关闭后的读取结果由 `ERR(kind="ChannelClosed")` 载荷承担(§8.1 / §17.2);需要硬诊断时由 `native_channel_close` 特性改用 `E0054`。
- 跨任务的不可变单元格写入触发 `E0024`,与单任务路径统一(3.4)。

**[v0.9 修订]** `E0014` 在并发下的追加用途("`YIELD` 必须出现在多语句块的直接子项")已废止。`YIELD` 可以出现在任务体内的任何表达式位置(§17.1);仅当 `YIELD` 出现在调度驱动的上下文之外时才触发 `E0014`。

**`E0032` / `E0050` / `E0051` 的校验顺序**:`CALL_METHOD` 入口按下列顺序校验,命中即报,不级联:

1. 接收者类型:`obj` 不是 `DICT` 或 `INSTANCE` → `E0030`;
2. 线性 `THIS` 越界(§15)→ `E0032`;
3. 协议状态(已终止等状态错位)→ `E0050`;
4. 协议步骤匹配(方法是否在当前状态被提供)→ `E0051`。

`SET_PROP` 按下列顺序校验:值为线性 `THIS` → `E0032`;非本方法 self 上下文 → `E0032`;类字段写入 → `E0032`;其余为实例字段的新建或更新。

## 13 OOP 关键字与对象模型

`CLASS` / `NEW` / `THIS` / `GET_PROP` / `SET_PROP` / `CALL_METHOD` 自 v0.9 起是完整定义的构造。本章定义对象模型;会话类型协议见 §14;`THIS` 的线性纪律见 §15;与并发的交互见 §16。

### 13.1 构造一览

| 构造 | 签名 | 类别 | 引入 | 语义摘要 |
|------|------|------|------|----------|
| `CLASS(name, parent, members)` | `-> CLASS` | 关键字调用 | v0.9 | 构造类对象(§13.2) |
| `NEW(cls, args...)` | `-> INSTANCE` | 关键字调用 | v0.9 | 实例化并运行 `init`(§13.3) |
| `THIS()` | `-> INSTANCE` | 关键字调用 | v0.9 | 当前方法的接收者(§15) |
| `GET_PROP(obj, key)` | `-> v` | 全局内建 | v0.9 | 读属性(§13.4) |
| `SET_PROP(obj, key, value)` | `-> NULL` | 全局内建 | v0.9 | 写实例字段(§13.4) |
| `CALL_METHOD(obj, method, args...)` | `-> v` | 全局内建 | v0.9 | 调方法并走协议状态机(§13.5 / §14) |

上述构造**均不是** §8.3 的 `ERR` 消费者;实参为 `ERR` 时按 §8.2 透明传播。

v0.9 **不提供**:类继承以外的动态特性(多重继承、混入)、抽象类、静态方法、构造重载、字段级生命周期注解、运行时派生协议。外部选择 `&`、命名协议、并行协议分支见 §14.5。

### 13.2 CLASS

```
CLASS(name, parent, members) -> CLASS
```

`CLASS` 恰取 3 个实参(元数不符 → `E0022`)。

**name**:`STRING` 或 `NULL`。`NULL` 表示匿名类;其他类型 → `E0030`。名字仅供诊断显示(2.5),不影响相等(2.4)或查找。

**parent**:下列三者之一:

| 形态 | 含义 |
|------|------|
| `NULL` | 无父类、无协议 |
| `CLASS` 值 | **单继承**父类;成员查找沿父链向上(§13.5) |
| 会话协议表达式(`DICT` / `ARRAY` / `STRING`,§14.1) | 声明会话类型协议;此时无继承父类 |
| 其他 | `E0030` |

父类链**不得**含环,深度**不得**超过 64;违者产生 `E0050`。协议表达式畸形产生 `E0050`。

**members**:`ARRAY`,每个元素是恰含两个元素的 `[STRING, value]` 数组;键必须是 `STRING`。其他形态 → `E0030`。成员按键名分类:

| 键 | 值形态 | 角色 |
|----|--------|------|
| `"init"` | 函数 | 构造器(§13.3);一个类至多一个 `init`,后者覆盖前者 |
| 其他键,且值是**第一个形参名为 `self`** 的闭包 | 函数 | 实例方法 |
| 其他键,其余值 | 任意 | **类字段** |

类字段对实例是**只读**的(§13.4)。方法经 `CALL_METHOD` 或 `a.m(...)` 调用时按 4.6 注入接收者。

```wlwl
LET(Base, CLASS("Base", NULL, [["hello", FUN((self), "hi")]]));
LET(D, CLASS("D", Base, []));
LET(o, NEW(D));
o.hello();   // "hi" — 沿父链找到方法,接收者注入 self
```

```wlwl
LET(C, CLASS("C", NULL, [
    ["count", 0],                          // 类字段,只读
    ["init", FUN((self), SET_PROP(self, "n", 1))],   // 构造器
    ["get", FUN((self), GET_PROP(self, "n"))]        // 方法
]));
LET(o, NEW(C));
CALL_METHOD(o, "get");   // 1
```

### 13.3 NEW

```
NEW(cls, args...) -> INSTANCE
```

1. `cls` 必须是 `CLASS` 值,否则 `E0030`。
2. 分配新实例:实例字段表初始为空;协议状态机按 `cls` 的协议初始化(§14.3);线性 `THIS` 记号置为未消费(§15.2)。
3. 若 `cls` 有 `init` 成员:
   - `init` 不是函数值 → `E0050`;
   - 元数:实参个数(`cls` 占一位,加上 `args...`)必须等于 `init` 的形参个数(含 `self`),不符 → `E0050`;
   - 若类声明了协议,先按协议状态机消费 `init` 步(§14.4);不匹配 → `E0050`;
   - 以实例为 `self` 调用 `init`,并把 `args...` 传给其余形参(4.6 注入规则)。
4. 若 `cls` 没有 `init`,直接返回空字段的新实例。
5. 表达式的结果是该实例。

```wlwl
LET(C, CLASS("C", NULL, [["init", FUN((self), SET_PROP(self, "x", 1))]]));
LET(o, NEW(C));
GET_PROP(o, "x");   // 1
```

**[v0.9]** 不提供构造重载:`init` 的形参数必须与 `NEW` 的实参数精确匹配。

### 13.4 GET_PROP / SET_PROP

```
GET_PROP(obj, key) -> v
SET_PROP(obj, key, value) -> NULL
```

`key` 必须是 `STRING`,否则 `E0030`。

**GET_PROP**

| `obj` | 行为 |
|-------|------|
| `DICT` | 按 4.5 字典取值;键不存在 → `E0037` |
| `INSTANCE` | 先查实例字段表;未命中则沿类父链查类字段;再未命中 → `E0037`。父链成环 / 超深 → `E0050`。类字段与实例字段均可读 |
| 其他 | `E0030` |

**SET_PROP**

| `obj` | 行为 |
|-------|------|
| `DICT` | 与 `INDEX_SET` 同族的值语义:返回**插入或更新后的新字典**,接收者不变 |
| `INSTANCE` | 见下 |
| 其他 | `E0030` |

对 `INSTANCE` 的 `SET_PROP` 按下列顺序校验,命中即报:

1. `value` 是当前线性 `THIS` → `E0032`(§15.3);键为线性 `THIS` 同样 → `E0032`;
2. 当前不在"该实例的 self 方法体"内(§15.1)→ `E0032`;
3. `key` 是类字段(含沿父链命中)→ `E0032`(类字段只读);
4. `key` 已是实例字段 → 原位更新,返回 `NULL`;
5. 否则 → 新建实例字段 `(key, value)`,返回 `NULL`。

```wlwl
LET(C, CLASS("C", NULL, [
    ["k", 42],
    ["m", FUN((self), SET_PROP(self, "k", 1))]
]));
CALL_METHOD(NEW(C), "m");   // E0032 — 类字段 k 只读
```

```wlwl
LET(C, CLASS("C", NULL, [
    ["m", FUN((self), SET_PROP(self, "n", 7); GET_PROP(self, "n"))]
]));
CALL_METHOD(NEW(C), "m");   // 7 — n 是新建的实例字段
```

**字段可变性**由声明位置决定:类字段(§13.2 `members` 中非 `init`、非 self 闭包者)只读;实例字段可写。该标志在类构造时即确定,**不**因持有引用而改变(§3.3 同源原则)。

### 13.5 CALL_METHOD

```
CALL_METHOD(obj, method, args...) -> v
```

`method` 必须是 `STRING`,否则 `E0030`;元数至少 2(`obj`, `method`)。

1. **接收者**:`DICT` 或 `INSTANCE`;其他 → `E0030`。
2. **线性检查**:`THIS` 越界形态先于协议校验(§11.2 校验顺序)。
3. **方法查找**:
   - `DICT`:按键查字典成员;缺失 → `E0037`;
   - `INSTANCE`:先查该类 `members`,再沿父链向上;全未命中 → `E0037`;父链成环 / 超深 → `E0050`。实例字段不参与方法查找。
4. **协议校验**(仅当类声明了协议):按 §14.3 推进状态机;违规 → `E0050` / `E0051`。
5. **调用**:按 4.6 注入规则调用成员。成员是闭包且首形参名为 `self` 时注入接收者;成员是内建时不注入。成员存在但不可调用 → `E0030`。

属性 / 方法语法糖 `obj.method(args)` 与 `CALL_METHOD(obj, "method", args...)` 等价。

### 13.6 类型、相等与显示

`TYPE(cls)` 为 `"CLASS"`;`TYPE(obj)` 为 `"INSTANCE"`。相等按 2.4 的对象身份;显示按 2.5。

### 13.7 与第 8 章的关系

- `CLASS` / `NEW` / `THIS` / `GET_PROP` / `SET_PROP` / `CALL_METHOD` 均**不是** §8.3 消费者(§8.2 适用)。
- §13 的失败**不**产生 `ERR` 载荷,而是原生诊断码:`E0030` / `E0032` / `E0037` / `E0050` / `E0051`。程序如需把它们转为 `RESULT`,应当在调用前自行校验,或捕获为宿主诊断(§17.1 `AWAIT` 的宿主诊断重抛规则)。
- 方法体内部产生的用户 `ERR` 仍按 §8.2 传播,不受本章影响。

## 14 行为类型与会话类型协议

每个 `CLASS` **可以**声明一个**会话类型协议**,约束其实例上方法调用的合法次序。协议在 `CLASS` 的第二实参位以**普通 WLWL 值**书写,经运行时解析为协议状态机;`CALL_METHOD` / `NEW` 在调用时按状态机校验。

### 14.1 协议表达式

协议表达式是 `STRING` / `ARRAY` / `DICT` 形态的值。合法形态如下(`T` 为载荷类型名,`X` 为 μ 变量):

| 形态 | 含义 |
|------|------|
| `"end"` | 终止 |
| `["end"]` | 同上 |
| `["then", "m", next]` 或 `["seq", "m", next]` | 先调 `m`,再继续 `next` |
| `["recv", T, next]` | 载荷类型注解 `T`(如 `"int"`),然后继续 `next`;作为 `then` 的续段使用 |
| `["seq", "a", "b", "c"]` | 平坦序列 `a → b → c → end` |
| `["choice", {m1: c1, m2: c2}]` 或 `["choice", [[m1, c1], [m2, c2]]]` | **内部选择 `⊕`**:调用方在 `m1` / `m2` 中恰选一个 |
| `["mu", "X", body]` | 递归绑定 `μX. body` |
| `["var", "X"]` | 递归变量 `X`(必须由外层 `mu` 绑定) |
| `{m1: v1, m2: v2, ...}` | **顺序序列** `m1 → m2 → …`;值是载荷类型名(`"end"` 表示无载荷)或嵌套续段 |

顺序字典形态 `{a: "end", b: "end", c: "end"}` 等价于 `a` 然后 `b` 然后 `c` 然后 `end`。若字典中某个值是非字符串的复合形态,则该值是该方法之后的**续段**,其后的键被忽略(显式链接请用 `then`)。

```wlwl
// 顺序协议:a → b → c
LET(C, CLASS("C", ["a": "end", "b": "end", "c": "end"], [
    ["a", FUN((self), 1)],
    ["b", FUN((self), 2)],
    ["c", FUN((self), 3)]
]));
LET(o, NEW(C));
CALL_METHOD(o, "a");
CALL_METHOD(o, "b");
CALL_METHOD(o, "c");   // 3
```

```wlwl
// 内部选择 ⊕:open 或 close 二选一
LET(C, CLASS("C", ["choice", ["open": "end", "close": "end"]], [
    ["open", FUN((self), "opened")],
    ["close", FUN((self), "closed")]
]));
CALL_METHOD(NEW(C), "close");   // "closed"
```

```wlwl
// μ 递归:get 可重复,close 终止
LET(C, CLASS("C",
    ["mu", "X", ["choice", [
        ["get", ["recv", "int", ["var", "X"]]],
        ["close", "end"]
    ]]],
    [
        ["get", FUN((self), 7)],
        ["close", FUN((self), "done")]
    ]
));
LET(o, NEW(C));
CALL_METHOD(o, "get");
CALL_METHOD(o, "get");
CALL_METHOD(o, "close");   // "done"
```

**[v0.9 范围]** 顺序、内部选择 `⊕`、μ 递归骨架受支持。下列形态**不在**本版:

| 形态 | 状态 |
|------|------|
| 外部选择 `&` | 不支持 |
| 命名协议 / `typealias` | 不支持 |
| 并行分支 `par` | 不支持 |

不支持的形态若出现在协议表达式中,按协议畸形处理(`E0050`)。

### 14.2 协议状态机

每个实例持有一个协议状态:

| 状态 | 含义 |
|------|------|
| **Unrestricted** | 类未声明协议;任意方法、任意次序均可调用 |
| **Live(remaining)** | 协议进行中;`remaining` 是剩余协议 |
| **Done** | 协议已到达 `end` |

μ 递归的展开有预算(默认 64 次);超出预算的展开按协议违规处理(`E0051`)。

### 14.3 CALL_METHOD 校验

对声明了协议的类,`CALL_METHOD(obj, method, args...)` 在找到方法之后、调用之前推进状态机:

1. 状态为 **Done** → `E0050`(协议已终止;任何方法都不可再调)。
2. 状态为 **Unrestricted** → 不校验,直接调用。
3. 状态为 **Live**:
   - `method` 不在当前 `remaining` 提供的方法集合中 → `E0051`(顺序错位、未选中的 `⊕` 分支、μ 展开后的不匹配);
   - 命中顺序步 → `remaining` 前进到续段;
   - 命中 `⊕` 的某个分支 → `remaining` 前进到该分支的续段;
   - 续段是 μ 变量 → 展开到 μ 体(消耗 1 点预算);
   - 续段是 `end` → 状态转为 **Done**。

**校验优先级**:状态错位(`Done`)优先于步骤不匹配。协议表达式畸形在 `CLASS` 求值期即报 `E0050`,不进入运行时状态机。

```wlwl
LET(C, CLASS("C", ["only": "end"], [["only", FUN((self), 1)]]));
LET(o, NEW(C));
CALL_METHOD(o, "only");
CALL_METHOD(o, "only");   // E0050 — 协议已终止
```

```wlwl
LET(C, CLASS("C", ["a": "end", "b": "end"], [
    ["a", FUN((self), 1)],
    ["b", FUN((self), 2)]
]));
CALL_METHOD(NEW(C), "b");   // E0051 — 当前应先调 a
```

### 14.4 NEW 与 init 步

若类声明了协议且 `members` 含 `init`,`NEW` 在调用 `init` 之前按状态机消费名为 `init` 的一步:协议当前不提供 `init` → `E0050`(构造期协议错配)。无 `init` 成员时,`NEW` 不消费协议步,实例停留在协议的起始状态。

### 14.5 与并发的关系

协议状态机是**每实例**的,不跨任务共享(§16.1)。`AWAIT` / `YIELD` / 通道操作不推进协议状态机;任务挂起期间协议位置保持不变。

## 15 `THIS` 与线性 capability

`THIS` 是当前方法接收者的**线性 capability**:每次方法调用内至多消费一次,**不得**逃出该次调用的动态范围。

### 15.1 THIS 求值

`THIS()`(或零参引用 `THIS`)求值为当前活跃的 `INSTANCE` 接收者。

- 元数必须为 0,否则 `E0022`。
- 当前没有活跃方法接收者(方法体之外)→ `E0032`。
- 当前接收者不是 `INSTANCE` → `E0032`。

**方法体**指:经 `CALL_METHOD` / `NEW`(init)调用、且接收者作为 `self` 注入(4.6)的闭包体。嵌套方法调用各自建立自己的接收者;内层返回后恢复外层接收者。

```wlwl
LET(C, CLASS("C", NULL, [["m", FUN((self), THIS())]]));
```

`THIS` 在 `m` 内是 `self`;在顶层求值 `THIS()` 是 `E0032`。

### 15.2 线性消费

在同一次方法调用内,`THIS()` 的求值**消费**该能力:

1. 第一次求值成功,返回接收者,并标记为已消费;
2. 同一次调用内的再次求值 → `E0032`;
3. 调用返回时,本次消费记号复位;下一次方法调用重新获得一次消费机会。

```wlwl
LET(C, CLASS("C", NULL, [
    ["m", FUN((self), LET(a, THIS()); LET(b, THIS()); 1)]
]));
CALL_METHOD(NEW(C), "m");   // E0032 — 第二次 THIS
```

### 15.3 逃逸边界

`THIS` 的值**不得**离开当前方法体。下列形态均产生 `E0032`:

| 边界 | 示例 |
|------|------|
| 数组字面量 | `LET(a, [THIS()])` |
| 字典字面量(键或值) | `LET(d, ["this": THIS()])` |
| 闭包捕获 | `LET(f, FUN(() , THIS()))` |
| 方法返回值 | `FUN((self), THIS())` 作为方法体;或 `FUN((self), LET(x, THIS()); x)` |
| `SPAWN` 的任务体或捕获环境 | `SPAWN(FUN(() , THIS()))` |
| `AWAIT` 实参 | `AWAIT(THIS())` |
| `SET_PROP` 的值或键 | `SET_PROP(o, "k", THIS())` |

逃逸检查在**构造该形态时**执行(闭包在捕获时、字面量在构造时、返回在离开方法帧时),而非延后到使用点。

### 15.4 SET_PROP 与 self 上下文

对 `INSTANCE` 的 `SET_PROP` 只在"该实例的 self 方法体"内合法(§13.4):外部引用、他实例的 self 方法内、或无活跃方法时写入 → `E0032`。`GET_PROP` 不受此限。

### 15.5 与 v0.8 的差异

| 路径 | v0.8 | v0.9 |
|------|------|------|
| `THIS` 在方法外求值 | 占位错误 | `E0032` |
| `THIS` 存入容器 / 被闭包捕获 / 作为返回值 | 未定义 | `E0032` |
| `THIS` 跨 `SPAWN` / `AWAIT` | 未定义 | `E0032` |
| `SET_PROP` 外部写实例 | 未定义 | `E0032` |

不使用上述形态的 v0.8 程序在 v0.9 上可观察行为不变。

## 16 OOP 与并发的交互

### 16.1 挂起与协议状态机

`CALL_METHOD` 执行期间,方法体可以触发挂起(`YIELD`、阻塞型通道操作、`AWAIT`,§17.4)。挂起时:

- 实例的协议状态机位置**保持不变**;恢复后从挂起点继续,协议不因挂起而推进或回退;
- 协议状态机是每实例私有(§14.5),其他任务**不能**经由该实例推进协议;
- `THIS` 的消费记号在挂起期间保持;恢复后仍按 §15.2 规则。

### 16.2 `THIS` 与 `SPAWN` / `AWAIT`

§15.3 的逃逸边界覆盖任务构造与等待:把 `THIS` 放进 `SPAWN` 的任务体或捕获环境、或作为 `AWAIT` 的实参,均产生 `E0032`。子任务中不存在 self 上下文;在子任务里求值 `THIS()` 同样是 `E0032`。

### 16.3 实例字段共享

实例字段的可见性不引入新规则:同一实例可被多个任务持有,`SET_PROP` 的写入对共享该实例的引用可见(§13.4)。跨任务协调**应当**经由通道(§17.2)显式编排;`SET_PROP` 不提供同步保证。

### 16.4 取消与方法体

任务取消(§17.3)在检查点生效。方法体内的取消观察与普通任务体一致:`TASK_IS_CANCELLED()`、`YIELD`、阻塞型通道操作。取消**不**直接改写协议状态机;实例的协议位置在任务终止后保持其最后推进到的状态。

## 17 并发(结构化并发与通道)

本章定义并发原语。第 8 章错误模型(含 8.2 透明传播、8.3 消费者注册表)对本章全部内建**原样适用**。本章原语全部是全局内建(附录 G「并发 / 通道」组),不经 `IMPORT`。

### 17.0 执行模型(非规范)

本章的并发是**结构化并发 + 通道**、**协作式单线程调度**、**真挂起**。任务在让步点与阻塞点把控制交还调度器;调度器担当效果处理器(effect handler),按 §17.4 的代数效果模型捕获让步、通道等待与取消,并切换到下一个可运行任务。取消携带结构化 `reason` 载荷;取消本身不产生用户 `ERR` 值,只在 `AWAIT` 观察点显现。

### 17.1 任务与作用域

| 构造 | 签名 | 语义 |
|------|------|------|
| `SCOPE(fn)` | `SCOPE(fn) -> v` | 创建**子作用域**并调用 0 元函数 `fn`;返回 `fn` 的值。`fn` 不是函数 → `E0052`。支持嵌套 |
| `SPAWN(fn)` | `SPAWN(fn) -> TASK` | 在当前作用域派生子任务,返回任务句柄。`fn` 必须是 0 元函数(`E0056`);`fn` 不是函数 → `E0052` |
| `AWAIT(task)` | `AWAIT(task) -> v` | 等待并取得子任务终值。非句柄 / 过期句柄 → `E0053` |
| `YIELD()` | `YIELD() -> NULL` | 协作让步检查点 |
| `TASK_CURRENT()` | `TASK_CURRENT() -> TASK` | 当前任务句柄;任务外 → `E0053` |
| `TASK_IS_CANCELLED()` | `TASK_IS_CANCELLED() -> BOOLEAN` | 协作取消检查;任务外返回 `FALSE`(不报错) |

**作用域与生命周期**

- 子任务寿命不超过词法 `SCOPE`;`SCOPE` 返回前等待其子任务结束(结构化并发不变量)。
- **无隐式 runtime scope**:任何 `SPAWN` **必须**直接或间接嵌套在某个 `SCOPE(...)` 内;顶层 `SPAWN` → `E0058`。不提供 free-floating task / 守护线程。
- `SCOPE` 的返回值是 `fn` 主体的值。若 `fn` 主体给出未消费的 `ERR`,该 `ERR` 成为 `SCOPE` 的返回值(与 8.2 一致);已被消费者处理掉的 `ERR` **不**再上浮。
- `SCOPE(fn)` 的 `fn` 在**调用者**的执行上下文中同步求值;只有 `SPAWN` 创建的任务体才是调度驱动的(见下)。

**AWAIT**

- 任务以用户 `ERR` 结束时,`AWAIT` **返回该 `ERR` 值**(不自动消费)。
- **宿主诊断**(实现内部错误,如 `E0101` 栈溢出、句柄失效 `E0053` 等)在 `AWAIT` 处重新抛出,并以诊断 trace 链关联目标任务的失败帧;**用户 `ERR` 值**(`RESULT` 变体)作为普通结果返回,不重新抛出。
- 已取消任务的 `AWAIT` 返回 `ERR(kind="Cancelled", reason: <dict>)`(§17.3)。
- `AWAIT` 的目标任务若永久阻塞在通道操作上且无对端可唤醒,产生 `E0053`(或在死锁检测触发时先见 `E0065` / `W0065`,§17.7)。

**YIELD 的位置与上下文**

`YIELD()` 可以出现在**任务体内的任何表达式位置**——实参、`LET` 右值、`IF` 分支、数组与字典字面量、嵌套的 `WHILE` / `FOR` / `IF` 体内,以及间接调用。v0.7 / v0.8 要求"`YIELD` 必须是块直接子项"的限制**已废止**。

| 形态 | 行为 |
|------|------|
| `LET(x, YIELD())` | 挂起后继续;`x` 取 `YIELD` 的值 `NULL` |
| `IF(cond, YIELD(), 42)` | 视 `cond` 走分支;在选中分支的 `YIELD` 处挂起后继续 |
| `[1, YIELD(), 3]` | 挂起后继续;字面量为 `[1, NULL, 3]` |
| `WHILE` / `FOR` / `IF` 体内的 `YIELD` | 挂起后**恢复嵌套体的剩余部分**,而不是跳到外层序列的下一段 |
| `LET(y, YIELD); y()` | 间接调用与直接 `YIELD()` 等价:每次都挂起 |

```wlwl
SPAWN(FUN(() ,
    PRINT("a");
    YIELD();          // 任意表达式位置均可
    PRINT("b");
    42
))
```

`YIELD` **必须**位于调度驱动的上下文(任务体)内。在任务体之外(例如模块顶层、`SCOPE` 的同步主体)调用 `YIELD` 产生 `E0014`。任务体末尾的 `YIELD()` 使任务以 `NULL` 值结束,不与"未消费 `ERR`"语义冲突。

### 17.2 通道

| 构造 | 签名 | 语义 |
|------|------|------|
| `CHANNEL_NEW(buf)` | `-> CHANNEL` | 创建缓冲大小为 `buf` 的通道;`buf = 0` 为同步通道。`buf` 须为非负 `INTEGER`;负数或非整数 → `E0031`。超过软阈值 → `W0066`(§9.4) |
| `CHANNEL_SEND(ch, v)` | `-> NULL` | 发送。缓冲满且无等待中的接收方时**挂起**(§17.2.1)。关闭后发送 → `E0054` |
| `CHANNEL_RECV(ch)` | `-> v` | 接收。缓冲空且无等待中的发送方时**挂起**。关闭且读空 → `ERR(kind="ChannelClosed")` |
| `CHANNEL_TRY_SEND(ch, v)` | `-> BOOLEAN` | **不挂起**:成功 `TRUE`,满 `FALSE`;关闭后 → `E0054` |
| `CHANNEL_TRY_RECV(ch)` | `-> v / NULL` | **不挂起**:成功返回值;空返回 `NULL`(**不是**关闭信号);关闭且读空 → `ERR(kind="ChannelClosed")` |
| `CHANNEL_CLOSE(ch)` | `-> NULL` | 关闭。幂等 |
| `CHANNEL_LEN(ch)` | `-> INTEGER` | 当前缓冲长度 |
| `CHANNEL_CAP(ch)` | `-> INTEGER` | 配置容量;同步通道为 `0` |

`TYPE(ch)` 为 `"CHANNEL"`。句柄恒等见 2.4。

#### 17.2.1 真挂起

阻塞型 `CHANNEL_SEND` / `CHANNEL_RECV` 在满足下列条件之一时**挂起**调用任务,把控制交还调度器:

- `SEND`:缓冲满,且没有等待中的接收方;
- `RECV`:缓冲空,且没有等待中的发送方。

挂起的任务离开运行队列,登记在通道的等待表上;对端到达或通道关闭时被唤醒。**不**返回 `ERR(kind="ChannelWouldBlock")`——该载荷在 v0.9 **没有**触发路径。

**对端配对(规范性)**:当一侧到达时,若对端已在等待,双方**必须**配对交接:

- 发送方到达且有等待中的接收方 → 值直接交给该接收方,双方就绪;
- 接收方到达且有等待中的发送方 → 取走该发送方的值,双方就绪;
- 缓冲有余位 / 有存货时,按缓冲路径立即完成,并顺带唤醒一个可推进的对端。

配对成功的双方都被标记为就绪,进入调度队列尾部(§17.8)。

**非阻塞形态** `CHANNEL_TRY_SEND` / `CHANNEL_TRY_RECV` 从不挂起,亦从不经 `ERR` 载荷报告"满 / 空":`TRY_SEND` 以 `TRUE` / `FALSE` 报告,`TRY_RECV` 以值 / `NULL` 报告。

**阻塞型操作要求活跃任务**:在任务体之外调用阻塞型 `CHANNEL_SEND` / `CHANNEL_RECV` 产生 `E0053`。`TRY_*` 无此限制。

#### 17.2.2 操作语义矩阵

| 操作 | closed | 缓冲状态 | 行为 |
|------|--------|----------|------|
| SEND | false | 有空位或有等待中的接收方 | 交接 / 入队,返回 `NULL` |
| SEND | false | 满且无接收方 | **挂起** |
| SEND | true | — | `E0054` |
| RECV | false | 非空或有等待中的发送方 | 交接 / 出队,返回值 |
| RECV | false | 空且无发送方 | **挂起** |
| RECV | true | 空 | `ERR(kind="ChannelClosed")` |
| RECV | true | 非空 | 先出队;读空后后续 `RECV` 得 `ChannelClosed` |
| TRY_SEND | false | 有空位 | `TRUE` |
| TRY_SEND | false | 满 | `FALSE` |
| TRY_SEND | true | — | `E0054` |
| TRY_RECV | false | 非空 | 返回值 |
| TRY_RECV | false | 空 | `NULL` |
| TRY_RECV | true | 空 | `ERR(kind="ChannelClosed")` |
| CLOSE | false | — | `closed = true` |
| CLOSE | true | — | 幂等 no-op |

#### 17.2.3 关闭协议

1. `CHANNEL_CLOSE(ch)` 置 `closed = true`;重复关闭是 no-op。
2. 关闭后 `SEND` / `TRY_SEND` → `E0054`。
3. 关闭后 `RECV` / `TRY_RECV` 在缓冲读空后返回 `ERR(kind="ChannelClosed", channel: <handle 显示>)`。
4. `NULL` **不得**用作关闭信号;**必须**用 `IS_ERR` + `ERR_PAYLOAD` 的 `kind` 识别。

**关闭对挂起等待方的唤醒**:关闭会释放该通道上全部挂起的等待方——

- 挂起的**接收方**被唤醒后,其 `RECV` 按"关闭且读空"完成,返回 `ERR(kind="ChannelClosed")`;
- 挂起的**发送方**被唤醒后,其 `SEND` 以 `E0054` 失败(发送到已关闭通道)。

多个等待方同时被唤醒时的次序**未定义**(实现可任选)。

`native_channel_close` 特性(§9.4)开启时,第 3 条的 `ERR(kind="ChannelClosed")` 改为硬诊断 `E0054`。

#### 17.2.4 限制

- 通道缓冲长度不设硬上界;`CHANNEL_NEW` 对大缓冲产生 `W0066`(默认阈值 1024,可经 `channel_large_buf_threshold` 调整,`0` 关闭)。
- `ERR(kind="ChannelWouldBlock")` 在 v0.9 无触发路径;需要"满 / 空即返回"的语义请用 `TRY_*`。

### 17.3 取消

| 构造 | 签名 | 语义 |
|------|------|------|
| `TASK_CANCEL(task, reason?)` | `-> NULL` | 请求取消目标任务(advisory)。`reason` 缺省空字典 `{}`;**必须**是 `DICT`,否则 `E0066`。**不**产生用户 `ERR`;过期/已结束句柄静默 no-op。非句柄 → `E0053` |
| `TASK_CANCEL_PARENT(reason?)` | `-> NULL` | 请求取消当前任务及当前作用域子树(自顶向下)。`reason` 规则同上。任务外 no-op |
| `SHIELD(fn)` | `SHIELD(fn) -> v` | 调用 `fn` 并屏蔽屏蔽块内收到的取消请求。**不**创建新作用域 |

`SHIELD` 与 `SCOPE` 正交:作用域负责生命周期,屏蔽负责取消推迟;可独立组合(`SCOPE(FUN(() , SHIELD(...)))`)。在顶层调用时,`SHIELD` 仅屏蔽来自当前任务的取消(顶层任务无取消源,故为 no-op)。

**结构化 reason**

- `TASK_CANCEL(task, reason)` / `TASK_CANCEL_PARENT(reason)` 携带结构化 `reason` 载荷;缺省为空字典。
- `reason` 不是 `DICT` → `E0066`(在元数与句柄校验之后)。
- `AWAIT` 已取消任务时返回的载荷为 `["kind": "Cancelled", "task": <handle>, "reason": <dict>]`;`reason` 直接透传用户传入的字典,不丢弃、不改写。

```wlwl
SCOPE(FUN(() ,
  LET(t, SPAWN(FUN(() , WHILE(TRUE, YIELD()))));
  TASK_CANCEL(t, ["why": "stop"]);
  LET(r, AWAIT(t));
  IF(IS_ERR(r), PRINT(ERR_PAYLOAD(r)), PRINT(r))
));
// 打印 [kind: Cancelled, task: <task handle id=0 gen=0>, reason: [why: stop]]
```

**SHIELD 语义**

1. **可嵌套**:层数累计;取消只在**最外层** `SHIELD` 退出后生效。
2. **内部取消仅记录**:屏蔽块内 `TASK_CANCEL_PARENT` 等只标记挂起取消(含 `reason`),不立即打断。
3. **退出后再生效**:最外层退出后,后续检查点(`TASK_IS_CANCELLED` / `YIELD` / 阻塞操作)立刻观察到取消。
4. **自身 `ERR` 不屏蔽**:`fn` 抛出的 `ERR` 仍走第 8 章传播,不受 `SHIELD` 影响。
5. `SHIELD` 的返回值是 `fn` 的返回值(透明包装)。

**取消与错误**

- 取消本身**不**生成用户 `ERR` 值;唯一观察点是 `AWAIT` 已取消任务(上列载荷)。
- 取消自顶向下传播;响应是**协作式**的:取消在检查点生效,不强制打断正在执行的表达式。
- 观察取消用 `TASK_IS_CANCELLED()`;`reason` 经 `ERR_PAYLOAD` 取得。

**兼容性**:`TASK_CANCEL(task)` / `TASK_CANCEL_PARENT()` 不带 `reason` 的写法继续合法,`reason` 隐式为空字典;仅按 `kind` 匹配的旧消费代码不受影响。

### 17.4 代数效果执行模型

本章并发原语在语义上建模为**代数效果**(algebraic effects):任务在效果点交出控制,调度器作为效果处理器接管并决定何时恢复。

| 用户语言构造 | 效果形式 |
|--------------|----------|
| `YIELD()` | `perform Yield` |
| `CHANNEL_SEND(ch, v)` | `perform ChannelOp(Send, ch, v)` |
| `CHANNEL_RECV(ch)` | `perform ChannelOp(Recv, ch)` |
| `TASK_CANCEL(t, reason)` | 对目标注入 `Cancelled(reason)` |

**效果点与挂起**

- 任务在 `YIELD`、阻塞型 `CHANNEL_SEND` / `CHANNEL_RECV`、以及 `AWAIT` 等待子任务时进入**挂起**;挂起任务保存其求值位置(continuation),恢复时从挂起点之后继续。
- 挂起对程序文本是**透明**的:任何表达式位置的效果点,恢复后语义上等价于"该表达式刚完成"。`LET(x, YIELD())` 恢复后 `x` 已绑定;嵌套构造内挂起后继续嵌套体剩余部分(§17.1)。
- 间接调用(把 `YIELD` 绑定到名字后再调用)与直接 `YIELD()` 等价。

**调度循环**

1. 从运行队列按 FIFO 取出一个就绪任务(§17.8);
2. 推进该任务直到它完成、或发出效果而挂起;
3. 挂起的任务登记到对应等待表(通道 / 子任务),移出运行队列;
4. 被配对、关闭、取消唤醒的任务重新入队;
5. 循环直至 `SCOPE` 的全部子任务结束。

**取消注入**:取消请求把目标任务标记为"待取消";目标在其下一个检查点观察到取消并按 §17.3 终止。被 `SHIELD` 屏蔽的取消只记录不生效。

**[非规范] 术语对应**:`YIELD` 对应 `perform Yield`;通道阻塞对应 `perform ChannelOp`;取消对应带载荷的 `Cancelled` 效果。实现可以把 `YIELD` / `ChannelOp` / `Cancelled` 作为内部效果标签,并把调度循环实现为效果处理器;本规范只规定可观察行为。v0.9 **不**暴露用户自定义效果处理器。

### 17.5 与第 8 章的关系

- 本章全部内建**均不是** 8.3 消费者:实参求值为 `ERR` 时按 8.2 透明传播,函数体不执行。
- `AWAIT` **返回**子任务的 `ERR` 作为普通结果值;是否消费由调用方按 8.3 决定。
- 跨任务边界后,`ERR` 载荷(含 `kind` 与 `reason`)保持原值。
- 未消费的 `ERR` 到达顶层仍为 `E0102`(8.5)。
- `SCOPE(ERR("x"))` 中,实参 `ERR("x")` 在 8.2 透明传播阶段先于 `fn` 的函数类型检查生效,故结果是 `ERR("x")` 透传,**不**产生 `E0052`。`E0052` 仅在 8.2 透明传播放过之后、参数被识别为非函数时触发。

### 17.6 标准库

v0.9 **不**新增 `wlwl:std.*` 并发模块。并发原语全部为全局内建(附录 G)。

### 17.7 限制与不承诺

| 项 | 说明 |
|----|------|
| 线程模型 | **单线程协作调度**。CPU 密集任务**不**获得并行加速 |
| 性能 | 保证单任务路径相对 v0.6 退化 < 10%;并发路径**只保证正确性与无泄漏** |
| 延迟 / 吞吐 | **不**承诺延迟上界或吞吐提升 |
| 阻塞挂起 | **真挂起**:阻塞型 `CHANNEL_SEND` / `CHANNEL_RECV` 在满 / 空且无对端时挂起;`TRY_*` 保持非阻塞 |
| 死锁检测 | **L1**,见下 |
| 隐式 scope | **不提供**(§17.1) |
| 通道关闭唤醒次序 | **未定义**(实现可任选) |
| 效果处理器 | **不**暴露用户自定义效果处理器 |

公平性与在飞兄弟取消的承诺见 §17.8。

**死锁检测 L1**

在同一 `SCOPE` 内,当 ≥ 2 个任务阻塞在通道操作上(`SEND` / `RECV` 挂起),且不存在任何可推进的对端配对(即运行队列已空、所有等待方都无法被唤醒)时,判定为死锁:

- **默认(严格)**:`[features] strict_deadlock_detect` 为 `true` 或缺省 → 抛 `E0065` 并终止(退出码 1);
- **软化**:`strict_deadlock_detect = false` → 先发 `W0065` 警告,随后相关 `AWAIT` 以 `E0053`(无对端唤醒)报告;
- **范围限制**:
  - **不跨 `SCOPE` 检测**;
  - **不检测**纯 `YIELD` 互让(多个任务互相让步但无通道依赖不算死锁);
  - **单个**通道挂起不算死锁(只是等不到对端;此时 `AWAIT` 该任务产生 `E0053`);
  - 同一通道上互为对端的挂起收发双方**不**构成死锁(见 §17.2.1 对端配对)。

### 17.8 公平性 / 可观测性

| 维度 | 承诺 |
|------|------|
| 调度公平性 | **best-effort FIFO**:让步检查点间隔下,同优先级任务按入队次序轮转。调度器从运行队列**按入队次序**取下一个可运行任务 |
| 通道配对顺序 | 对端配对成功的双方都被标记为就绪并加入运行队列**尾部**,避免一对抢占其他就绪任务 |
| 在飞兄弟取消 | **保证在下一个检查点可观测**:目标任务在下一个 `YIELD`、阻塞型通道操作或 `TASK_IS_CANCELLED()` 处观察到取消请求 |
| 取消扫描 | 每轮调度前扫描待取消标记,把对应任务置为已取消并清空其等待登记 |

**[非规范]** v0.7 / v0.8 不承诺调度公平、不保证在飞兄弟取消可观测;v0.9 把两项升格为上表承诺。

### A.1 记法

### A.2 语法

```

OpToken     = "+" | "-" | "*" | "/" | "%" | "==" | "=" | "!=" | "<" | ">"
            | "<=" | ">=" | "&&" | "||" | "!" .

string_lit     = '"' { string_element | interpolation } '"' .
string_element = any_char_except_quote_backslash_newline_dollar | escape .
interpolation  = "${" Expression "}" .
escape         = "\" ( "n" | "t" | "r" | "\" | '"' | "/" | "0" | "b" | "f" | "$" ) .

ClauseArray = "[" [ Clause { "," Clause } ] "]" .
Clause      = "[" Pattern "," Expression "]" .

Pattern     = identifier | "_" | Literal
            | ArrayPattern | DictPattern
            | "OK" "(" Pattern ")" | "ERR" "(" Pattern ")" .
ArrayPattern= "[" [ Pattern { "," Pattern } [ "," "*" identifier ] ] "]" .
DictPattern = "[" Expression ":" Pattern { "," Expression ":" Pattern } ]" .
```

**注**:`Block` 允许以一个无分号的表达式收尾,其值为括号序列的值;顶层 `Program` 通常写作若干 `ExprStmt`。`Postfix` 的三种形式可任意交错。`LetExpr` 中的 `MUT` 是上下文关键字(1.4);`string_lit` 中的 `Expression` 是完整的 `Expression` 文法,但为避免歧义,实现通常在词法阶段以括号配对定位插值边界。

`CLASS` / `NEW` / `THIS` 是关键字(1.4),出现在调用位置(§13 / §15)。会话协议表达式(§14.1)是普通 `Expression`(以 `ArrayLit` / `DictLit` / 字符串字面量书写),无独立文法。

## 附录 B 与早期草案的语义差异(非规范)

本规范以参考实现为准全新定义语言。与此前草案(v0.5 文本)相比,以下行为差异是**有意的**,以本规范为准:

1. **真值**:假值为 `FALSE`、`NULL`、`0`、`0.0`、`""`、空数组、空字典、`NaN`;其余一切值为真。`OK(FALSE)` 仍为真(成功变体本身为真)。
2. **逻辑短路**:`&&`/`||` 均为短路求值:左为假(`&&`)/真(`||`)/`ERR` 时不求右;返回值是被求值那侧的真值化结果(`BOOL`)。
3. **运算严格二元**:`+`、`-`、`*`、`/`、`%`、`CONCAT` 恰取两实参。
4. **容器非破坏性**:`PUSH`/`INDEX_SET`/`REMOVE_KEY`/`REVERSE` 等返回新容器,**不**修改接收者;更新**可变**绑定用 `SET`。
5. **`LET` 与 `LET MUT`**:默认 `LET` 建立不可变绑定;需可变的绑定须显式 `LET MUT`。单元格可变标志在绑定创建时即确定,不再因闭包调用而升级。
6. **`MATCH` 无默认且无命中**时值为 `NULL`(不报错)。
7. **`WHILE`/`FOR` 的值为 `NULL`**。
8. **字符串支持下标读**:`INDEX_GET` 接受字符串与整数索引,按码点返回单字符字符串;`INDEX_SET` 不接受字符串。
9. **相等跨数值类型**:`=(1, 1.0)` 为真。
10. **默认参数在词法帧内求值**、`*rest` 收集余参;元数检查为范围式。
11. **命名函数定义绑定名字**;`LET` 与命名定义可并存。
12. **`=` 是 `==` 的别名**(无警告);`!` 与 `NOT` 同义,均无警告。
13. **IF 消费 ERR**:条件为 `ERR` 时等价于条件为假;无 else 则 `IF` 整体透传 `ERR`。
14. **整数运算溢出抛错** `E0035`(原"饱和 + 警告"语义移除)。
15. **字符串插值**:`"${expr}"` 形式,内部等价于 `STR` 拼接;插值表达式产生 `ERR` 时整体透传。
16. **字典取值函数**:`POP(d, k, default)` 改名为 `AT_K(d, k, default)`(语义不变,更贴近行为)。
17. **`BOOL` 注册为 ERR 消费者**:对 `ERR` 返回布尔而不透传,便于在 IF 之外的真值判断位置安全使用。
18. **[v0.9 修订]** 面向对象构造(`CLASS`/`NEW`/`THIS`/`GET_PROP`/`SET_PROP`/`CALL_METHOD`)已定义(§13–§15),不再是保留形式。
