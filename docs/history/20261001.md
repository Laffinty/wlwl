### 目标(6 条)与非目标

1. **双轨实现机制**(M1):标准库分三层 —— R0 内建层(纯 Rust,语言表达不了的原语)、
   R1 语言层(纯 wlwl)、R2 原生层(纯 Rust);允许「R2 原生内核 + R1 wlwl 门面」的
   混合模块。调用者只见统一调用面(全局内建免导入 + `IMPORT("wlwl:std.X", [...])`),
   实现语言不可感知。
2. **值直通**(M2,必须):先拆 `wlwl-value`,再解除 `wlwl-std` 的 `serde_json::Value`
   边界,最后宿主归位(collection/test 迁出 `wlwl-eval`)。值层只承载值与句柄,
   函数调用经 trait/回调注入,保持 `eval → value ← std` 单向依赖。
3. **R1 首批**(M3):`std.collection` 以纯 wlwl 重写为终态;新增 `std.str`;
   新增 `std.math`(**混合**:R1 门面 + R2 浮点内核 `SQRT`/`POW`);`std.test` 允许混合。
4. **文档独立**:标准库文档与语言规范相互独立,落
   `docs/stdlib/wlwl-stdlib-spec-v0.11.md`,自含版本号。
5. **稳定性政策成文**(M4):v0.x 按 CHANGELOG + 规范改版执行;1.0 起冻结。
6. **基准基线**(M5):criterion 对 R1 模块建立基线,作为未来下沉/上浮的决策依据。

**非目标**:面向用户的 FFI;预编译快照(启动解析 + 进程内缓存即可);新 R2 大命名空间
实体化(net/process/env/time 仅记演进方向);prelude 扩张;`std.ai` / `std.agent`
降级为官方包(仅记方向);`std.math` 超越函数(sin/cos/exp/log 族)。

**机制**:`StdSource` 增私有 `kernels` 注入槽;`load_std_lang` 在 `eval_module`

注入 ⇒ 覆盖不可能改变导出面(M1 的 `E0023` 漂移守卫不受影响)。
**被否决**:让 R1 靠「误撞」可发的原生码报类型错 —— 码对了但消息指向 `LEN` 而非
`MAP`,诊断反而更糟。

### 批次 B:`YIELD` 续体保存(**0 细化**,不写成「已就绪」)

原承诺「细化计划在 M1 落地后补入」——M1 早已落地(`d56cf08`)而细化**始终未补**。
**开细化前必须先定三件事**(缺一都写不下去):

1. **「续体保存」的数据形态**:续体是解释器状态(调用栈 + 局部绑定 + 挂起的
   `Outcome`/`Signal`),落盘要么序列化整个帧,要么改写成可重放的显式栈 ——
   两条路复杂度差一个数量级,且决定是否需要 R0 解释器改动。
2. **是否与批次 A 遗留的 `MAP` 平方级成本合并**:两者同根(语言层缺原语 ——
   前者缺续体存储,后者缺线性建数组)。合成一个「R0 原语补齐」批次还是分两批,属
   范围决策,未裁。
3. **是否需要 `Serialize` 进 `wlwl-value`**:当前值层刻意零依赖(ADR-0022),
   引入序列化会改变依赖画像。

### 做过什么

`std.web` 成员面达到 4 个:`PARSE_TEMPLATE` / `EMIT_HTML` / `EMIT_CSS` / `TOKEN`。

### 失败原因(全部查实,不是「太难」)

1. **旗舰差异化的逻辑链在排期上就是断的。** 裁决 C「行为最小化」逐个问
   「CSS 2025 能否表达这个**动态绑定**」,而 `{{ }}` 插值**未实现、也没排进任何
   里程碑**;它的消费者是 W5 的 JS 发射器,却被排在消费者**前一个**里程碑。做到
   W4 才查出来 —— 那一刻节点树里**一个绑定都没有**,判定表无表可判。
2. **作用域共推导建立在一个不可用的降级方案上。** 裁决 B 的核心(无前置子
   `@scope` + 零类名哈希)依赖「`@supports` 守卫的降级副本」兜底,而该副本查实
   **两头都错**:
   - **语法错**:`at-rule()` 是 `@supports` 的**函数式**条件,正确写法是
     `@supports at-rule(@scope)`;计划原写的 `(at-rule: …)` 冒号形式不是合法语法。
   - **支持度正好反了**(MDN 兼容表三个独立镜像 + Chrome Platform Status 条目
     `5110744177836032`,2026-10-01 核实,四方一致):

     | 特性 | Chrome | Firefox | Safari |
     |---|---|---|---|
     | `@scope` 本身 | 143 | 146 | 26.4 |
     | `at-rule()` 特征查询 | **148** | **不支持** | **不支持** |

     ⇒ 守卫在 **Firefox / Safari —— 恰恰支持 `@scope` 的那两个引擎** —— 身上求值为
     假、屏蔽掉作用域样式;在真正需要降级的旧浏览器身上整块失效。**意图整个反转。**
     反向写法 `not at-rule(@scope)` 更糟(两者都不支持时整个 `@supports` 块被当
     非法丢弃,`@scope {}` 也丢弃 ⇒ **一条样式都拿不到**)。**无条件发两份也不行**:
     fallback 那份的选择器会匹配到组件之外的同名元素(前置子不增特异性 ⇒ 两份同
     权重、后写者赢)⇒ 隔离在绝大多数用户那里被摧毁,比不做降级更糟。
   - **结论:纯 CSS 做不出这个降级。** 要么有能区分 at-rule 支持度的特征查询
     (今天不存在),要么注入标记属性并前置选择器(= 类名哈希,需解析 CSS,正是裁决 B
     废除的东西)。**删掉降级反而加固裁决 B**。计划原文「这消掉了原风险 R-1 的整个
     降级分支」**本身是错的** —— 该降级分支从来不存在。
3. **预定成员面 9 个,有 6 个从未有明确归属**(`ELEMENT` / `COMPONENT` / `RULES` /
   `PAGE` / `RENDER` / `EMIT_JS`)。W4 做 `EMIT_CSS` 时才发现它的输入里根本没有
   `RULES`。
4. **里程碑之间存在未被发现的依赖**,W2-1 与 W4 各踩一次 —— 计划把「需要前一里程碑
   先有的能力」当成了已有。
5. **W2-1 在 R1 连续三次失败**,根因全是括号嵌套深度(无元组 + `LET` 顺序绑定 +

### 归档前保留的设计裁决(供复活参考)

- **裁决 A 表面语法**:惰性模板(`.wlwt` 扩展名),不用组合子(Gleam+Lustre 式
  `html.div([...], [...])`)、不用宿主插值。否决宿主 `${}` 的三条硬理由:静态片段与
  动态值不可分(插值产出已拼好的单串,分离信息**不可恢复**)、无法生成 JS(值在模板
  求值那刻已成死文本)、连 `\$$` 转义当逃生阀都不比 `.wlwt` 省事。
- **裁决 B 作用域共推导**:`@scope` 前置选择器**不增加内层特异性**(一手规范
  CSS Cascade 6 §2.5.1);无前置子的 `@scope { }` **只在 `<style>` 内生效**,绑到该
  `<style>` 的父元素 ⇒ 把组件 `<style>` 放进根元素内部,作用域根自动就是组件根,
  **不需要注入属性、不需要知道根是什么标签、不需要类名哈希**。
- **裁决 C 行为最小化**:判定表 6 行(`:has()` / `@container` / `@scope` /
  原生控件状态 / 展示态切换 / `view-transition-name`),其余进 JS;**表是固定模式
  匹配,纯函数,R1 可写**。⚠ 第 5 行的 `data-wc-state` **全仓只出现过那一行** ——
  从未定义谁写它、值语法、何时增删,**做判定表前必须先补这个定义**。
- **裁决 D token 共推导**:`TOKEN` 发射成 `@property --w-<name>`,让 token
  **带类型、可过渡、可继承**。`@property` 地基比原估更稳(newly 2024-07-09,
  **Firefox 128** 起可用,原判断低估)。
- **产物不变量 JS-1..JS-5**:不含位置化字符串索引 / `INTEGER` 满足 \|v\| ≤ 2^53−1 /
  不对数据派生串用 `toUpperCase`/`toLowerCase` / 不含 wlwl 算术的重新实现 /
  **零第三方依赖**(产物自带最小运行时)。锁测试必须扫**产物文本**而不是发射器代码
  —— 对发射器断言等于自证。
- **平台事实更正**(W1 复核,原引自技术博客的三条被推翻):`@scope` 实为
  Chrome 143 / Safari 26.4 / Firefox 146(Baseline newly 2026-03-24),不是
  「Chrome 118 / Safari 17.4」;`light-dark()` 是 newly 2024-05-13;
  `color-mix()` 的**三色及以上**变体仍是 limited。
