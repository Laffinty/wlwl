# 2026-09-15 (续) — P4-A5: RESULT 一等值类型 + TYPE builtin (spec v0.4 §2.2.1)

A6 (commit 9f0c0f6) commit 之后继续推进 Phase A 的 A5 项——把 spec §2.2.1
"OK / ERR 是 RESULT 一等值类型"的语义落地:实装 `TYPE` builtin + 给
`ERR(e)` 加 payload 类型约束。本批改动 ~60 行 impl + 12 个新测试 +
2 处 baseline 测试更新(spec 一致化)。

## 范围 (spec v0.4 §2.2.1)

- `OK(v)` / `ERR(e)` 是 **RESULT** 一等值类型(非"普通 DICT 包装")
- `TYPE(x)` 返回大写类型名 (`INTEGER` / `FLOAT` / `STRING` / `BOOLEAN` /
  `NULL` / `ARRAY` / `DICT` / `FUNCTION` / `RESULT`)
- `OK(v)` / `ERR(e)` 都是 `RESULT` 类型(spec 表格明示)
- `ERR(e)` 强制 `e` 是 STRING 或 DICT(违反 → `E0030`)
- `OK / ERR` 是**构造器宏函数**(非关键字)—— spec §3.3 不列入关键字表

## 关键设计决策

1. **新增 `value_type_name(v) -> &'static str`**(大写) — 与既有 `type_name`(小写)
   并存,避免 ripple `type_error` / `arity_error` 等诊断消息字符串(spec §14 是诊断
   schema 范畴,不在本批)。`value_type_name` 专给 `TYPE` builtin 用。
2. **`Value::Closure` 与 `Value::NativeFn` 都映射为 `"FUNCTION"`** — spec §2.2 表只
   列 `FUNCTION` 一种;`NativeFn` 是 std 注入机制,不是独立 user-visible 类型。
   这是 v0.4 偏差候选,记 deviations.md `P4-A5-001`(用户也可以接受另立
   `"NATIVE_FUNCTION"`,但 spec 表只一种更稳)。
3. **`Value::Ok` 与 `Value::Err` 都返回 `"RESULT"`** — spec §2.2.1 明确:
   "`OK(v)` 产生 RESULT 类型的'成功变体'... `ERR(e)` 产生'失败变体'";
   两个 variant **共享**一个 type name。
4. **`TYPE` 实装为 builtin**(A6 注册表已为 TYPE 占位) — 加 `"TYPE" => Some(builtin_type)`
   到 `resolve_builtin`,关闭 A6 tripwire 中的 TYPE 项(UNWRAP / ERR_PAYLOAD / WRAP
   仍是 B4 tripwire)。
5. **`Expr::Err` payload 类型检查在 eval 时跑**(非 parser) — spec 钉死在 §2.2.1
   "e **必须**是 STRING 或 DICT(违反 → `E0030`)",需要 runtime check 因为 payload
   可能是 LET 变量、函数返回值等动态值。检查时机:`eval_expr(value)` 之后立即。
6. **`OK(v)` 不加类型约束** — spec §2.2.1 只对 ERR 限制;OK 接受任意类型(包括
   嵌套 OK / ARRAY / dict 等)。
7. **OK / ERR 当 keyword(lexer-level) — 偏差登记到 deviations.md `P4-A5-002`** —
   spec §2.2.1 钉死 OK / ERR 是"构造器宏函数**(非关键字,因为 §3.3 不列入关键字表)**",
   但当前 lexer 把 OK / ERR 当 `TokenKind::Ok / Err` keyword 处理。改成"构造器宏"
   需要 lexer + parser 大改,本批**保持现状**,留待 v0.5 决策;行为差异是
   用户不能用 `LET(OK, 1)` 作为变量名——用户写 `OK` 永远触发 Expr::Ok 构造路径。
   这与 spec 的"宏函数"在 lexer 层不可作为变量名是**间接兼容**的(普通 macro
   在 parser 层处理也行),但严格按 spec "OK / ERR 不在 §3.3 关键字表" 还有
   form-level 偏差。

## 实现摘要

### wlwl-eval
- 新增 `value_type_name` 函数(大写 variant 名),与 `type_name` 并存
- 新增 `builtin_type` 函数: 1 arg,返回 `Value::String(value_type_name(&arg))`
- `resolve_builtin` 加 `"TYPE" => Some(builtin_type)`(关闭 A6 tripwire)
- `Expr::Err` 加 payload 类型检查:非 String / Dict → E0030

### 不在本批改动的文件
- `wlwl-parser`: OK / ERR 当 keyword 不动(留 P4-A5-002 deviations)
- `wlwl-error`: 无错误码新增(E0030 已存在,本批触发新路径)
- `wlwl-ast`: 无 AST 改动

## 行为变更(用户可见)

| 输入 | 旧行为 | 新行为 |
|---|---|---|
| `TYPE(1);` | E0020 undefined | `"INTEGER"` |
| `TYPE("hi");` | E0020 | `"STRING"` |
| `TYPE([1,2]);` | E0020 | `"ARRAY"` |
| `TYPE(OK(1));` | E0020 | `"RESULT"` |
| `TYPE(ERR("e"));` | E0020 | `"RESULT"` |
| `TYPE(LET(f, FUN((), 1)) f);` | E0020 | `"FUNCTION"` |
| `ERR("hi");`(top) | ERR 透传到 E0102 | ERR 透传到 E0102(**零变化**) |
| `ERR(42);` | ERR 顶层 E0102 | E0030 `ERR payload must be STRING or DICT, got integer` |
| `ERR([1,2,3]);` | ERR 顶层 E0102 | E0030 type error |
| `ERR(TRUE);` / `ERR(NULL);` | ERR 顶层 E0102 | E0030 type error |
| `ERR(OK(1));` | ERR 顶层 E0102 | E0030 type error(OK 是 RESULT 不是 STRING/DICT) |
| `ERR(["k": "v"]);` | ERR 顶层 E0102 | ERR 顶层 E0102(**零变化,DICT 是允许类型**) |
| `OK(42);` / `OK([1,2]);` / `OK(OK(1));` | OK(v) 包装 | OK(v) 包装(**零变化**) |
| `LET(x, 42); ERR(x);` | ERR 顶层 E0102 | E0030 type error(检查 evaluated payload) |
| `LET(d, ["k": "v"]); ERR(d);` | ERR 顶层 E0102 | ERR 顶层 E0102(**零变化**) |

### baseline 测试更新(spec 一致化)

| 测试 | 原代码 | 新代码 | 原因 |
|---|---|---|---|
| `err_is_ok_is_err` | `IS_OK(ERR(1));` / `IS_ERR(ERR(1));` | `IS_OK(ERR("1"));` / `IS_ERR(ERR("1"));` | ERR(1) 现在触发 E0030(spec §2.2.1) |
| `p4_a4_destructure_constructor_mismatch_is_e0026` | `LET([OK(x), v], [ERR(5), 10])` | `LET([OK(x), v], [ERR("5"), 10])` | ERR(5) 现在触发 E0030 而不是 E0026 |

这两处不是 baseline 退化,是 v0.4 spec 合规化的必然改动;旧形式在新规则下不可能
产生 ERR 值(destructure 永远先 E0030 fail)。
