## 一、E2(wlwl-formatter):canonical formatter + `wlwl fmt`(commit c427b2a)

| 项 | 详情 |
|---|---|
| 新 crate | `wlwl-formatter`(依赖仅 wlwl-ast;测试 dev-dep wlwl-parser + serde_json) |
| 实现策略 | **parse → AST → 重建**(非文本改写),输出是 AST 的纯函数 |
| 10 条规则 | 4 空格缩进 / ≤100 列超长调用按"每参一行"+8 折行 / `;` 语句必填、块末表达式无 `;` / 逗号必填无尾随 / `"` 字符串(转义集与 lexer 精确互逆,非 ASCII 保留) / 空白规范化 / 多语句块逐行 / IMPORT·EXPORT 独立行不合并 / CLASS members 折行 / 空集合 `ARRAY()`·`DICT()` |
| CLI | `wlwl fmt <file>`(stdout,永不就地写) + `wlwl fmt --check`(偏离即 W0053 诊断、exit 1) |
| W0053 | wlwl-error 新 ErrorCode(Syntax bucket,is_warning),警告码计数测试 12 → 13 |
| 测试 | formatter crate 26 个(含 **`fmt_idempotent_over_100_fixtures`**:75 手写全节点 fixture + 75 组合生成 fixture,同时断言 span-stripped AST 相等)+ examples/ 目录幂等 + CLI 6 个 |
| wlwl-cli 测试 | 24 → 30 |

关键正确性设计(保证 `fmt(fmt(x)) == fmt(x)`):

1. 浮点渲染保小数点(`1.0` 不得渲染为 `1`,否则 re-parse 变 INTEGER);
2. 单语句块与 `parse_block` 的解包语义对齐(单语句 block 内联渲染,re-parse 得同 AST);
3. `-x` 语法糖按解析后的 desugar 形式(`-(0, x)`)渲染,re-parse 等价;
4. match 分支的 default 臂按 parser 物化行为总是显式渲染;
5. CLASS 成员折行在 inline 尝试**之前**短路(rule 9 不受行长影响)。

## 二、E3(wlwl-ast):稳定 node ID + SHA-256 内容 hash(commit c494260)

| 项 | 详情 |
|---|---|
| 新模块 | `wlwl-ast::stable`(`stable_tree(root, module) -> StableNode`) |
| node_id | `{module}:fn:<top|NAME|<anon>>/body/{label}:{sibling}/...`;FUN 体边界嵌入 `/fn:{NAME}/body:N` 段;完整结构前缀保留 → 同名函数不冲突;**与行号无关**(行漂移不变) |
| hash | `sha256:<hex>`,对**剥离 span** 的子树 serde JSON 计算 → 内容变化才变化;空白/排版漂移不影响 |
| span-strip | 兼容 serde 枚举位置式 payload(5 键形态识别),不止 `span` 命名键 |
| 新模块 | `wlwl-ast::sha256`(纯 Rust FIPS 180-4,零外部 crypto 依赖;FIPS 测试向量) |
| CLI | `wlwl ast --format=json` 输出 §16.4.3 schema:`ast_schema_version` 0.3.1 → **0.4.0**,`source_bytes` 实填,root = stable-ID 树 |
| 测试 | +9 stable-tree 集成测试 + 4 sha256 向量 + 2 CLI schema 测试;wlwl-ast 测试 38 → 53 |

> **工程注**:stable 测试放在 `tests/stable_tests.rs`(集成测试)而非 lib 单元测试 —— 跨 crate dev-dep 循环会让 wlwl-ast 被编译成两个实例,`Expr` 类型不匹配。
