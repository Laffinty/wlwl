## 范围 (spec v0.4 §10.1)

| 函数 | 签名 | 行为 |
|------|------|------|
| SHIFT | SHIFT(arr) -> ARRAY | 移除第一个元素 |
| UNSHIFT | UNSHIFT(arr, x) -> ARRAY | 在开头插入元素 |
| SLICE | SLICE(arr, start, end?) -> ARRAY | 半开区间 [start, end),负数从尾数,end 缺省切到末尾 |
| CONCAT | CONCAT(a, b) -> ARRAY | ARRAY+ARRAY 拼接;STRING+STRING 返回 codepoint ARRAY |

## 关键设计决策

### 1. immutable 语义

所有 array builtin 返回新 array,不修改原 array:
```
LET(arr, [1,2,3]); SHIFT(arr); LEN(arr);  // 仍是 3
```

锁测试 `b12_immutable_does_not_mutate_input` 守住。

### 2. ARRAY + STRING 双形参

CONCAT / CONTAINS / INDEX / REVERSE 同时接受 ARRAY 和 STRING。STRING 路径与 §10.3 字符串工具对称:
- CONCAT("ab", "cd") → [97, 98, 99, 100] (codepoint array)
- CONTAINS("hello", "world") → false
- INDEX("hello", "ll") → 3 (1-based)
- REVERSE("abc") → [99, 98, 97]

这是 §10.1 通用 builtin 风格 (PUSH 接受 ARRAY,AT 接受 ARRAY/DICT 都是同样模式)。spec 表 row 6/8/10 只列 ARRAY,但实现上扩展到 STRING 不破坏 spec,只是用同样的工具覆盖更多场景。

### 3. POP 命名沿用 B1

spec 附录 G 表 row 2 标 `POP(arr) -> ARRAY`(移除最后一个元素返回新 array)。但 impl 早在 B1 把 POP 重载为 `POP(dict, key, default) -> v`(3-arg DICT 安全删除 + 默认值 fallback)。

本批**不动** POP 语义以保持向后兼容——任何调用 `POP(arr)` 的现有代码 (虽然 spec 推荐这个写法) 会触发 E0022 arity 错。

P4-B12-002 deviation 记录这条 spec drift。v0.5 重命名 `POP_DICT` / `POP_ARR` 可彻底分开。

### 4. INDEX 找不到 → -1 而非 E0031

spec §10.1 row 8 写 "INTEGER / E0031" 暗示找不到抛错。但 v0.2 历史是返回 -1。

本批选 -1,理由:
- 用户用例 `IF(INDEX(arr, x) > 0, found, not)` 风格比 TRY-wrapped 更自然
- 与 spec §10.1 其它"查找"原语 (HAS / CONTAINS) 返回 BOOLEAN 不一致是另一回事,但 INDEX 历史上就是 INTEGER

E0031 只在 array 类型错的极端 case (INDEX(42, 1)) 触发。

### 5. CONCAT STRING+STRING 返回 codepoint ARRAY

spec 表 row 7 暗示这是 ARRAY 操作。但允许 `CONCAT("ab", "cd")` 是 §10.3 字符串拼接的实用工具——返回 codepoint ARRAY 让 caller 用 `FROM_CODEPOINTS` 还原 STRING。

如果 spec 严格要求 STRING+STRING → STRING,后续可以加专用 `CONCAT_STRING` (v0.5)。当前实现宽松路径。
