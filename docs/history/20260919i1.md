## 一、修复清单

| # | 缺陷 | 严重度 | 根因位置 | 修复 |
|---|------|--------|----------|------|
| 1 | LET 遮蔽语义错误(cell 名字冲突污染) | 严重 | `wlwl-eval/src/lib.rs` `Expr::Let` 分支的 `set_existing` 路径("Phase 2 fix":任何外层作用域已有同名绑定就覆盖) | 删除该路径,LET 总是 `check_let_shadowing` + `set_local` 新建 cell;`Env::set_existing` 删除 |
| 2 | `RANGE(start, end)` 双参 panic(exit 101) | 严重 | `wlwl-eval/src/collection.rs` `builtin_range` match 缺 `2 =>` 分支,落入 `unreachable!()` | 补 `2 => (start, end, 1)` 分支 |
| 3 | `=(a, b)` 规范拼写不可解析 | 中 | lexer `as_op_name()` 缺 `Eq` | `TokenKind::Eq => Some("==")`,与默认参数语法无冲突(`parse_fun` 先行消费) |
| 4 | 命名 FUN 语句不绑定名字 | 中 | eval `Expr::Fun` 分支丢弃 `name` 字段 | `name` 为 Some 时 `check_let_shadowing` + `set_local` 绑定闭包,与 parser linter 记账对齐 |
| 5 | `arr[i]` / `arr[i] = v` 下标语法糖缺失 | 中 | parser `parse_call_or_ident` 后缀链仅支持 `.` | 后缀循环扩展 `[`:读糖 → `INDEX_GET(a, i)`,写糖 → `INDEX_SET(a, i, v)`,可与 `.` 混合链式;无新 AST 节点(沿 §5.5 `.` 糖先例) |
| 6(连带)| 默认参数解析但调用时不应用(严格等元数检查致不可达) | 中 | `invoke_closure` 元数检查 `params.len() != arg_values.len()` | 放宽为 §8.4 范围 `R <= A <= N`(rest 时 `A >= R`);缺省参数在词法帧内求 `default_expr` 填充;`*rest` 收集余参为 ARRAY;错误消息改为 `expects R..N` |
| 7(连带)| `is_rest` 完全未实现 | 中 | 同上 | 同上 |

## 二、语义对齐的连带影响

- **LET 循环累加模式失效**(§6.6 正确行为):11 个 eval 测试、`phase2_demo.wll`、5 个 bench 的 workload 全部改写为规范模式 —— 闭包捕获 cell(§6.4)或 FOR + RANGE(§7.3/§10.5)。`simple_loop_1m` 仍保持"无闭包、纯循环分发 + LET + 算术"的设计意图。
- **同作用域重复 LET 仍静默覆盖**(`HashMap::insert`),E0021 仍未对 LET 强制(保持 IMPORT-only)—— 记 deviations P4-I1-001 follow-up,避免本轮爆炸半径扩大。
- **写糖 `a[i] = v` 的值** = INDEX_SET 返回的更新容器,不回写 `a`(值模型 owned,deviation P4-B1-003 不变,即"原地修改回写"不在本轮范围)。
- **bench baseline 重置**:workload 变更使 Phase F1 基线不可比,`benches/baseline.txt` 按 Phase I1 表头重新生成( documented 命令,`--warm-up-time 1 --measurement-time 2 --sample-size 10`):

| bench | Phase F1 (mean) | Phase I1 (mean) | 说明 |
|-------|-----------------|-----------------|------|
| simple_loop_1m | 965.73 ms | 536.57 ms | WHILE+LET累加 → FOR+RANGE+LET+add(无闭包) |
| closure_density | 899.89 ms | 716.57 ms | 驱动改 FOR+RANGE,300k 闭包调用不变 |
| string_concat | 2.08 ms | 4.26 ms | 累加改捕获 cell(每次 + SET) |
| array_higher_order | 23.63 ms | 30.35 ms | 数组构建改捕获 cell append |
| error_propagation | 92.46 ms | 140.05 ms | 驱动改 FOR+RANGE,40k UNWRAP_OR 不变 |

- **formatter 门禁修复**:`fmt_examples_dir_files_idempotent` 自 v0.4 语法落地起在 HEAD 上即失败(destruct/format/match/std_test 四个示例仍是 v0.3 语法)。本轮将示例现代化后该门禁恢复绿。
